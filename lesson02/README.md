# 第2章 セキュリティの基本概念とガバナンス【D1】

CISSP の全ドメインの土台となる「セキュリティの基本概念」と「ガバナンス」を学びます。CIA トライアドと制御の分類はこの先のすべての章で問われ続ける道具箱であり、デューケアとポリシー体系は「マネジメント視点で BEST を選ぶ」CISSP 的思考の出発点です。

## 1. CIAトライアドと5つの柱

### 情報セキュリティの目的は3つ+2つ

情報セキュリティの目的は、**CIA トライアド**と呼ばれる3つの性質を守ることです。

| 性質 | 意味 | 破られると… | 代表的な対策 |
|---|---|---|---|
| **機密性** (Confidentiality) | 許可された人だけが読める | 漏えい・暴露 (Disclosure) | 暗号化、アクセス制御 |
| **完全性** (Integrity) | 情報が正しく、勝手に変えられていない | 改ざん (Alteration) | ハッシュ、デジタル署名、変更管理 |
| **可用性** (Availability) | 使いたいときに使える | 破壊・停止 (Destruction) | 冗長化、バックアップ、DoS対策 |

破られた状態の頭文字をとって **DAD**（Disclosure / Alteration / Destruction）と呼びます。「この攻撃は CIA のどれを脅かすか？」は試験全体を通じて問われ続ける視点です。

### 5つの柱（Five Pillars）

ISC2 は CIA に次の2つを加えた **5つの柱**を掲げています。

- **真正性** (Authenticity): その情報や通信相手が「本物である」こと。なりすましの防止です
- **否認防止** (Nonrepudiation): 行為者が後から「やっていない」と言い逃れできないこと。**デジタル署名**が代表的な実現手段です

さらに、誰が何をしたかを個人に紐づけて追跡できる **アカウンタビリティ** (Accountability) も重要概念です。識別→認証→認可→監査の仕組みがそろって初めて成立します。

💡 コツ: 対策を見たら「どの性質を守るためのものか」を即答する練習をしましょう。例えばハッシュ値の照合は完全性、RAID は可用性、暗号化は機密性です。ただし暗号化は署名と組み合わせると完全性や否認防止にも効く、というように**1つの技術が複数の性質に効く**こともあります。問題文の文脈で「主目的」を選ぶのが CISSP 流です。

### 確認問題

**問1.** ある病院で、電子カルテシステムが障害で丸1日停止し、医師が患者の投薬履歴を確認できなくなりました。この事象で主に損なわれたセキュリティの性質はどれですか？

1. 機密性 (Confidentiality)
2. 完全性 (Integrity)
3. 可用性 (Availability)
4. 否認防止 (Nonrepudiation)

<details><summary>答えと解説</summary>

正解: **3**

「使いたいときに使えない」状態なので可用性 (Availability) の侵害です。情報が漏れたわけではないので機密性ではなく、カルテの内容が書き換えられたわけでもないので完全性でもありません。否認防止は「やっていないと言い逃れできないこと」で無関係です。ひっかけポイント: 病院＝個人情報＝機密性、と反射的に選ばないこと。問題文の事象（停止）を素直に読みましょう。

</details>

**問2.** 送信者が後から「そのメールは自分が送ったものではない」と主張することを防ぎたい。この要件を満たすのに最も適切 (BEST) な技術はどれですか？

1. 共通鍵による通信の暗号化
2. デジタル署名
3. ファイルのハッシュ値の公開
4. 多要素認証によるログイン

<details><summary>答えと解説</summary>

正解: **2**

「送った事実を否認させない」は否認防止 (Nonrepudiation) の要件で、送信者本人だけが持つ秘密鍵で署名するデジタル署名が BEST です。共通鍵暗号は鍵を双方が持つため「相手が作ったかもしれない」と言い逃れでき、否認防止になりません（ここが最大のひっかけ）。ハッシュ値だけでは誰が作ったか証明できず完全性の確認止まり、多要素認証はログイン時の真正性を高めますが送信行為そのものの証明にはなりません。

</details>

**問3.** CIA トライアドが破られた状態を表す「DAD」の組み合わせとして正しいものはどれですか？

1. Disclosure（暴露）・Alteration（改ざん）・Destruction（破壊）
2. Denial（拒否）・Attack（攻撃）・Damage（損害）
3. Disclosure（暴露）・Authentication（認証）・Destruction（破壊）
4. Deletion（削除）・Alteration（改ざん）・Disaster（災害）

<details><summary>答えと解説</summary>

正解: **1**

機密性の反対が Disclosure（暴露・漏えい）、完全性の反対が Alteration（改ざん）、可用性の反対が Destruction（破壊・停止）で、頭文字をとって DAD です。他の選択肢はもっともらしい英単語を並べたダミーです。特に Authentication（認証）はセキュリティの仕組みであって「破られた状態」ではない点に注意しましょう。

</details>

**問4.** あなたは CISO です。経理部門から「取引記録が何者かに書き換えられていないことを継続的に確認したい」と相談されました。最も適切 (MOST) な対策はどれですか？

1. 取引記録を保存するディスクを RAID 構成にする
2. 取引記録のファイルを暗号化して保存する
3. 経理システムに多要素認証を導入する
4. 取引記録のハッシュ値を定期的に取得し照合する

<details><summary>答えと解説</summary>

正解: **4**

「書き換えられていないことの確認」は完全性 (Integrity) の検証なので、ハッシュ値の照合が最も直接的な対策です。RAID は可用性（ディスク故障対策）、暗号化は機密性が主目的で、暗号化しても権限を持つ内部者による改ざんは検出できません。多要素認証は不正ログインの予防にはなりますが、改ざんが「起きていないことの確認」という要件には答えられません。要件の動詞（確認したい）に対応する機能を選ぶのがコツです。

</details>

**問5.** アカウンタビリティ (Accountability) を成立させるために必要な要素の組み合わせとして、最も適切なものはどれですか？

1. 暗号化・バックアップ・冗長化
2. ポリシー・標準・手順
3. 識別・認証・認可・監査（ログ）
4. 予防・発見・是正

<details><summary>答えと解説</summary>

正解: **3**

アカウンタビリティとは「誰が何をしたかを個人に紐づけて追跡できること」です。そのためには、まず利用者を識別 (Identification) し、本人であることを認証 (Authentication) し、権限を認可 (Authorization) した上で、行動を監査ログ (Auditing) に記録する必要があります。どれか1つでも欠けると「その操作をしたのは確かにこの人だ」と言えなくなります。他の選択肢は可用性対策の組（1番目）、文書体系（2番目）、制御の機能分類（3番目）で、いずれも追跡可能性とは別の話です。

</details>

## 2. セキュリティガバナンス

### ガバナンス＝経営の仕組みにセキュリティを組み込む

**セキュリティガバナンス** (Security Governance) とは、セキュリティを現場任せの技術論ではなく、**経営の意思決定と監督の仕組み**として運営することです。ポイントは2つあります。

- **事業目標との整合** (Alignment): セキュリティは事業を守り支えるための手段です。事業のミッション・目標・戦略から出発して計画します
- **トップダウンアプローチ**: 方針は経営層が決め、承認し、資源（予算・人）を割り当てます。現場から積み上げるボトムアップは CISSP では不正解側の定番です

### 役割と責任 (Roles and Responsibilities)

| 役割 | 責任 |
|---|---|
| **経営陣** (Senior Management) | セキュリティの**最終責任** (ultimately responsible)。ポリシーの承認 |
| **セキュリティ専門家 / CISO** | ポリシーの起案・実装・運用（機能的責任）。ただし最終責任は負わない |
| **データオーナー** | データの分類とラベル付けの決定責任 |
| **データカストディアン** | バックアップ等、日々の保護作業の実施 |
| **ユーザー** | ポリシーに従って業務でデータを利用 |

「最終責任は誰か？」と問われたら、答えはいつも**経営陣**です。

### デューケアとデューデリジェンス（超頻出）

- **デューデリジェンス** (Due Diligence): **知るための活動**。リスクを調査・評価し、計画やポリシーを策定すること。*Do Detect* と覚えます
- **デューケア** (Due Care): **行動**。策定したポリシーや対策を実際に実行し、合理的な注意義務を果たすこと。*Do Correct* と覚えます

両者を果たしていないと、インシデント発生時に経営陣が**過失** (negligence) を問われます。

💡 コツ: 「調べる・評価する・計画する」ならデューデリジェンス、「実行する・運用する」ならデューケア。順番はデューデリジェンス→デューケアです。なお、警備やSOC運用などセキュリティ機能を外部委託しても、**責任は委託元に残る**（第三者ガバナンスでは委託先を監督する義務がある）点もセットで覚えましょう。

### 確認問題

**問1.** 組織の情報セキュリティについて最終責任 (ultimate responsibility) を負うのは誰ですか？

1. CISO（最高情報セキュリティ責任者）
2. データオーナー
3. セキュリティ運用チーム
4. 経営陣 (Senior Management)

<details><summary>答えと解説</summary>

正解: **4**

セキュリティの最終責任は常に経営陣にあります。CISO はポリシーの起案や実装を担う機能的責任者ですが、最終責任者ではありません。ここが最大のひっかけで、「セキュリティの専門家だから CISO が最終責任」と選ばせる問題が定番です。データオーナーはデータ分類の決定、運用チームは日々の作業の責任を持つにとどまります。トップダウンアプローチの原則とセットで覚えましょう。

</details>

**問2.** 新しいセキュリティプログラムを立ち上げるとき、計画の出発点として最も適切 (BEST) なものはどれですか？

1. 組織の事業目標とミッション
2. 最新のファイアウォール製品の選定
3. 現場エンジニアからの改善要望リスト
4. 競合他社が導入しているセキュリティ製品の調査

<details><summary>答えと解説</summary>

正解: **1**

セキュリティガバナンスの核心は事業目標との整合 (alignment) です。セキュリティは事業を支える手段なので、計画は必ず組織のミッション・事業目標から出発します。製品選定から入るのは手段の目的化、現場要望からの積み上げはボトムアップで CISSP では不正解側の定番、他社の真似は自社のリスクと合う保証がありません。「技術より先にビジネス」が CISSP 的思考の基本です。

</details>

**問3.** ある企業の経営陣は、情報漏えいのリスクを調査・評価させ、その結果に基づいてセキュリティポリシーを策定・承認しました。この活動は何に該当しますか？

1. デューケア (Due Care)
2. デューデリジェンス (Due Diligence)
3. 職務の分離 (Separation of Duties)
4. 最小権限の原則 (Least Privilege)

<details><summary>答えと解説</summary>

正解: **2**

リスクを「調査・評価し、計画やポリシーを策定する」のはデューデリジェンス（知るための活動、Do Detect）です。策定したポリシーを実際に実行・運用する段階がデューケア（行動、Do Correct）になります。「策定まで」か「実行しているか」で区別するのがコツです。職務の分離や最小権限はアクセス制御の原則で、この文脈とは別の話です。

</details>

**問4.** あなたは CISO です。自社の SOC（セキュリティ監視）業務を外部企業に委託することになりました。委託後のセキュリティの責任について最も適切 (MOST) な説明はどれですか？

1. 契約により、監視対象システムの事故の責任はすべて委託先に移転する
2. 委託先が SLA を満たしている限り、委託元に監督義務はない
3. セキュリティの責任は委託元に残り、委託先を継続的に監督する必要がある
4. 責任は委託元と委託先で均等に分担される

<details><summary>答えと解説</summary>

正解: **3**

業務は委託できても責任 (accountability) は委託できない、が第三者ガバナンスの大原則です。委託元は契約・SLA の設定に加え、監査や報告などで委託先を継続的に監督する義務を負います。「契約で責任を移転できる」「SLA を満たせば監督不要」は、どちらも委託すれば安心というひっかけです。責任の均等分担という考え方も CISSP にはありません。

</details>

**問5.** セキュリティポリシーの策定と承認は、組織のどの層が主導すべきとされていますか？

1. 現場チームが起案し、現場リーダーが承認するボトムアップ型
2. 経営層が方針を示し承認するトップダウン型
3. 外部コンサルタントが策定し、そのまま全社に適用する
4. 各部門が独自に策定し、部門ごとに運用する

<details><summary>答えと解説</summary>

正解: **2**

セキュリティガバナンスはトップダウンアプローチが原則です。経営層が方針を定めて承認し、予算と人員を割り当てることで、全社に強制力のあるプログラムになります。ボトムアップは経営の支持と資源を欠くため CISSP では不正解の定番です。外部コンサルタントの成果物をそのまま使うのは自社の事業目標との整合を欠き、部門ごとのばらばらな運用は統制が取れません。

</details>

## 3. ポリシー体系（ポリシー・標準・手順・ガイドライン）

### セキュリティ文書は階層でできている

セキュリティの文書体系は、上位の方針から下位の具体的な手順書へと階層になっています。**どれが必須 (mandatory) で、どれが任意 (discretionary) か**が超頻出ポイントです。

| 文書 | 性格 | 内容 |
|---|---|---|
| **ポリシー** (Policy) | **必須** | 経営層が定める方針。「何を守るか・なぜか」を宣言する。具体的な製品名や設定値は書かない |
| **標準** (Standard) | **必須** | ポリシーを実現するための統一的な要求事項。「ノート PC は全台 AES-256 でディスク暗号化する」など具体的 |
| **ベースライン** (Baseline) | **必須** | システムが満たすべき**最低限**のセキュリティ構成レベル |
| **手順** (Procedure) | **必須** | 作業を実行するためのステップバイステップの手順書。文書体系の最下層 |
| **ガイドライン** (Guideline) | **任意** | 推奨・ベストプラクティス。従うことが望ましいが強制ではない |

💡 コツ: 「必須か任意か」で切ると、任意なのは**ガイドラインだけ**です。「方針ならポリシー、具体的な要求なら標準、最低ラインならベースライン、手順書ならプロシージャ、推奨ならガイドライン」と1対1で言えるようにしましょう。

### ポリシーの種類

- **組織ポリシー** (Organizational Policy): 全社のセキュリティプログラム全体の方針
- **課題別ポリシー** (Issue-specific Policy): 電子メール利用、リモートワークなど特定テーマ向け
- **システム別ポリシー** (System-specific Policy): 特定のシステムや機器に対する方針

従業員が守るべき利用ルールを定めた **AUP** (Acceptable Use Policy: 利用規程) は課題別ポリシーの代表例で、入社時に同意させるのが一般的です。ポリシーは事業や技術の変化に合わせて**定期的に見直す**ことも忘れてはいけません。

### 確認問題

**問1.** 「社給ノート PC は全台、AES-256 によるフルディスク暗号化を必須とする」という文書は、セキュリティ文書体系のどれに該当しますか？

1. ポリシー (Policy)
2. ガイドライン (Guideline)
3. 標準 (Standard)
4. 手順 (Procedure)

<details><summary>答えと解説</summary>

正解: **3**

特定の技術・設定を全社で統一的に要求する具体的かつ必須の文書は標準 (Standard) です。ポリシーは「会社の情報資産を保護する」といった方針レベルで、製品名や暗号アルゴリズムのような具体的な記述はしません。手順は「暗号化を有効にする操作ステップ」を書く文書、ガイドラインは任意の推奨です。「具体的で必須＝標準」がひっかけ対策の決め手です。

</details>

**問2.** セキュリティ文書体系のうち、従うことが「任意 (discretionary)」とされるものはどれですか？

1. ガイドライン (Guideline)
2. 標準 (Standard)
3. ベースライン (Baseline)
4. 手順 (Procedure)

<details><summary>答えと解説</summary>

正解: **1**

任意なのはガイドラインだけです。ガイドラインは推奨やベストプラクティスを示す文書で、状況に応じた柔軟な判断を許します。ポリシー・標準・ベースライン・手順はすべて必須 (mandatory) です。試験では「ガイドラインも必須である」「標準は任意である」といった逆の記述でひっかけてくるので、「任意＝ガイドラインのみ」と一点で覚えてしまうのが確実です。

</details>

**問3.** あなたはセキュリティ管理者です。新しく導入するサーバー群に対して「最低限満たすべきセキュリティ構成レベル」を定義した文書を整備したいと考えています。作成すべき文書として最も適切 (BEST) なものはどれですか？

1. 手順 (Procedure)
2. ベースライン (Baseline)
3. 課題別ポリシー (Issue-specific Policy)
4. ガイドライン (Guideline)

<details><summary>答えと解説</summary>

正解: **2**

「最低限満たすべきセキュリティ構成レベル」はベースラインの定義そのものです。手順は作業ステップの文書なので構成レベルの定義には使いません。課題別ポリシーはメール利用などテーマ別の方針であり、個々のサーバー構成の最低ラインを定める文書ではありません。ガイドラインは任意の推奨なので「必ず満たすべき最低限」という要件に合いません。キーワード（最低限のレベル）と文書名を直結させましょう。

</details>

**問4.** 入社時に従業員へ同意させる、会社の IT 資産の許容される使い方を定めた文書 AUP は何の略ですか？

1. Authorized User Program
2. Acceptable Use Policy
3. Access Usage Procedure
4. Asset Utilization Plan

<details><summary>答えと解説</summary>

正解: **2**

AUP は Acceptable Use Policy（利用規程）の略で、会社のシステムやネットワークの許容される使い方・禁止事項を定めた課題別ポリシーの代表例です。違反時の懲戒の根拠にもなるため、入社時に読ませて同意の署名を取るのが一般的です。他の選択肢はもっともらしい英語を並べたダミーです。略語問題は日本語版の試験でも英語のまま出るので、原語で覚えておきましょう。

</details>

**問5.** あなたは CISO です。経営層に承認を求めるセキュリティポリシーの草案をレビューしています。ポリシー文書に含める内容として最も不適切なものはどれですか？

1. セキュリティに対する経営層のコミットメントの宣言
2. 保護すべき情報資産の範囲と目的
3. 特定ベンダーのファイアウォール製品名と推奨設定値
4. 違反した場合の罰則についての方針

<details><summary>答えと解説</summary>

正解: **3**

ポリシーは「何を・なぜ守るか」を示す方針レベルの文書で、特定の製品名や設定値のような実装の詳細は書きません。詳細は下位の標準や手順に委ねます。製品名を書いてしまうと、製品を入れ替えるたびに経営層の承認を取り直す羽目になり、文書体系の階層化の利点が失われます。経営層のコミットメント、適用範囲と目的、罰則の方針はいずれもポリシーに含める定番の要素です。

</details>

## 4. セキュリティ制御の分類（タイプ×機能）

### 制御は「実施方法」と「機能」の2軸で分類する

セキュリティ制御 (Security Control) は、**実施方法 (type)** と**機能 (function)** の2つの軸で分類します。この分類は D1 だけでなく試験全体で問われ続ける、最重要の道具箱です。

**実施方法による分類（3つ）**

| タイプ | 内容 | 例 |
|---|---|---|
| **管理的** (Administrative/Managerial) | 文書・プロセス・人の管理 | ポリシー、教育、背景調査、職務の分離 |
| **技術的** (Technical/Logical) | ハードウェア・ソフトウェアの仕組み | ファイアウォール、暗号化、IDS、アクセス制御リスト |
| **物理的** (Physical) | 物理的な接触を制御 | 施錠、フェンス、警備員、監視カメラ |

**機能による分類（主要7つ）**

| 機能 | 狙い | 例 |
|---|---|---|
| **抑止** (Deterrent) | 攻撃する気を失わせる | 警告掲示、「監視カメラ作動中」の表示 |
| **予防** (Preventive) | 発生そのものを防ぐ | 施錠、暗号化、アクセス制御 |
| **発見** (Detective) | 起きたことを見つける | 監視カメラの録画確認、IDS、監査ログ |
| **是正** (Corrective) | 被害を修復して通常へ戻す | ウイルス駆除、パッチ適用 |
| **復旧** (Recovery) | より大きな損害からの回復 | バックアップからの復元、DR サイト |
| **補償** (Compensating) | 本来の制御が使えないときの代替 | 職務の分離ができない場合の操作ログ強化 |
| **指示** (Directive) | 望ましい行動を指示・強制する | ポリシー、避難経路の標識 |

💡 コツ: 同じモノでも使い方で機能が変わります。**警備員**は立っているだけで抑止、侵入を止めれば予防、巡回で見つければ発見。**監視カメラ**は「作動中」の掲示が抑止、リアルタイム監視が発見です。問題文の「何をさせたいか」で機能を判定しましょう。多層防御 (Defense in Depth) では、これらを組み合わせて単一障害点をなくします。

### 確認問題

**問1.** バックアップからシステムを復元して業務を再開できるようにする制御は、機能による分類ではどれに該当しますか？

1. 予防的制御 (Preventive)
2. 発見的制御 (Detective)
3. 復旧的制御 (Recovery)
4. 抑止的制御 (Deterrent)

<details><summary>答えと解説</summary>

正解: **3**

バックアップからの復元や DR サイトへの切り替えのように、損害から通常状態へ回復させる制御は復旧的制御 (Recovery) です。予防は発生前に防ぐもの、発見は起きたことを見つけるもの、抑止は攻撃の意欲をくじくもので、いずれも「起きてしまった後に戻す」機能ではありません。是正 (Corrective) と復旧の区別も問われますが、ウイルス駆除のような小さな修復が是正、バックアップ復元のような大きな回復が復旧、と覚えると整理できます。

</details>

**問2.** セキュリティ意識向上トレーニング（教育）は、実施方法による分類ではどれに該当しますか？

1. 管理的制御 (Administrative)
2. 技術的制御 (Technical)
3. 物理的制御 (Physical)
4. 論理的制御 (Logical)

<details><summary>答えと解説</summary>

正解: **1**

教育・訓練はポリシーや背景調査と同じく、人とプロセスを対象とする管理的制御 (Administrative) です。技術的制御（論理的制御と同義）はファイアウォールや暗号化などソフトウェア・ハードウェアの仕組み、物理的制御は施錠やフェンスなど物理的な接触の制御です。選択肢の「論理的制御」は技術的制御の別名であり、教育には当てはまりません。同義語を別の選択肢に見せかけるのも定番のひっかけです。

</details>

**問3.** データセンターの入口に「監視カメラ作動中・不正侵入は通報します」という掲示を設置しました。この掲示が主に果たす機能はどれですか？

1. 発見的制御 (Detective)
2. 抑止的制御 (Deterrent)
3. 是正的制御 (Corrective)
4. 補償的制御 (Compensating)

<details><summary>答えと解説</summary>

正解: **2**

掲示そのものは侵入を物理的に防ぐことも検知することもできませんが、「見られている・通報される」と思わせて攻撃の意欲をくじきます。これが抑止的制御 (Deterrent) です。カメラの録画をレビューして侵入を見つけるなら発見的制御ですが、この問題で問われているのは掲示の機能です。同じカメラでも使い方で機能が変わる、という典型論点なので、問題文の主語（掲示なのかカメラ運用なのか）を正確に読み取りましょう。

</details>

**問4.** あなたはセキュリティ管理者です。小規模な経理チームでは発注担当と支払承認担当を分ける職務の分離が人数的に実現できません。この状況で導入する制御として最も適切 (BEST) なものはどれですか？

1. リスクを文書化して何も対策しない
2. 全操作の詳細ログ取得と上長による定期レビューを導入する
3. 経理システムの利用を停止する
4. 担当者にセキュリティ教育を追加で実施する

<details><summary>答えと解説</summary>

正解: **2**

本来の制御（職務の分離）が実現できないとき、代わりに同等の目的を果たす制御を補償的制御 (Compensating Control) と呼びます。詳細ログと定期レビューは「一人で不正を完結させない」という職務の分離の狙いを代替する典型例です。何もしないのはリスク放置で、経営判断としての正式なリスク受容とも異なります。システム停止は事業目標に反し、教育だけでは不正の機会そのものを統制できません。「本来の制御が使えない→補償的制御」の流れを覚えましょう。

</details>

**問5.** 多層防御 (Defense in Depth) の考え方の説明として最も適切 (MOST) なものはどれですか？

1. 最も強力な制御を1つ選び、そこに予算を集中させる
2. 予防的制御だけを複数重ねて、攻撃の発生をゼロにする
3. 種類の異なる制御を複数の層で組み合わせ、1つが破られても次の層で守る
4. すべての制御を技術的制御に統一し、人為ミスを排除する

<details><summary>答えと解説</summary>

正解: **3**

多層防御は、管理的・技術的・物理的、そして予防・発見・復旧といった異なる種類の制御を層状に組み合わせ、単一の制御の突破が全体の侵害に直結しないようにする考え方です。1つの強力な制御への集中は単一障害点 (Single Point of Failure) を生みます。予防だけを重ねても攻撃はゼロにできないため、発見・対応の層が必要です。技術で人為ミスをゼロにする発想も、人・プロセス・物理を含めた層の考え方に反します。

</details>
