# 第16章 無線・モバイル・クラウドのネットワーク【D4】

無線LAN・モバイル・セルラーなど「ケーブルのないネットワーク」はCISSPのD4で確実に問われる領域です。この章ではWEPからWPA3までの進化、リモートアクセスとモバイル端末の統制、5Gや衛星といった新しい接続のリスクを、管理者としてどう選択・統制するかという視点で学びます。

## 1. 無線LANのセキュリティ（WEPからWPA3まで）

### 無線LAN規格の進化

無線LANは電波が壁を越えて届くため、「盗聴されている前提」で暗号化と認証を設計します。端末は **AP (アクセスポイント: 無線端末をつなぐ親機)** に接続し、AP は **SSID** (無線ネットワークの名前。例: `example-office`) を名乗ります。規格の進化は超頻出です。

| 規格 | 暗号方式 | 試験での位置づけ |
|---|---|---|
| WEP | RC4（静的鍵・短いIV） | 数分で解読可能。**使用禁止** |
| WPA | TKIP（RC4ベース） | WEPの応急処置。現在は非推奨 |
| WPA2 | CCMP（**AES** を使う暗号化と改ざん検知の方式） | 長年の標準。PSKは辞書攻撃に注意 |
| WPA3 | **SAE** + AES | オフライン辞書攻撃に強く、**前方秘匿性 (forward secrecy)** を提供 |

RC4 と AES は L11 で見た共通鍵暗号です。WEP の弱点は、パケットごとに鍵を変えるための **IV (初期化ベクトル)** が 24 ビットしかなく、通信量が多いとすぐに同じ値が繰り返されることです。同じ IV のパケットを集めると鍵を計算できてしまいます。TKIP は WEP 用の古い機器でも動くようにパケットごとの鍵の作り方を改良したものですが、RC4 のままなので現在は使いません。

### 認証の2モード

- **パーソナルモード**: 事前共有鍵 (PSK: 全員が同じ Wi-Fi パスワードを入力する方式)。家庭・小規模向け。全員が同じ鍵を知るのが弱点です
- **エンタープライズモード**: **802.1X + EAP** で RADIUS サーバが利用者ごとに認証します。企業では原則こちらです

EAP の種類では、クライアントとサーバの**双方に証明書**を要求する **EAP-TLS** が最も安全です。PEAP はサーバ証明書で TLS トンネルを作り、その中でパスワード認証を行います。LEAP は脆弱で使いません。

### WPA2-PSK はなぜ辞書攻撃に弱く、WPA3-SAE はなぜ強いのか

WPA2 パーソナルでは、接続のたびに端末と AP が **4ウェイハンドシェイク** (暗号鍵を作るための4回のやり取り) を行います。

1. 端末と AP は、PSK (Wi-Fi のパスワード) と SSID から、同じ親鍵 (PMK) をそれぞれ計算します。パスワードそのものは電波に流れません
2. AP と端末が乱数 (ANonce と SNonce) を交換し、親鍵と乱数から今回の接続だけの通信鍵 (PTK) を作ります
3. 互いに「同じ鍵を持っている」ことを示す検証値 (MIC) を送り合い、暗号化通信を始めます

攻撃者はこの4回を盗聴して持ち帰れば、手元で「パスワードが `password123` なら MIC はこの値になるはず」と、辞書の単語を次々に試せます。これが**オフライン辞書攻撃**で、AP に問い合わせないのでロックもされず、検知もされません。さらにパスワードが判明すると、録っておいた過去の通信まで復号できます。

WPA3 の **SAE** では、パスワードを使った鍵交換が「1回試すごとに相手との実際のやり取りが必要」な作りになっていて、盗聴データを持ち帰っても手元で総当たりできません。また接続ごとに使い捨ての鍵を作るので、後でパスワードが漏れても過去の通信は復号できません。これが**前方秘匿性 (forward secrecy)** です。

### エンタープライズモードの接続の流れ (EAP-TLS の例)

L15 で見た 802.1X と同じ3役で、無線では AP がオーセンティケータになります。EAP (Extensible Authentication Protocol) は、パスワードや証明書など様々な認証方式を載せられる共通の枠組みです。

1. 端末 (サプリカント) が AP に接続します。この時点では EAP のやり取りしか通りません
2. AP は端末の EAP メッセージを RADIUS サーバー (例: 192.0.2.5) へ中継します
3. RADIUS サーバーがサーバー証明書を提示し、端末は「社内の認証局が発行した正しい証明書か」を検証します (偽の AP・偽の RADIUS につながるのを防ぎます)
4. 端末もクライアント証明書を提示し、RADIUS サーバーが検証します
5. 成功すると RADIUS サーバーは Access-Accept と、この利用者専用の親鍵 (PMK) を AP に渡します
6. AP と端末が4ウェイハンドシェイクで通信鍵を作り、暗号化通信が始まります

PSK と違って利用者ごとに鍵が別になり、退職者は証明書やアカウントを無効にするだけで締め出せます。PEAP の場合は3の後、TLS の暗号化トンネルの中で ID とパスワードを送ります。端末がサーバー証明書の検証を省くと、偽の RADIUS サーバーに認証情報を渡してしまう点が弱点です。

### 「気休め」対策と無線への攻撃

SSID ステルスや MAC アドレスフィルタは、盗聴ツールで容易に回避できるため**主要な防御にはなりません**。攻撃としては、正規と同名の偽APへ誘導する **Evil Twin（不正AP: rogue AP）**、管理フレーム (接続・切断などを指示する制御用の通信) を偽造して切断させる**ディスアソシエーション攻撃**、車で電波を探し回る**ウォードライビング**、PIN 総当たりに弱い **WPS** (ボタンや 8 桁の PIN で簡単に接続設定する機能) の悪用を押さえましょう。

- ディスアソシエーション攻撃: WPA2 では管理フレームが暗号で保護されないことが多く、攻撃者が AP のふりをして「切断せよ」を送れます。切断された端末が再接続するときの4ウェイハンドシェイクを盗聴したり、Evil Twin へ誘導したりするのに使われます。対策は管理フレームを保護する **PMF (802.11w)** で、WPA3 では必須です
- WPS: 8 桁の PIN は前半4桁と後半を別々に確認する作りで、後半の最後の1桁は検査用の数字です。そのため最大 10,000 + 1,000 = 11,000 回試せば当たります。WPS は無効にします

💡 コツ: 導入前の**サイトサーベイ**（電波調査）でアンテナ配置と出力を調整し、電波を敷地外へ漏らさないのが管理者の第一歩です。「最も安全な無線認証は？」→ EAP-TLS、「今から選ぶ暗号化は？」→ WPA3 と即答できるようにしてください。

### 確認問題

**問1.** WPA3 がパーソナルモードで導入した鍵交換方式で、オフライン辞書攻撃への耐性と前方秘匿性を提供するものはどれでしょう？

1. TKIP
2. SAE (Simultaneous Authentication of Equals)
3. WPS
4. 静的 WEP キー

<details><summary>答えと解説</summary>

正解: **2**

WPA3 は PSK の握手を SAE（別名 Dragonfly）に置き換え、パケットを収集してオフラインでパスワードを総当たりする攻撃を困難にし、前方秘匿性 (forward secrecy) も提供します。TKIP は WPA の暗号方式で RC4 ベースの応急処置、WPS は PIN 総当たりに弱い簡易設定機能、静的 WEP キーは数分で解読される廃止技術です。「WPA3 = SAE + 前方秘匿性」はセットで覚えましょう。

</details>

**問2.** 社員がカフェで会社と同じ SSID 名のアクセスポイントに接続したところ、通信内容を攻撃者に取得されていました。この攻撃を何と呼ぶでしょう？

1. ウォードライビング (war driving)
2. ディスアソシエーション攻撃
3. WPS PIN 総当たり
4. Evil Twin（悪魔の双子）

<details><summary>答えと解説</summary>

正解: **4**

正規のアクセスポイントと同じ（または紛らわしい）SSID を名乗る偽 AP を立て、利用者を接続させて通信を中間者として窃取するのが Evil Twin です。ウォードライビングは電波を探し回る「偵察」で窃取そのものではなく、ディスアソシエーション攻撃は切断を引き起こす攻撃、WPS PIN 総当たりは AP への侵入手口です。「同名 SSID + 利用者が接続してしまう」というキーワードが出たら Evil Twin を選びます。

</details>

**問3.** WPA2 パーソナル (PSK) の無線 LAN に対し、攻撃者がオフライン辞書攻撃でパスワードを割り出すために盗聴して持ち帰るものとして、最も適切なものはどれでしょう？

1. AP が定期的に送る SSID の告知 (ビーコン) だけ
2. RADIUS サーバーが返す Access-Accept のメッセージ
3. 端末と AP が接続時に行う4ウェイハンドシェイクのやり取り
4. 端末の MAC アドレスの一覧

<details><summary>答えと解説</summary>

正解: **3**

WPA2-PSK では、パスワードと SSID から作った親鍵と、4ウェイハンドシェイクで交換した乱数から通信鍵が作られ、検証値 (MIC) が送られます。このやり取りを録っておけば、攻撃者は手元で候補のパスワードから MIC を計算して一致を探せます。ビーコンや MAC アドレスの一覧からはパスワードを検算できず、Access-Accept はエンタープライズモードの RADIUS のメッセージで PSK には登場しません。WPA3 の SAE は、まさにこの「録って持ち帰り、手元で試す」攻撃を防ぐために導入されました。

</details>

**問4.** エンタープライズ無線LANで最も強固な認証を実現したい場合、選択すべき EAP 方式はどれでしょう？

1. EAP-TLS
2. LEAP
3. PEAP
4. EAP-MD5

<details><summary>答えと解説</summary>

正解: **1**

EAP-TLS はサーバとクライアントの双方にデジタル証明書を要求する相互認証で、パスワードに依存しないため最も安全とされます。PEAP はサーバ証明書のみで TLS トンネルを張り内部でパスワード認証するため EAP-TLS より弱く、LEAP は既知の脆弱性がある Cisco 独自方式、EAP-MD5 は盗聴に弱く無線では使いません。「最も安全な EAP = EAP-TLS（両側証明書）」は定番の問われ方です。

</details>

**問5.** 新しいオフィスに無線LANを導入します。電波が敷地外へ漏れて駐車場から盗聴されるリスクを抑えるために、最初に (FIRST) 実施すべきものはどれでしょう？

1. SSID をステルス設定にする
2. MAC アドレスフィルタを有効にする
3. サイトサーベイを実施してアンテナ配置と出力を設計する
4. 全端末に VPN クライアントを配布する

<details><summary>答えと解説</summary>

正解: **3**

電波の到達範囲という物理的な問題には、導入前のサイトサーベイ（電波調査）でアンテナの位置・向き・出力を設計するのが根本対策であり、計画段階で最初に行うべき活動です。SSID ステルスと MAC フィルタは盗聴ツールで容易に回避できる「気休め」で、漏れた電波自体は減りません。VPN は通信の暗号化には有効ですが、電波漏えいの範囲を抑える対策ではありません。CISSP では「場当たりな設定より、まず調査と設計」という発想が正解になりやすいことを覚えておきましょう。

</details>

**問6.** SSID ステルス（ブロードキャスト停止）と MAC アドレスフィルタリングについて、最も適切 (MOST accurate) な説明はどれでしょう？

1. 両方を併用すれば WPA2 と同等の保護が得られる
2. 攻撃の手間をわずかに増やすが、ツールで容易に回避されるため主要な防御にしてはならない
3. MAC アドレスは暗号化されるため、フィルタリングは強力な認証手段である
4. SSID を隠せば Evil Twin 攻撃は成立しなくなる

<details><summary>答えと解説</summary>

正解: **2**

SSID はプローブ応答などから、MAC アドレスは平文のフレームヘッダから盗聴で判明し、MAC は偽装（スプーフィング）も簡単です。したがってこれらは多層防御のごく薄い一枚にはなっても、暗号化・認証の代わりにはなりません。WPA2 相当の保護にはならず、MAC アドレスは暗号化されず、SSID を隠しても偽 AP は立てられるため他の選択肢は誤りです。試験では「ステルスとMACフィルタ=主要な防御ではない」と断言できるかが問われます。

</details>

## 2. モバイルとリモートアクセスの統制

### VPN — トンネルの張り方で統制が変わる

リモートアクセスの基本は VPN (インターネット上に暗号化した専用の通り道=トンネルを作る技術。L14 で見た IPsec や TLS を使います) です。**リモートアクセス VPN**（個人端末→社内）と**サイト間 VPN**（拠点間常時接続）を区別しましょう。頻出なのがトンネル方式の違いです。

| 方式 | 動き | リスク・特徴 |
|---|---|---|
| フルトンネル | 全通信を VPN 経由で社内に送る | 社内のセキュリティ装置で**全通信を検査できる**。帯域は消費 |
| スプリットトンネル | 社内宛だけ VPN、他は自宅回線から直接 | 帯域は節約できるが、**検査を迂回した直接通信**が発生し統制が弱まる |

自宅 PC (VPN 接続中) から2つの宛先へ送るとき、通り道は次のように変わります。社内は 192.0.2.0/24 とします。

| 宛先 | フルトンネル | スプリットトンネル |
|---|---|---|
| 192.0.2.50 (社内ファイルサーバー) | VPN → 社内 | VPN → 社内 |
| 198.51.100.80 (外部の Web サイト) | VPN → 社内のプロキシ・IPS で検査 → インターネット | 自宅ルータから直接インターネットへ (社内の検査を通らない) |

統制を最優先するなら、端末起動時から自動接続する**常時 VPN (always-on VPN)** + フルトンネルが堅い構成です。

### モバイル端末管理 — MDM/UEM

会社のデータがポケットの中の端末に乗る以上、**MDM/UEM** (MDM: スマホ等を遠隔管理する仕組み、UEM: PC も含めて一元管理する仕組み) による統制が必須です。紛失時の**リモートワイプ**、業務領域だけを分離する**コンテナ化**（選択的ワイプが可能）、位置に応じて機能を制限する**ジオフェンシング**、脱獄・root 化 (OS の制限を外して最上位の権限を得ること。MDM の制御を無効にできてしまう) の検知などを押さえます。MDM で配る設定は、たとえば次のようなものです。

| 項目 | 設定値の例 |
|---|---|
| 画面ロック | 6 桁以上の PIN、5 分操作がなければ自動ロック |
| ロック解除の失敗 | 10 回失敗で業務コンテナを消去 |
| 端末の状態 | 脱獄・root 化を検知したら業務アプリを停止 |
| ジオフェンシング | 研究所の敷地内ではカメラを無効化 |
| 紛失時 | 管理画面からリモートワイプ (遠隔でデータ消去) |

### 所有形態 — BYOD / COPE / CYOD

- **BYOD** (Bring Your Own Device): 個人所有端末を業務利用。コスト安だが会社の統制が最も弱く、私的データとの混在・プライバシー問題が生じます
- **COPE** (Corporate-Owned, Personally Enabled): 会社所有・個人利用可。会社が完全に統制でき、試験では最も管理しやすい選択肢です
- **CYOD** (Choose Your Own Device): 会社が承認したリストから社員が選ぶ中間形態

### その他の近距離通信とテレワーク

Bluetooth では、メッセージを送りつける **bluejacking**、データを窃取する **bluesnarfing**、端末を乗っ取る **bluebugging** を区別します。NFC (数 cm で通信する近接無線。非接触決済などに使う) は近接通信ですが、**リレー攻撃**に注意します。攻撃者が2台の機器でカードと決済端末の間の通信を遠くまで中継し、カードがすぐそばにあるかのように見せかける手口です。テレワークでは家庭用ルーターの初期パスワード変更、画面の覗き見（ショルダーサーフィン）、Web 会議の盗聴対策まで含めてポリシー化するのが管理者の仕事です。

💡 コツ: 「BYOD で紛失」→ 事前の同意 + MDM コンテナの選択的ワイプ、が CISSP 的な模範対応です。

### 確認問題

**問1.** スプリットトンネル VPN を許可した場合に組織が最も懸念すべき (MOST) リスクはどれでしょう？

1. VPN サーバの帯域が枯渇する
2. 端末のバッテリー消費が増える
3. 社内のセキュリティ装置による検査を受けないインターネット直接通信が発生する
4. 社内 DNS が利用できなくなる

<details><summary>答えと解説</summary>

正解: **3**

スプリットトンネルでは社内宛て以外の通信が自宅回線から直接インターネットへ出るため、プロキシや IPS など社内の検査・統制を迂回します。感染した端末が VPN 経由で社内に入る「橋渡し」になるのが最大の懸念です。帯域の節約はむしろスプリットトンネルの利点であり、バッテリーや DNS は本質的な論点ではありません。「統制の観点ではフルトンネルが BEST」という対比で覚えましょう。

</details>

**問2.** BYOD プログラムを開始するにあたり、紛失・退職時に備えて会社が最初に (FIRST) 整備すべきものはどれでしょう？

1. 全私物端末の充電設備
2. 利用条件とリモートワイプへの同意を定めたポリシーと誓約
3. 社内 Wi-Fi の増強
4. 端末購入補助金制度

<details><summary>答えと解説</summary>

正解: **2**

私物端末を会社がワイプ・監視することは、本人の事前同意なしには法的・プライバシー上の問題になります。そのため技術導入より先に、利用条件・会社の権限・リモートワイプへの同意を定めた BYOD ポリシーと誓約書を整備するのが正解です。充電設備や Wi-Fi 増強や補助金は利便性の話であり、セキュリティ統制の前提にはなりません。CISSP では「技術より先にポリシーと同意」という順序が繰り返し問われます。

</details>

**問3.** 攻撃者が Bluetooth 経由でスマートフォン内の連絡先やメールなどのデータを不正に取得する攻撃はどれでしょう？

1. bluejacking（ブルージャッキング）
2. ジオフェンシング
3. ウォードライビング
4. bluesnarfing（ブルースナーフィング）

<details><summary>答えと解説</summary>

正解: **4**

bluesnarfing は Bluetooth の脆弱性を突いて端末内のデータを「盗み取る」攻撃です。bluejacking は一方的にメッセージを「送りつける」だけでデータ窃取はしない迷惑行為、ジオフェンシングは位置情報に基づく管理機能（攻撃ではありません）、ウォードライビングは無線LANの探索行為です。jacking=送りつけ、snarfing=窃取、bugging=乗っ取り、と動詞で区別するのがコツです。

</details>

**問4.** 退職予定の社員の私物スマートフォンから、個人の写真や連絡先に触れずに業務データとアプリだけを確実に削除したい場合、最も適切な (BEST) 事前対策はどれでしょう？

1. MDM のコンテナ化を導入し業務領域の選択的ワイプを可能にしておく
2. 端末全体のフルワイプを実行する
3. 社員に業務アプリを手動で削除するよう口頭で依頼する
4. 業務データ持ち出しを禁止する誓約書のみで対応する

<details><summary>答えと解説</summary>

正解: **1**

コンテナ化（ワークプロファイル）は端末内に業務専用の分離領域を作り、その領域だけを消す選択的ワイプを可能にします。私物端末のフルワイプは個人データまで消してしまい法的トラブルの元です。口頭依頼は実施を検証できず、誓約書だけでは実際のデータは消えません。「BYOD では個人領域に触れない統制」が CISSP 的な正解の軸です。

</details>

**問5.** COPE (Corporate-Owned, Personally Enabled) モデルの説明として最も適切なものはどれでしょう？

1. 社員の私物端末をそのまま業務に使わせる
2. 会社が承認した機種リストから社員が購入する端末を選ぶ
3. 会社所有の端末を支給し、一定の個人利用も認める
4. 業務利用は会社の共用タブレットに限定する

<details><summary>答えと解説</summary>

正解: **3**

COPE は会社が所有・管理する端末を社員に支給しつつ、私的な利用もある程度許すモデルで、所有権が会社にあるため統制が最も効きます。私物をそのまま使うのは BYOD、承認リストから選ぶのは CYOD です。共用端末限定は COPE の定義ではありません。試験では「統制の強さ: COPE > CYOD > BYOD」という並びと、BYOD はプライバシー・混在リスクが高いという対比を押さえましょう。

</details>

## 3. セルラー・衛星・新しい接続技術

### セルラー (4G/5G) — 公衆網でも「自分の統制」を考える

携帯網は SIM (携帯会社が発行する IC カード。中の秘密鍵で網と相互に本人確認する) ベースの強い加入者認証を持ちますが、通信事業者のインフラである以上、組織からは中身が見えません。**5G** では**ネットワークスライシング (network slicing)** により、1つの物理網の上に論理的に分離された「スライス」を用途別に提供できます。スライス間の分離はセキュリティ機能であると同時に、分離の不備が新しいリスクにもなります。工場や港湾など、公衆網に依存せず自組織で統制したい場面では**プライベート 5G** が選択肢です。

### 衛星・光・IoT 向け通信

- **衛星通信**: 広域をカバーする反面、**電波が広範囲に届くため傍受されやすく、遅延 (送ってから届くまでの時間) も大きい**のが特徴です。機密データは**エンドツーエンドの暗号化が前提**です
- **Li-Fi**: 可視光で通信するため、**光が届く部屋の外には漏れにくい**という物理的な利点があります
- **Zigbee**: IoT (センサーや家電などネットにつながる機器) 向けの低消費電力プロトコル。鍵管理の弱さや古い機器の脆弱性が狙われます

### CDN とエッジ

**CDN (Content Delivery Network)** はコンテンツを世界中のエッジサーバに分散配置します。性能だけでなく、**DDoS トラフィックを分散して吸収し、オリジンサーバを隠す**というセキュリティ上の利点が試験で問われます。流れは次のとおりです。

1. 利用者が www.example.com を名前解決すると、オリジン (本来のサーバー 203.0.113.10) ではなく、近くの CDN エッジサーバー (例: 198.51.100.20) のアドレスが返ります
2. エッジがコンテンツを持っていればそのまま返し、なければオリジンから取ってきて返し、しばらく保存 (キャッシュ) します
3. オリジン側のファイアウォールを「CDN 事業者のアドレス帯からの TCP/443 だけ許可」にしておけば、オリジンのアドレスを知られても直接は攻撃されにくくなります

DDoS の大量の通信は世界中のエッジに分かれて届くため、1か所のオリジンに集中しません。エッジコンピューティング (端末の近くでデータを処理する方式)・フォグコンピューティング (エッジとクラウドの中間の層で処理する方式) では、データ処理が末端に分散するぶん、物理的に守りにくい場所に機器が置かれる点を考慮します。

💡 コツ: この分野の問題は個別技術の暗記よりも、「機密性・可用性の要件から通信手段をリスク評価して選ぶ」というマネジメント視点で解くのが近道です。「衛星=傍受前提で暗号化」「5G スライシング=論理分離」「CDN=DDoS 吸収」の3点は即答できるようにしましょう。

### 確認問題

**問1.** 5G ネットワークで、1つの物理インフラ上に用途ごとに論理的に分離された仮想ネットワークを提供する仕組みはどれでしょう？

1. ネットワークスライシング
2. ローミング
3. キャリアアグリゲーション
4. テザリング

<details><summary>答えと解説</summary>

正解: **1**

ネットワークスライシングは 5G の特徴で、低遅延用・IoT 用などの「スライス」を論理的に分離して提供します。セキュリティ的にはスライス間分離が肝で、分離の不備が新たな攻撃面になります。ローミングは他事業者網の利用、キャリアアグリゲーションは複数周波数を束ねる高速化技術、テザリングは端末のアクセスポイント化であり、いずれも論理分離の仕組みではありません。

</details>

**問2.** 遠隔地の拠点と衛星通信で機密データをやり取りすることになりました。最も適切な (BEST) 保護策はどれでしょう？

1. アンテナを目立たない場所に設置する
2. 通信時間帯を深夜に限定する
3. エンドツーエンドの暗号化を適用する
4. 衛星事業者との NDA のみで対応する

<details><summary>答えと解説</summary>

正解: **3**

衛星の電波は地上の広い範囲に届くため「第三者に受信される前提」で設計する必要があり、エンドツーエンド暗号化が根本対策です。アンテナの設置場所や時間帯の工夫では電波自体の傍受可能性は変えられません。NDA は事業者との契約上の約束にすぎず、経路上の傍受者には何の効力もありません。「物理的に盗聴を防げない経路 → 暗号化で守る」という原則で解けます。

</details>

**問3.** CDN (Content Delivery Network) を利用することで得られるセキュリティ上の利点として、最も適切 (MOST) なものはどれでしょう？

1. Web アプリケーションの脆弱性が自動的に修正される
2. DDoS トラフィックを世界中のエッジで分散吸収し、オリジンサーバを保護できる
3. 利用者の端末がマルウェアに感染しなくなる
4. TLS 証明書が不要になる

<details><summary>答えと解説</summary>

正解: **2**

CDN は大量のエッジサーバでトラフィックを受けるため、DDoS 攻撃を分散して吸収でき、オリジンサーバの IP を隠す効果もあります。コードの脆弱性そのものは直らず（WAF を併用しても「自動修正」ではありません）、端末のマルウェア対策とは無関係で、TLS 証明書はむしろ CDN 側にも必要です。「CDN = 可用性 (DDoS 耐性) + オリジン隠蔽」と覚えましょう。

</details>

**問4.** 通信が光の届く範囲に物理的に限定されるため、電波の漏えいによる盗聴リスクを下げられる通信技術はどれでしょう？

1. Zigbee
2. 5G
3. 衛星通信
4. Li-Fi

<details><summary>答えと解説</summary>

正解: **4**

Li-Fi は可視光（照明）で通信するため、壁を透過せず光の届く部屋の中に通信が閉じるという物理特性があり、電波型の無線より盗聴範囲を限定できます。Zigbee と 5G は電波なので壁を越えて漏れ、衛星通信はむしろ最も広範囲に電波が届きます。物理層の性質がそのままセキュリティ特性になる例として問われます。

</details>

**問5.** 港湾で数千台の IoT センサーを接続します。公衆網に依存せず、自組織の統制下で広域のモバイル接続を実現したい場合、最も適切な (BEST) 選択はどれでしょう？

1. 公衆 Wi-Fi スポットの契約
2. プライベート 5G ネットワークの構築
3. 全センサーへの衛星回線の搭載
4. Bluetooth メッシュのみでの接続

<details><summary>答えと解説</summary>

正解: **2**

プライベート 5G は自組織専用のセルラー網を構築でき、広域カバレッジ・多数接続・自組織による統制（認証・分離・監視）を同時に満たします。公衆 Wi-Fi は統制もカバレッジも不足し、衛星回線を数千台のセンサーに積むのはコストと遅延の面で不適切、Bluetooth メッシュは到達距離が短く広域には向きません。「統制したい + 広域 + 多数接続」のキーワードでプライベート 5G を選びます。

</details>
