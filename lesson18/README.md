# 第18章 認証とアイデンティティ管理【D5】

認証とアイデンティティ管理は CISSP ドメイン5(出題比率 13%)の入口です。この章では「識別→認証→認可→説明責任」という IAAA の流れ、認証の3要素、多要素認証(MFA)、バイオメトリクスの精度指標までを一気に固めます。「パスワード+PIN は多要素か?」「FAR と FRR はどちらを優先?」といった定番のひっかけを見抜けるようになるのが目標です。

## 1. IAAA — 識別から説明責任まで

### アクセス管理の5ステップ

誰かがシステムを使うとき、裏側では必ず次の流れが動いています。この流れ全体を **IAAA** と呼びます。

| ステップ | 英語 | 何をするか | 例 |
|---|---|---|---|
| 識別 | identification | 「私は〇〇です」と**主張**する | ユーザー名の入力 |
| 認証 | authentication | 主張が本人であると**証明**する | パスワードの入力 |
| 認可 | authorization | その人に**何を許すか**決める | 読み取りのみ許可 |
| 監査 | auditing | 行動を**記録**する | アクセスログ |
| 説明責任 | accountability | 行動を**本人に紐付ける** | ログとIDの突き合わせ |

- **識別は「主張」、認証は「証明」**です。ユーザー名を入れただけでは、まだ何も証明していません
- 認可は認証の**後**です。本人確認ができて初めて「どこまで許すか」が決まります
- **説明責任**が成立する条件は2つ: ①**一意の ID**(共有アカウント禁止)と ②**監査ログ**です。どちらが欠けても「誰がやったか」を証明できません

### 主体と客体

アクセスする側(ユーザーやプロセス)を**主体 (subject)**、アクセスされる側(ファイルやDB)を**客体 (object)** と呼びます。アクセス制御とは「主体が客体に何をできるかの管理」です。

💡 コツ: 試験では「説明責任を実現するために最も重要なものは?」が定番です。答えはほぼ「一意の識別 + 監査」。否認防止 (nonrepudiation) も「本人が『やっていない』と言えなくする」という点で説明責任の親戚です。

### 確認問題

**問1.** ユーザーがログイン画面でユーザー名を入力しました。IAAA のどのステップにあたりますか?

1. 認証 (authentication)
2. 認可 (authorization)
3. 識別 (identification)
4. 説明責任 (accountability)

<details><summary>答えと解説</summary>

正解: **3**

ユーザー名の入力は「私は〇〇です」という主張であり、識別 (identification) です。まだ本人である証明はしていないので認証ではありません。認証はパスワード等で主張を証明する次のステップ、認可は認証後にアクセス権を決めるステップ、説明責任は行動を本人に紐付ける最終段階です。試験では「ユーザー名=識別、パスワード=認証」の切り分けが定番のひっかけです。

</details>

**問2.** 組織内で説明責任 (accountability) を確立するために最も (MOST) 重要な組み合わせはどれですか?

1. 一意のユーザーIDと監査ログ
2. 強力なパスワードポリシーと暗号化
3. 共有アカウントとアクセス制御リスト
4. 多要素認証とファイアウォール

<details><summary>答えと解説</summary>

正解: **1**

説明責任は「どの行動を誰が行ったか」を証明できる状態です。そのためには各人を区別する一意のIDと、行動を記録する監査ログの両方が必要です。強いパスワードや MFA は認証を強化しますが、記録がなければ行動を追跡できません。共有アカウントは逆に説明責任を破壊する代表例です。「セキュリティを強くする」選択肢に流されず、問われている性質(説明責任)に直結するものを選ぶのがコツです。

</details>

**問3.** 認証に成功したユーザーに対して、ファイルの読み取りは許可するが書き込みは拒否する判断を行うのはどれですか?

1. 識別 (identification)
2. 認可 (authorization)
3. 監査 (auditing)
4. 認証 (authentication)

<details><summary>答えと解説</summary>

正解: **2**

本人確認が済んだ後に「何をどこまで許すか」を決めるのが認可 (authorization) です。認証はあくまで本人であることの証明までで、権限の判断は含みません。監査は行動の記録、識別は名乗りの段階です。「認証済み=何でもできる」ではない、という流れの順序(識別→認証→認可)を押さえましょう。

</details>

**問4.** システム管理者4人が1つの root アカウントを共有しています。この運用の最大 (BEST) の問題点はどれですか?

1. パスワードの強度が下がる
2. 認可の設定が複雑になる
3. ライセンス違反になる
4. 誰が操作したか特定できず説明責任が成立しない

<details><summary>答えと解説</summary>

正解: **4**

共有アカウントでは監査ログに残る ID が全員同じため、操作を個人に紐付けられず説明責任 (accountability) が成立しません。これが CISSP 的に最大の問題です。パスワード強度やライセンスは共有と直接の関係がなく、認可はむしろ単純になります。対策は個人アカウント+特権昇格(sudo 等)で「root を直接共有しない」ことです。

</details>

**問5.** 否認防止 (nonrepudiation) の説明として最も適切なものはどれですか?

1. データが改ざんされていないことを保証する
2. 行為者が後から「自分はやっていない」と主張できないようにする
3. 許可された人だけが情報にアクセスできるようにする
4. システムが常に利用可能であることを保証する

<details><summary>答えと解説</summary>

正解: **2**

否認防止は、送信や操作を行った本人がその事実を否定できないようにする性質で、デジタル署名や監査ログで実現します。説明責任と深く関係します。改ざんされていない保証は完全性、許可された人だけのアクセスは機密性、常に使える保証は可用性の説明で、いずれも別の性質です。性質の定義問題は選択肢がすべて「正しいことを言っている」ので、問われた用語との対応だけで選ぶのがコツです。

</details>

## 2. 認証の3要素とパスワード

### 認証の3要素(+2)

認証に使う情報は、性質ごとに**要素 (factor)** に分類されます。

| タイプ | 要素 | 英語 | 例 |
|---|---|---|---|
| Type 1 | 知識 | something you **know** | パスワード、PIN、秘密の質問 |
| Type 2 | 所持 | something you **have** | スマートカード、OTPトークン、スマホ |
| Type 3 | 生体 | something you **are** | 指紋、虹彩、顔 |
| — | 場所 | somewhere you are | 社内ネットワークからの接続 |
| — | 行動 | something you do | 署名の書き方、キーストローク |

**多要素認証 (MFA) は「異なるタイプ」の組み合わせ**です。ここが最大のひっかけポイント:

- パスワード + PIN → どちらも知識 → **単一要素 (SFA)**
- スマートカード + PIN → 所持 + 知識 → **2要素 ✅**

### パスワード管理の現代的な考え方

NIST SP 800-63B 以降、考え方が変わりました。

- **複雑さの強制より「長さ」**。長いパスフレーズを推奨します
- **定期変更の強制は非推奨**。使い回しや紙メモを誘発するためで、漏えいの兆候があったときに変更させます
- 漏えい済みパスワードのブラックリスト照合、パスワードマネージャーの利用を推奨
- アカウントロックアウトとログイン試行の監視で総当たりを防ぐ

秘密の質問 (security questions) は SNS などで答えを調べられるため、現在は弱い認証とされます。

💡 コツ: 「2つ使っているから MFA」とは限りません。試験では必ず**タイプが異なるか**を確認しましょう。

### 確認問題

**問1.** パスワードと PIN の両方を要求するシステムがあります。この認証方式の説明として正しいものはどれですか?

1. 二要素認証である
2. どちらも知識要素なので単一要素認証である
3. 所持要素と知識要素の組み合わせである
4. 生体要素を含む多要素認証である

<details><summary>答えと解説</summary>

正解: **2**

パスワードも PIN も「知っていること (something you know)」という同じタイプなので、2つ使っても単一要素認証 (SFA) のままです。多要素認証と呼べるのは、知識+所持、知識+生体のように異なるタイプを組み合わせた場合だけです。これは CISSP で最も有名なひっかけの1つで、「2つ=2要素」と機械的に考えないことが重要です。

</details>

**問2.** 「something you have(所持要素)」に分類されるものはどれですか?

1. 虹彩パターン
2. パスフレーズ
3. キーストロークの癖
4. ワンタイムパスワードを生成するハードウェアトークン

<details><summary>答えと解説</summary>

正解: **4**

ハードウェアトークンは物理的に持っているものなので所持要素 (Type 2) です。虹彩は生体要素 (Type 3)、パスフレーズは知識要素 (Type 1)、キーストロークの癖は行動要素 (something you do) に分類されます。各要素の代表例を表で対応づけて覚えると、組み合わせが MFA かどうかの判定も速くなります。

</details>

**問3.** 最新のガイドライン(NIST SP 800-63B)の方向性に沿ったパスワードポリシーとして最も適切 (BEST) なものはどれですか?

1. 90日ごとの定期変更を全ユーザーに強制する
2. 記号・数字・大文字をすべて含む8文字を要求する
3. 長いパスフレーズを許容し、漏えい時のみ変更を求める
4. 秘密の質問を第2の認証手段として追加する

<details><summary>答えと解説</summary>

正解: **3**

現代のガイドラインは「複雑さの強制や定期変更の強制」から「長さの確保と漏えい時対応」へ転換しています。定期変更の強制は Password1→Password2 のような弱い変更や使い回しを誘発するため非推奨です。記号必須の複雑さ要求も同様に形骸化しやすく、秘密の質問は SNS で調べられる弱い知識要素です。古い常識が誤答選択肢として並ぶ典型問題です。

</details>

**問4.** 攻撃者がヘルプデスクに電話して従業員になりすまし、パスワードリセットを依頼する攻撃が続いています。最も効果的 (MOST) な対策はどれですか?

1. リセット前の本人確認手続きを強化する
2. パスワードの最小文字数を16文字にする
3. 全社員のパスワードを毎月変更させる
4. ヘルプデスクの通話をすべて録音する

<details><summary>答えと解説</summary>

正解: **1**

この攻撃はパスワードの強度と無関係に、リセット手続きというプロセスの穴を突くソーシャルエンジニアリングです。したがって対策もプロセス側、つまりリセット前の本人確認(登録済みデバイスへの通知、上長確認、MFA での確認など)の強化が最も効果的です。文字数や定期変更は盗まれる経路に効かず、録音は事後の調査には役立ちますが予防になりません。「攻撃がどこを突いているか」に対策を合わせるのが CISSP 流です。

</details>

**問5.** アカウントロックアウトポリシーが主に防ぐ攻撃はどれですか?

1. フィッシングによるパスワード詐取
2. ショルダーサーフィン
3. オンラインでの総当たり(ブルートフォース)攻撃
4. キーロガーによる入力記録

<details><summary>答えと解説</summary>

正解: **3**

ロックアウトは一定回数ログインに失敗したアカウントを一時的に使えなくする仕組みで、オンラインでパスワードを片端から試す総当たり攻撃を直接妨げます。フィッシングやキーロガーは正しいパスワードを盗むため失敗回数が増えず、ロックアウトでは防げません。ショルダーサーフィンも盗み見であり試行回数と無関係です。対策と攻撃の対応関係を一対一で覚えておくと、シナリオ問題で迷いません。

</details>

## 3. 多要素認証とデバイス認証

### ワンタイムパスワード (OTP)

使い捨てパスワードを生成する仕組みは2方式あります。

| 方式 | 基準 | 特徴 |
|---|---|---|
| **HOTP** | カウンタ(イベント) | ボタンを押すたびに生成。**使うまで有効なまま**残る |
| **TOTP** | 時刻 | 30〜60秒で**自動失効**。スマホ認証アプリの主流 |

「H はイベント(回数)、T は Time」で覚えます。失効までの猶予が短い TOTP の方が盗まれたコードを使われにくい方式です。

### 主な MFA 手段と弱点

- **スマートカード (PIV/CAC) + PIN**: 所持+知識の代表例。証明書ベースで強力
- **プッシュ通知**: 便利ですが、攻撃者が大量に通知を送って誤承認を誘う **MFA 疲労攻撃 (MFA fatigue)** が問題に。対策は**ナンバーマッチング**(画面の数字を入力させる)など
- **SMS**: **SIM スワップ**(電話番号の乗っ取り)で傍受されるため、最も弱い MFA とされます
- **FIDO2 / WebAuthn**: 公開鍵暗号ベースで、サイトごとに鍵が分かれ**フィッシング耐性が最も高い**方式。偽サイトには正しい応答を返せません

### デバイス認証

人だけでなく端末も認証する考え方です。クライアント証明書を配布して会社支給端末だけを接続させる、MDM で管理状態を確認してからアクセスを許すなど、ゼロトラストの文脈で重要になっています。

💡 コツ: 「フィッシング耐性が最も高い MFA は?」→ FIDO2/WebAuthn、「最も弱い MFA は?」→ SMS。この両端が頻出です。

### 確認問題

**問1.** TOTP が HOTP より安全とされる主な理由はどれですか?

1. 生成されたコードが短時間で自動的に失効するから
2. コードの桁数が多いから
3. ハードウェアトークンでしか使えないから
4. サーバー側に秘密鍵を保存しないから

<details><summary>答えと解説</summary>

正解: **1**

TOTP は時刻ベースで 30〜60 秒ごとにコードが変わるため、盗まれたコードを後から使う余地がほとんどありません。HOTP はカウンタベースで、生成したコードが使用されるまで有効に残る点が弱みです。桁数やトークンの形態は方式の違いと無関係で、どちらも共有秘密鍵をサーバー側にも保持します。「H=イベント、T=時刻」の区別は頻出です。

</details>

**問2.** 従業員を狙ったフィッシングサイトによる認証情報の窃取が多発しています。フィッシング耐性の観点で最も強力 (BEST) な認証方式はどれですか?

1. SMS で送るワンタイムコード
2. FIDO2/WebAuthn による認証
3. 認証アプリの TOTP
4. より長いパスワードと秘密の質問

<details><summary>答えと解説</summary>

正解: **2**

FIDO2/WebAuthn は公開鍵暗号を使い、鍵がサイト(オリジン)ごとに紐付くため、偽サイトに対しては正しい応答がそもそも生成されません。これがフィッシング耐性と呼ばれる理由です。SMS や TOTP のコードは、本物そっくりの偽サイトに利用者が入力すれば中継されてしまいます(リアルタイムフィッシング)。パスワードの強化はフィッシングには無力です。「MFA ならフィッシングに安全」とは限らない点がひっかけです。

</details>

**問3.** SIM スワップ攻撃によって無効化されやすい認証手段はどれですか?

1. スマートカードと PIN
2. SMS によるワンタイムコード
3. FIDO2 セキュリティキー
4. 虹彩認証

<details><summary>答えと解説</summary>

正解: **2**

SIM スワップは携帯キャリアを騙して被害者の電話番号を攻撃者の SIM に移す攻撃で、電話番号宛ての SMS コードがそのまま攻撃者に届くようになります。このため SMS は最も弱い MFA とされます。スマートカードや FIDO2 キーは物理的な所持が必要で、虹彩は本人の生体が必要なため、電話番号の乗っ取りでは突破できません。

</details>

**問4.** 深夜に大量の MFA プッシュ通知を送りつけ、従業員がうんざりして「承認」を押すのを狙う攻撃が報告されました。最も適切 (BEST) な対策はどれですか?

1. プッシュ通知の回数制限とナンバーマッチングを導入する
2. パスワードの定期変更を義務付ける
3. 通知音を消すよう従業員に案内する
4. MFA を廃止してパスワードのみに戻す

<details><summary>答えと解説</summary>

正解: **1**

これは MFA 疲労攻撃 (MFA fatigue) です。対策は、短時間の試行回数制限に加え、ログイン画面に表示された数字をスマホ側で入力させるナンバーマッチングのように「見ずに承認」をできなくする仕組みです。パスワード変更は攻撃の前提(パスワードは既に漏れている)に効かず、通知音を消すのは攻撃を見えなくするだけ、MFA 廃止は論外の改悪です。利便性による形骸化を設計で防ぐのがポイントです。

</details>

**問5.** 会社支給の端末からのみ社内システムへのアクセスを許可したい場合、最も適切な手段はどれですか?

1. 全従業員に同じ接続用パスワードを配布する
2. 接続元の IP アドレスだけで判定する
3. 各端末にクライアント証明書を配布して検証する
4. ユーザーのパスワードを複雑にする

<details><summary>答えと解説</summary>

正解: **3**

端末そのものを認証するにはクライアント証明書(デバイス証明書)が定石です。MDM と組み合わせれば管理下にある端末だけに証明書を配布できます。共有パスワードは説明責任を壊し、IP アドレスはモバイル環境で変動し偽装もされ得ます。ユーザーパスワードは人の認証であり、端末の判別はできません。「人の認証」と「デバイスの認証」を区別させる問題は、ゼロトラスト文脈で増えています。

</details>

## 4. バイオメトリクス

### 生体認証の種類

| 方式 | 特徴 |
|---|---|
| 指紋 | 最も普及。安価 |
| 虹彩 (iris) | **精度が非常に高く**、カメラ撮影のため受容性も比較的良い |
| 網膜 (retina) | 精度は高いが目に光を当てるため**侵襲感があり受容性が低い**。健康状態が分かる懸念も |
| 顔 | 非接触で便利。双子や経年変化が課題 |
| 声・署名・キーストローク | 行動的特徴。精度は低め |

### 精度の指標 — FRR・FAR・CER

ここが試験の最重要ポイントです。

| 指標 | 英語 | 意味 | 別名 |
|---|---|---|---|
| **FRR** | False Rejection Rate | **本人を誤って拒否**する率 | Type 1 エラー |
| **FAR** | False Acceptance Rate | **他人を誤って受け入れる**率 | Type 2 エラー |
| **CER** | Crossover Error Rate | FRR と FAR が交差する点。**低いほど高精度** | EER |

感度を上げると FAR は下がりますが FRR が上がります(本人も弾かれやすくなる)。逆もまた然り。そこで両者が等しくなる **CER** で装置の精度を比較します。

- **高セキュリティ施設**(データセンターの入口など)→ **FAR を最小化**(他人を絶対入れない。本人が弾かれる不便は許容)
- 利便性重視の場面 → FRR を抑える調整

### 運用上の注意

利用開始時には**登録 (enrollment)** が必要で、登録・照合に時間がかかりすぎると受容されません(目安: 登録2分以内、照合6秒以内)。最大のリスクは、**生体情報はパスワードと違って漏えいしても変更できない**ことです。

💡 コツ: 「Type 1 =本人拒否(FRR)、Type 2 =他人受入(FAR)」。番号と意味の対応は丸暗記必須です。

### 確認問題

**問1.** バイオメトリクスにおける Type 2 エラーの説明として正しいものはどれですか?

1. 本人を誤って拒否してしまう
2. 登録に時間がかかりすぎる
3. センサーが故障して誰も認証できない
4. 権限のない他人を誤って受け入れてしまう

<details><summary>答えと解説</summary>

正解: **4**

Type 2 エラーは FAR (False Acceptance Rate)、つまり他人を誤って本人と判定して受け入れてしまう誤りです。セキュリティ上はこちらの方が危険です。本人を誤って拒否するのは Type 1 エラー (FRR) で、利便性の問題です。登録時間やセンサー故障はエラー率の分類とは関係ありません。「1=本人拒否、2=他人受入」の対応は試験直前まで確認しましょう。

</details>

**問2.** 2つの虹彩認証装置を比較したところ、装置 A の CER は 2%、装置 B の CER は 5% でした。この結果から言えることはどれですか?

1. 装置 A の方が精度が高い
2. 装置 B の方が精度が高い
3. 装置 A の方が他人を受け入れやすい
4. CER だけでは精度は比較できない

<details><summary>答えと解説</summary>

正解: **1**

CER (Crossover Error Rate) は FRR と FAR が等しくなる点の誤り率で、装置の精度を比較する標準的な指標です。低いほど高精度なので、CER 2% の装置 A が優秀です。CER はまさに装置間の精度比較のための指標なので「比較できない」は誤り、また CER が低い装置が他人を受け入れやすいという関係もありません。「CER は低いほど良い」と覚えてください。

</details>

**問3.** データセンターの入室管理に生体認証を導入します。セキュリティを最優先する場合、どの調整が最も適切 (BEST) ですか?

1. FRR を最小化し、本人が確実に入れるようにする
2. FAR を最小化し、本人拒否が増えるのは許容する
3. FAR と FRR を常に等しく保つ
4. CER を最大化する

<details><summary>答えと解説</summary>

正解: **2**

高セキュリティ施設では「他人を誤って入れる (FAR)」ことが最悪の事態なので、感度を上げて FAR を最小化します。その代償として本人が弾かれる FRR の上昇は運用でカバーします(再試行や警備員対応)。FRR 最小化は利便性重視の調整で逆です。FAR と FRR を等しくする点 (CER) は精度比較用の概念で運用目標ではなく、CER は低いほど良い指標なので最大化は無意味です。

</details>

**問4.** 精度が高い一方で、目に光を当てる方式のため利用者の抵抗感が強く、健康状態が推測できてしまう懸念もある生体認証はどれですか?

1. 虹彩認証
2. 指紋認証
3. 網膜認証
4. 声紋認証

<details><summary>答えと解説</summary>

正解: **3**

網膜 (retina) 認証は眼底の血管パターンを読むため目に近距離で光を当てる必要があり、侵襲感から受容性 (acceptability) が低い方式です。血管パターンから妊娠や高血圧などの健康状態が分かり得る点もプライバシー上の懸念です。虹彩認証はカメラで撮影するだけなので受容性は比較的良好です。「虹彩=受け入れられやすい高精度、網膜=嫌がられる」という対比で覚えましょう。

</details>

**問5.** 生体認証がパスワード認証と比べて本質的に抱えるリスクはどれですか?

1. 総当たり攻撃に弱い
2. 漏えいしても本人が変更できない
3. 定期的な変更が義務付けられている
4. 複数のシステムで使い回せない

<details><summary>答えと解説</summary>

正解: **2**

指紋や虹彩のパターンは生涯ほぼ変わらないため、一度テンプレートが漏えいすると「変更して無効化する」ことができません。これが生体情報の本質的リスクで、テンプレートの保護(暗号化・端末内保存)が重要になります。総当たりはむしろパスワードの弱点、生体情報に定期変更の義務はなく、同じ指紋が複数システムで使える(使い回せてしまう)ことはデメリットではあってもこの選択肢の記述とは逆です。

</details>
