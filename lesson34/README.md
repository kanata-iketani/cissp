# 第34章 模試②（全ドメイン50問・出題比率準拠）

本試験1〜2週間前の総仕上げとして取り組む模試です。模試①より一段ひねった「2段階の思考」が必要な問題を多めに配置しています。間違えた問題は必ずにがて帳で解き直し、該当章の本文まで戻って「なぜその選択肢がBESTなのか」を自分の言葉で説明できるようにしましょう。

## 1. 模試② Part1: D1+D2（問1〜13）

模試②の前半戦です。Part1 はドメイン1「セキュリティとリスクマネジメント」から8問、ドメイン2「資産のセキュリティ」から5問の計13問。本試験の出題比率（D1 16%・D2 10%）に合わせています。

### 取り組み方

- 本試験ペースは **1問あたり約70〜90秒** です。13問を18分以内で解き切りましょう
- 模試②は「2段階の思考」を要する問題を多めにしています。シナリオの状況を整理→原則に当てはめる、の順で落ち着いて読んでください
- BEST/MOST/FIRST を問う問題は、**全選択肢が部分的に正しい**前提で「管理者として最も適切な一手」を選びます

💡 模試②で間違えた問題は、本試験までに必ず該当章へ戻って解き直しましょう。にがて帳からワンクリックで再挑戦できます。

### 確認問題

**問1.** ある企業の経営陣は、外部機関によるリスク評価を実施し、重大な脆弱性を列挙した報告書を受け取りました。しかしその後1年間、予算を理由に何の対策も指示しませんでした。この状況で欠けているものとして最も適切なのはどれでしょう？

1. デューデリジェンス (due diligence)
2. デューケア (due care)
3. 職務分掌 (separation of duties)
4. リスク移転 (risk transference)

<details><summary>答えと解説</summary>

正解: **2**

リスク評価を実施して「知る努力」をした点でデューデリジェンス（調査・把握）は果たされています。問題は、把握したリスクに対して合理的な行動を取っていないこと、つまりデューケア（思慮ある行動）の欠如です。この状態で侵害が起きると過失 (negligence。必要な注意を怠ったこと) を問われます。職務分掌やリスク移転は本シナリオの論点ではありません。「調査した＝診断 (diligence)、行動した＝ケア (care)」とセットで覚え、どちらが欠けているかを状況から判定できるようにしましょう。📖 復習: 第2章・第4章

</details>

**問2.** 海外支社で使われている老朽化した業務システムについて、改修費用の見積りが年間予想損失 (ALE) を大きく上回り、しかも該当業務は本社システムへ統合可能なことがわかりました。リスクマネジメントの観点で最も適切な対応はどれでしょう？

1. サイバー保険に加入してリスクを移転する
2. 補償コントロールを追加してリスクを軽減する
3. システムを廃止し業務を本社へ統合してリスクを回避する
4. 現状を文書化してリスクを受容する

<details><summary>答えと解説</summary>

正解: **3**

年間予想損失 (ALE) は「1回の損失額 × 1年に起きる回数」で出す、1年あたりの損失見込みです。対策費用が効果を上回り、かつその活動自体をやめられる（代替手段がある）場合は、リスクの原因となる活動を排除する「回避 (avoidance)」が最適です。軽減や移転はコストに見合わず、受容は統合という現実的な代替策があるのに損失可能性を放置する点で不適切です。「回避が選べるのは、やめても事業が成り立つとき」という条件まで読み取るのがポイントです。リスク対応は 回避（活動をやめる）・軽減（対策で減らす）・移転（保険などで他者へ移す）・受容（承知のうえで受け入れる）の4つです。📖 復習: 第4章

</details>

**問3.** 資産価値 2,000万円のサーバーに対し、ある脅威の暴露係数 (EF) は 25%、年間発生率 (ARO) は 0.2 です。年間 60万円の対策を導入すると ALE が 20万円まで下がります。この対策の年間価値（費用対効果）はいくらでしょう？

1. 20万円
2. 40万円
3. 80万円
4. マイナス20万円

<details><summary>答えと解説</summary>

正解: **1**

SLE（1回の事故の損失額）= 2,000万円 × 25% = 500万円、対策前 ALE（1年あたりの損失見込み）= 500万円 × 0.2 = 100万円です。対策の価値 = 対策前ALE(100万) − 対策後ALE(20万) − 年間対策費用(60万) = 20万円。プラスなので導入する価値があります。40万円は対策費用の引き忘れ、80万円は対策後ALEの引き忘れによる誤答です。計算問題は「SLE→ALE→価値」の3段階を機械的に進めましょう。📖 復習: 第4章

</details>

**問4.** 多国籍企業のセキュリティポリシーが、新しく進出した国の個人データ保護法と矛盾していることが判明しました。セキュリティ責任者として最初に (FIRST) 取るべき行動はどれでしょう？

1. 本社ポリシーを優先し、現地でもそのまま適用する
2. 現地拠点だけポリシーの適用を免除する
3. 矛盾を文書化し、法務と連携して現地法に適合するようポリシーを改定する
4. 現地の法律が変わるまで事業を一時停止する

<details><summary>答えと解説</summary>

正解: **3**

法規制はポリシーより上位です。組織の内部ルールが法律と矛盾する場合は法律が優先され、ポリシー側を適合させる必要があります。その際は独断でなく法務部門と連携するのが管理者としての正しい手順です。本社ポリシーの強行は違法リスク、無条件の適用免除は統制の崩壊、事業停止は過剰反応です。「法律 > 規制 > ポリシー」の優先順位は試験全体で繰り返し問われます。ポリシー（組織が自分で決めた内部ルール）は、法律の範囲内でしか有効になりません。📖 復習: 第2章・第3章

</details>

**問5.** BCP のテストとして、本番業務を止めずに代替サイトのシステムを実際に起動し、本番と並行して処理結果を検証する方式はどれでしょう？

1. 構造化ウォークスルー (structured walk-through)
2. シミュレーションテスト
3. パラレルテスト
4. フルインタラプションテスト

<details><summary>答えと解説</summary>

正解: **3**

BCP（事業継続計画。災害時に業務を続けるための計画）のテストのうち、パラレルテストは代替サイトを実際に稼働させつつ、本番業務は通常どおり継続する方式で、「実機検証」と「業務無停止」を両立します。構造化ウォークスルーは会議室での机上確認、シミュレーションはシナリオに沿った演習でシステムの実起動を伴わないか限定的、フルインタラプションは本番を実際に切り替える最もリスクの高いテストです。「本番を止めたか・代替サイトを動かしたか」の2軸で5方式を整理しましょう。📖 復習: 第6章・第26章

</details>

**問6.** 経理担当者が5年間ほとんど休暇を取らず、仕入先への支払処理を一人で完結させています。進行中かもしれない不正を「発見」するための管理策として最も効果的 (MOST) なのはどれでしょう？

1. 支払業務の手順書を整備する
2. 強制休暇 (mandatory vacation) を実施し、別の担当者に業務を引き継がせる
3. 支払システムに多要素認証を導入する
4. 本人にセキュリティ研修を受講させる

<details><summary>答えと解説</summary>

正解: **2**

強制休暇は、不正をしている本人を業務から引き離し、代わりの担当者が処理を行うことで隠蔽されていた不正が表面化する「発見的 (detective)」統制です。職務分掌（1つの業務を複数人に分け、一人で完結させない統制）は今後の不正を防ぐ予防的統制としては有効ですが、設問は「進行中の不正の発見」を求めています。手順書・MFA（パスワード＋スマホなど種類の違う要素で本人確認する方式）・研修はいずれもこのシナリオの不正発見には直接つながりません。問題文の「予防か発見か」という動詞を見逃さないようにしましょう。📖 復習: 第6章

</details>

**問7.** CISSP 保持者であるあなたは、顧客システムに重大な脆弱性を発見しました。顧客の担当役員は「公表も修正もせず黙っていてほしい。利用者への影響は当社が判断する」と指示しています。ISC2 倫理規範に照らして最も適切な行動はどれでしょう？

1. 契約相手である顧客の指示に従い、何もしない
2. 社会と公共の利益を第一に、組織内の適切なルートでエスカレーションし是正を働きかける
3. 利用者を守るため、ただちに SNS で脆弱性の詳細を公開する
4. 関与を避けるため理由を告げずに契約を打ち切る

<details><summary>答えと解説</summary>

正解: **2**

ISC2 倫理規範の4つのカノン（倫理規範の柱となる4つの条文）は番号順に優先され、第1カノン「社会・公共の利益・インフラの保護」が依頼主への誠実なサービス（第3カノン）より上位です。したがって公共の利益を優先しつつ、無責任な暴露ではなく適切なエスカレーション（上位の責任者や然るべき窓口へ判断を上げること）で是正を促すのがBESTです。指示への盲従は第1カノン違反、SNS での即時公開は利用者をかえって危険にさらす無責任な開示、無言の契約打ち切りは問題を放置します。「カノンは番号順」が鉄則です。📖 復習: 第6章

</details>

**問8.** クラウドサービスの調達にあたり、稼働率 99.9% を下回った場合の返金条項を含む、法的拘束力のある合意を結びたいと考えています。最も適切な文書はどれでしょう？

1. SLA（サービスレベルアグリーメント）
2. MOU（覚書）
3. NDA（秘密保持契約）
4. BPA（事業パートナー契約）

<details><summary>答えと解説</summary>

正解: **1**

SLA は稼働率や応答時間といったサービス水準を数値で定義し、未達時のペナルティ（返金・違約金）まで定める法的拘束力のある契約です。MOU は意図の合意を示す文書（「協力していきましょう」という覚書）で一般に拘束力が弱く、ペナルティ条項には不向きです。NDA は秘密情報の扱い、BPA はパートナー間の利益配分や責任分担を定めるもので、サービス水準の保証とは目的が異なります。「数値目標＋ペナルティ＝SLA」と覚えましょう。稼働率 99.9% は、1か月（約30日）でおよそ43分までの停止なら守られている計算です。📖 復習: 第5章

</details>

**問9.** 極秘プロジェクトの終了に伴い、関連文書の機密区分を「社外秘」へ引き下げたいという依頼がありました。格下げ (declassification) の前に最も重要なステップはどれでしょう？

1. 文書をすべて暗号化する
2. カストディアンが独自の判断で速やかにラベルを貼り替える
3. データオーナーが格下げの妥当性をレビューし承認する
4. 文書を即座にシュレッダーで廃棄する

<details><summary>答えと解説</summary>

正解: **3**

分類と再分類（格下げを含む）の決定権限と責任はデータオーナーにあります。手続きなしに区分を下げると、保護が必要な情報が弱い管理下に流出する恐れがあるため、オーナーによるレビューと承認が必須です。カストディアン（オーナーの方針どおりバックアップやアクセス設定をする担当）は日々の保護作業の実行者であり分類の決定者ではありません（超頻出のひっかけ）。暗号化や廃棄は格下げ判断そのものの代わりになりません。📖 復習: 第7章

</details>

**問10.** 政府系の情報分類で、漏えいした場合に国家安全保障へ「重大な損害 (serious damage)」を与えると想定される情報に付与される区分はどれでしょう？

1. Top Secret
2. Secret
3. Confidential
4. Unclassified

<details><summary>答えと解説</summary>

正解: **2**

政府分類は損害の程度で階層化されており、Top Secret は「例外的に重大な損害 (exceptionally grave damage)」、Secret は「重大な損害 (serious damage)」、Confidential は「損害 (damage)」に対応します。形容詞と区分の対応はそのまま出題される超頻出知識です。商用分類（Confidential/Private/Sensitive/Public など）との混同にも注意しましょう。📖 復習: 第7章

</details>

**問11.** リース満了で返却する SSD 搭載ノートPC 200台から、業務データを確実に読み出せなくしたいと考えています。機器を再利用可能な状態で返却する前提で、最も適切な方法はどれでしょう？

1. 強力な磁場をかける消磁 (degaussing) を行う
2. OS のゴミ箱を空にしてから初期化する
3. 暗号化消去 (crypto-erase) を実施し、結果を検証する
4. 各ドライブを物理的に粉砕する

<details><summary>答えと解説</summary>

正解: **3**

SSD はフラッシュメモリなので磁気に依存せず、消磁（強い磁気で磁気媒体の記録を壊す方法）は無効です。またウェアレベリング（書き込みを全体に散らして寿命を延ばす SSD の仕組み。古いデータが別の場所に残りうる）により上書き消去も完全性を保証できません。全領域を暗号化した鍵を破壊する暗号化消去なら（鍵がなければ残ったデータは読めない乱数の塊です）、媒体を再利用可能なままデータを実質復元不能にでき、リース返却の要件に合致します。物理破壊は確実ですが「再利用可能な状態で返却」という前提に反します。ゴミ箱の削除は論理削除にすぎません。媒体の種類と廃棄方式の相性は超頻出です。📖 復習: 第8章

</details>

**問12.** 従業員が会社非公認のクラウドストレージ（シャドーIT）へ機密ファイルをアップロードしている実態を可視化し、ポリシーに基づいて利用を制御したいと考えています。最も適切なソリューションはどれでしょう？

1. ネットワーク型 DLP
2. CASB（クラウドアクセスセキュリティブローカー）
3. DRM（デジタル著作権管理）
4. SIEM

<details><summary>答えと解説</summary>

正解: **2**

CASB は組織とクラウドサービスの間に立ち、どのクラウドが使われているかの可視化（シャドーIT の発見）とポリシーベースの利用制御を担う、クラウド利用統制に特化したソリューションです。DLP（機密データの持ち出しを内容で見つけて止める仕組み）は持ち出し検知が主目的で、未知のクラウドサービスの発見・制御は不得意です。DRM はファイル自体の利用権制御、SIEM はログの相関分析（各所のログを集めて突き合わせ、攻撃の兆候を見つけること）であり、どちらも「クラウド利用の可視化と制御」という要件には合いません。「クラウドの可視化なら CASB」が定石です。📖 復習: 第8章

</details>

**問13.** ある企業は「念のため」という理由で全従業員のメールを無期限に保存しています。この慣行がもたらす最大 (GREATEST) のリスクはどれでしょう？

1. ストレージ費用がわずかに増える
2. メールの検索速度が低下する
3. バックアップ時間が長くなる
4. 訴訟時の eディスカバリ対象と情報漏えい時の影響範囲が際限なく拡大する

<details><summary>答えと解説</summary>

正解: **4**

保持期間を定めず何でも保存すると、訴訟になった際に開示（eディスカバリ＝訴訟で相手方に電子データを提出する手続き）すべきデータが膨大になり、コストと法的リスクが跳ね上がります。さらに侵害時に漏えいする情報量も増え続けます。これが「データは持っているだけでリスク」と言われる理由で、保持ポリシー（データ種別ごとに保存期間を決めた規程）に基づく計画的な廃棄 (defensible destruction。法的に説明できる手順での廃棄) が正解の方向性です。費用・速度・バックアップ時間も影響はありますが、法的リスクに比べれば二次的です。📖 復習: 第7章・第23章

</details>

## 2. 模試② Part2: D3+D4（問14〜26）

Part2 はドメイン3「セキュリティアーキテクチャとエンジニアリング」から7問、ドメイン4「通信とネットワークのセキュリティ」から6問の計13問です（出題比率はともに13%）。

### このパートの頻出ポイント

- セキュリティモデルは「どの向きの読み書きを禁止するか」をルール名つきで即答できるか
- 暗号は「アルゴリズムの中身」より「攻撃の識別と運用（失効確認・鍵保護）」
- ネットワークは「そのプロトコル・機器が守れる範囲はどこまでか」（DNSSEC に機密性はない、AH に暗号化はない等）

💡 選択肢に迷ったら「このコントロールが『できないこと』は何か」を考えると、ひっかけを除外しやすくなります。13問を18分以内で解きましょう。

### 確認問題

**問1.** Bell-LaPadula モデルを実装したシステムで、Secret クリアランスのユーザーが Confidential（下位）レベルの文書へ書き込もうとしてブロックされました。このブロックの根拠となるルールはどれでしょう？

1. 単純セキュリティプロパティ（no read up）
2. スタープロパティ（no write down）
3. 単純完全性プロパティ（no read down）
4. 完全性スタープロパティ（no write up）

<details><summary>答えと解説</summary>

正解: **2**

Bell-LaPadula は機密性のモデルで、スタープロパティ（*-property）が上位レベルの主体から下位レベルへの書き込み（write down）を禁止します。上位の機密情報が下位区分へ流出するのを防ぐためです。単純セキュリティプロパティは「上を読むな」のルール。no read down と no write up は完全性モデル Biba のルールで、機密性のシナリオには適用されません。「BLP は機密性・Biba は完全性」「単純＝読み・スター＝書き」の2軸で整理すると混同しません。主体（ユーザーやプロセス）と客体（文書やファイル）の両方にレベルが付いていて、その上下関係で読み書きの可否が決まります。📖 復習: 第9章

</details>

**問2.** 「システム内のすべての主体から客体へのアクセスを例外なく仲介し、改ざんできず、検証可能なほど小さい」という要件を満たすべき抽象概念を、OS の中で実際に実装したものはどれと呼ばれるでしょう？

1. TCB（トラステッドコンピューティングベース）
2. セキュリティ境界 (security perimeter)
3. セキュリティカーネル (security kernel)
4. 保護リング (protection ring)

<details><summary>答えと解説</summary>

正解: **3**

**問8.** DNSSEC を導入した場合に得られる保護として、正しい説明はどれでしょう？

1. DNS 応答が暗号化され、問い合わせ内容の盗聴を防げる
2. DNS 応答のなりすましと改ざんを、デジタル署名の検証で検知できる

**問11.** 侵害発生時の攻撃者による横移動 (lateral movement) をデータセンター内のワークロード単位で制限したいと考えています。最も効果的 (MOST) なアプローチはどれでしょう？

**問12.** カフェなどの公共スペースで、正規のアクセスポイントと同じ SSID を名乗る偽 AP（Evil Twin）に社員が接続してしまうリスクを低減したい。技術的対策として最も効果的なのはどれでしょう？

1. SSID をステルス化する
2. MAC アドレスフィルタリングを導入する
3. サーバー証明書を検証する 802.1X/EAP-TLS 認証と常時 VPN を併用する

**問13.** 自社ドメインをかたるなりすましメールへの対策として SPF・DKIM・DMARC を導入します。このうち DMARC が担う役割として正しいのはどれでしょう？

## 3. 模試② Part3: D5+D6（問27〜38）

### 確認問題

**問1.** データセンターの入室管理に虹彩認証を導入します。許可されていない人物の入室を最小限にすることが最優先の要件である場合、しきい値の調整方針として正しいのはどれでしょう？

1. FRR（本人拒否率）を最小化する。FAR が上がるのは許容する
2. CER（交差エラー率）が最大になるよう調整する
3. FAR（他人受入率）を最小化する。FRR が上がるのは許容する
4. FAR と FRR を両方ともゼロにする

<details><summary>答えと解説</summary>

正解: **3**

許可されていない人物を通さないこと＝他人受入 (FAR、Type 2 エラー) の最小化が最優先です。しきい値（どれだけ似ていれば本人と判定するかの基準）を厳しくすると FAR は下がりますが、本人が拒否される FRR (Type 1) は上がるトレードオフが生じ、高セキュリティ施設ではこれを許容します。CER は FAR と FRR が交差する点で装置の精度比較に使う指標（低いほど高精度）であり、「最大化」は無意味です。両方ゼロは現実には不可能です。「守りたいものに合わせてどちらのエラーを許容するか」が問われます。数値例: しきい値を上げて FAR が 1%→0.1% に下がる代わりに、FRR が 2%→5% に上がる、という動き方をします。📖 復習: 第18章

</details>

**問2.** 開発チームが「OAuth 2.0 を導入したのでユーザー認証は完了している」と報告してきました。セキュリティレビューアとして指摘すべき点はどれでしょう？

1. OAuth 2.0 は認可 (authorization) のフレームワークであり、認証には OIDC などの仕組みを追加する必要がある

</details>

**問3.** 数百台のネットワーク機器への管理者アクセスについて、コマンド単位の認可と通信全体の暗号化、認証・認可・アカウンティングの分離を要件としています。最も適切なプロトコルはどれでしょう？

<details><summary>答えと解説</summary>

正解: **2**

TACACS+ は TCP（届いたかを確認しながら送る通信方式）上で動作し、パケット全体を暗号化し、AAA（認証・認可・アカウンティング）を分離して扱えるため、コマンド単位の認可が必要な機器管理に最適です。RADIUS は UDP（確認なしで送る軽い通信方式）でパスワード部分しか暗号化せず、認証と認可が一体で細かな認可制御に不向き（ネットワークアクセス用途が主）。LDAP はディレクトリ（ユーザーや組織の情報を集めた台帳）の参照、SAML は Web SSO（一度のログインで複数サービスを使える仕組み）のフェデレーション（組織をまたいだ ID の連携）であり、機器管理 AAA の要件に合いません。RADIUS と TACACS+ の対比表は頻出です。アカウンティングは「誰がいつ何をしたか」の利用記録です。TACACS+ なら「show コマンドは可、設定変更は不可」のようにコマンドごとの許可が書けます。📖 復習: 第20章

</details>

**問4.** 監視チームが「多数のアカウントに対し、少数のよくあるパスワードを低頻度で試すログイン失敗が広範囲で発生している」と報告しました。この攻撃と、それでも突破されないための最も効果的な対策の組み合わせはどれでしょう？

1. ブルートフォース攻撃 — アカウントロックアウトの強化
2. クレデンシャルスタッフィング — パスワード定期変更の義務化
3. 辞書攻撃 — SSID のステルス化
4. パスワードスプレー攻撃 — フィッシング耐性のある多要素認証の導入

<details><summary>答えと解説</summary>

正解: **4**

「多数アカウント×少数パスワード×低頻度」はロックアウトを回避するよう設計されたパスワードスプレー攻撃の典型パターンです。ロックアウト（一定回数失敗したアカウントを一時停止する仕組み）強化はこの攻撃にほぼ無力（1アカウントあたりの試行が閾値未満）なので、パスワードが破られても突破されない MFA が最も効果的です。クレデンシャルスタッフィングは「漏えい済みの ID/パスワードの組」を使い回す別の攻撃で、定期変更の強制は現代のベストプラクティスでもありません。攻撃パターンの識別と対策をセットで問う2段階問題です。例: 「Password1」を社員1,000人に1回ずつ試し、1時間後に「Summer2026」を1回ずつ…と進めれば、各アカウントの失敗は数回で済み、ロックアウトに届きません。フィッシング耐性のある MFA は、偽サイトにだまされても使えない方式（FIDO2 の鍵など）を指します。📖 復習: 第19章

</details>

**問5.** 「経理部に所属し、社給の準拠端末を使い、平日9〜18時に国内からアクセスしている場合のみ決裁システムの承認操作を許可する」という要件を実装したい。最も適した制御モデルはどれでしょう？

1. DAC（任意アクセス制御）
2. MAC（強制アクセス制御）
3. ABAC（属性ベースアクセス制御）
4. 単純な RBAC（役割ベースアクセス制御）

<details><summary>答えと解説</summary>

正解: **3**

部署（主体属性）・端末の準拠状態（環境属性）・時間帯・場所という複数の属性を組み合わせて動的にアクセスを判断するのは ABAC（主体・対象・環境の属性を条件式で組み合わせて判断する方式）の得意分野です。RBAC は役割だけで決めるため時間・場所・端末状態の条件を表現できず、DAC はオーナーの裁量ベース、MAC はラベルとクリアランスによる制御で、いずれも要件に合いません。「役割＋環境条件の動的な組み合わせ→ABAC」というパターン認識が有効です。ABAC のルールは「部署＝経理 かつ 端末＝準拠 かつ 時刻＝平日9〜18時 かつ 国＝日本 なら 承認を許可」のような形で書きます。📖 復習: 第19章

</details>

**問6.** システム管理者が常時 Domain Admin 権限を保有している現状を改善し、特権の悪用・窃取リスクを下げたいと考えています。最も効果的 (MOST) なアプローチはどれでしょう？

1. 管理者のパスワードをより複雑にする
2. PAM を導入し、承認に基づくジャストインタイム (JIT) の特権昇格と操作記録に切り替える

<details><summary>答えと解説</summary>

常時付与された強力な特権は、窃取されれば即座に最大の被害につながります。PAM（特権 ID 管理。強い権限の貸し出し・記録をまとめて管理する仕組み）によるジャストインタイム昇格なら、特権は必要な作業の間だけ承認を経て付与され、セッションは記録されるため、悪用の機会と攻撃対象時間 (attack window) が大幅に縮小します。パスワード強化や命名規則は常時特権という構造的問題を解決せず、管理者の増員はむしろ特権保有者を増やして逆効果です。Domain Admin は、社内の全 Windows 端末・サーバーを管理できる最上位の管理者グループです。📖 復習: 第20章

</details>

**問7.** アクセスレビューの結果、退職者のアカウント12個が90日以上有効なまま残っていたことが判明しました。再発防止として最も効果的なのはどれでしょう？

**問8.** 脆弱性スキャンの方式を検討しています。OS 内部のパッチ適用漏れや設定不備まで検出したい場合、どの方式を選ぶべきでしょう？

**問9.** 外部業者によるペネトレーションテストを計画しています。テスト開始前に最も重要 (MOST) なものはどれでしょう？

**問10.** クラウドサービス事業者の内部統制が「一定期間にわたって有効に運用されていたこと」の独立した保証を得たい。要求すべき報告書はどれでしょう？

**問11.** EC サイトの購入フローが正常に動作しているかを、実際の顧客に影響を与えずに24時間自動で監視したいと考えています。最も適切な手法はどれでしょう？

**問12.** セキュリティ態勢の報告指標を整備しています。「将来のリスク増大を早期に警告する先行指標」に該当するものはどれでしょう？

**問1.** 侵害が疑われるサーバーのフォレンジック調査を開始します。証拠の揮発性 (order of volatility) に従う場合、最初に (FIRST) 収集すべきものはどれでしょう？

1. ディスク上のログファイル
2. オフサイトのバックアップテープ
3. CPU のレジスタとキャッシュの内容
4. ネットワーク機器の設定ファイル

<details><summary>答えと解説</summary>

正解: **3**

証拠収集は揮発性（電源断などで消えやすい度合い）の高い順に行います。CPU レジスタ・キャッシュ（CPU 内部の一時記憶。ナノ秒単位で書き換わる）→メモリ→ネットワーク状態・実行中プロセス→ディスク→バックアップ媒体の順で、最も消えやすい CPU レジスタ・キャッシュが最優先です。ディスク上のログや設定ファイル、バックアップは電源断後も残るため後回しにできます。「電源を切った瞬間に失われるものから集める」と覚えると、順序の並べ替え問題にも対応できます。📖 復習: 第23章

</details>

**問2.** 自社を相手取る訴訟の通知が届き、法務部門から訴訟ホールド (litigation hold) の指示が出ました。IT 部門が最初に (FIRST) 行うべきことはどれでしょう？

1. 保持ポリシーに従い予定どおり古いメールの自動削除を続行する
2. 関連しうるデータの削除・自動廃棄を直ちに停止し、保全する
3. 関連データをすべて外部の弁護士へ即時送付する
4. 対象データを暗号化して誰も読めないようにする

<details><summary>答えと解説</summary>

正解: **2**

訴訟ホールドが発動したら、通常の保持ポリシーに基づく自動削除よりホールドが優先され、関連しうる情報 (ESI＝電子的に保存された情報。メール・ファイル・ログなど) の削除停止と保全が最優先です。削除を続行すると証拠隠滅 (spoliation) とみなされ制裁の対象になります。弁護士への送付は eディスカバリ（訴訟で相手方に電子データを提出する手続き）の後工程（収集・レビュー・提出）で、まず保全が先。暗号化で読めなくすることは保全ではなく、開示義務への妨げになります。「ホールド＞保持ポリシー」の優先関係が核心です。IT 部門の具体的な作業は、メールの自動削除ジョブやバックアップテープの上書きローテーションを、対象分だけ止めることです。📖 復習: 第23章

</details>

**問3.** 社内ネットワークに、わざと魅力的に見える疑似サーバー（ハニーポット）を設置して攻撃者の手口を観察しています。この運用が合法的な「誘引 (enticement)」にとどまり、違法となりうる「罠にはめる行為 (entrapment)」にならないために重要な条件はどれでしょう？

1. もともと侵入の意図を持つ者に機会を見せるだけにとどめ、犯行をそそのかさない
2. ハニーポットに本物の顧客データを置いて現実味を高める
3. 攻撃者の端末へ逆侵入して証拠を収集する
4. 観察した手口を攻撃者本人へ通知する

<details><summary>答えと解説</summary>

正解: **1**

誘引 (enticement) は「すでに犯意を持つ者に機会を提示する」ことで合法とされ、証拠としても有効です。一方、犯意のなかった者をそそのかして犯行させるのは entrapment（違法な囮）で、証拠能力や訴追に問題が生じます。本物の顧客データを置くのはそれ自体がデータ保護義務違反、逆侵入（ハックバック）は自身が不正アクセスになる行為、手口の通知は無意味です。この対概念は D7 の超頻出論点です。ハニーポットはおとりのサーバーで、攻撃者の操作を記録して手口や使うツールを調べるために置きます。📖 復習: 第24章

</details>

**問4.** CISSP の示すインシデント管理の7段階（検知→対応→軽減→報告→復旧→修復→教訓）において、「軽減 (mitigation)」の段階で行う活動として最も適切なのはどれでしょう？

1. 根本原因を恒久的に除去し、再発防止策を実装する
2. 感染した端末をネットワークから隔離し、被害の拡大を封じ込める

<details><summary>答えと解説</summary>

正解: **2**

軽減は「封じ込め (containment)」の段階で、感染端末の隔離やアカウントの無効化により被害の拡大を止めることが目的です。根本原因の恒久的な除去は修復 (remediation)、通常運用への回帰は復旧 (recovery)、振り返りは教訓 (lessons learned) の活動で、それぞれ段階が異なります。7段階は順序の並べ替えや「この活動はどの段階か」という形式で頻出なので、各段階の代表的な活動をセットで覚えましょう。📖 復習: 第25章

</details>

**問5.** 日曜夜にフルバックアップ、月〜土曜夜に増分 (incremental) バックアップを取得しています。木曜の朝にストレージ障害が発生した場合、完全復旧に必要なバックアップセットはどれでしょう？

1. 日曜のフルバックアップのみ
2. 日曜のフルバックアップと水曜の増分
3. 日曜のフルバックアップと月・火・水曜の増分すべて
4. 水曜の増分のみ

<details><summary>答えと解説</summary>

正解: **3**

増分バックアップは「前回の何らかのバックアップ以降」の変更だけを保存するため、復元にはフル＋障害直前までのすべての増分（月・火・水）が必要で、合計4セットを順に適用します。これが差分 (differential) なら「前回のフル以降」の変更を毎回含むため、フル＋最新の差分の2セットで済みます（「日曜のフルバックアップと水曜の増分」は差分の場合の答え）。「増分＝全部必要・差分＝最新1つ」のトレードオフ（バックアップは速いが復元が遅い）は計算形式で超頻出です。日ごとに見ると、月曜の増分＝月曜1日分の変更、火曜の増分＝火曜1日分…なので、「日曜フル → 月 → 火 → 水」の順に重ねて戻します。📖 復習: 第26章

</details>

**問6.** DR テストとして、本番システムを実際に停止して代替サイトへ切り替えるフルインタラプションテストを提案します。実施の前提として最も重要 (MOST) なのはどれでしょう？

1. テスト担当者の残業代の確保
2. 本番停止に伴う事業リスクを理解した経営陣による明示的な承認
3. 切り替え手順を担当者が暗記していること
4. テスト当日の天候の確認

<details><summary>答えと解説</summary>

正解: **2**

フルインタラプションテストは本番業務の実停止を伴う最もリスクの高いテストで、切り戻し（本番環境へ戻すこと）に失敗すれば実害が出ます。したがって、そのリスクを受容できるのは経営陣だけであり、事前の明示的な承認が絶対条件です。読み合わせ（手順書を各自で確認）→ウォークスルー（集まって机上で手順をたどる）→シミュレーション（想定シナリオで演習）→パラレル（本番を止めずに代替サイトを実際に動かす）と段階を踏んだ後に初めて実施するのが定石です。手順の暗記は文書化された手順書の存在より劣り（属人化はむしろリスク）、残業代や天候は本質ではありません。DR（災害復旧）テストは、障害時に代替サイトへ切り替えられるかを確かめる訓練です。📖 復習: 第26章

</details>

**問7.** 深夜のデータセンターで、警備員が侵入者に脅され「異常なし」と定時連絡をするよう強要されています。このような状況に備えて事前に整備しておくべき仕組みはどれでしょう？

1. 連絡を2回繰り返すルール
2. 警備員の増員
3. 強要されていることを無言で伝える合図（duress コード）の取り決め
4. 定時連絡の廃止

<details><summary>答えと解説</summary>

正解: **3**

duress（強要）コードは、普段と違う特定の言い回しや偽のパスワードを使うことで「脅迫下にある」ことを相手に気づかれず本部へ伝える仕組みです。人の安全が常に最優先というCISSPの原則どおり、警備員は攻撃者に従うふりをしながら無言の警報を送れます。連絡の反復や増員はこの場面の解決にならず、定時連絡の廃止は異常検知の手段を自ら失う悪手です。人的安全のコントロールとして duress は頻出です。📖 復習: 第27章

</details>

**問8.** あるプログラムは、設定ファイルの権限を検査 (check) してから開く (use) までの間にわずかな時間差があり、攻撃者がその間にファイルをシンボリックリンクへ差し替えて権限昇格に成功しました。この脆弱性の分類と対策の組み合わせとして正しいのはどれでしょう？

1. バッファオーバーフロー — 境界チェックの追加
2. SQL インジェクション — パラメータ化クエリ
3. 整数オーバーフロー — 型の拡張
4. TOCTOU（検査時刻と使用時刻の差）による競合状態 — 検査と使用のアトミック化・ファイルロック

<details><summary>答えと解説</summary>

正解: **4**

検査 (Time of Check) と使用 (Time of Use) の間隙を突いて対象をすり替える攻撃は TOCTOU と呼ばれる競合状態 (race condition。処理の順番やタイミング次第で結果が変わってしまう欠陥) の典型です。対策は検査と使用を不可分（アトミック）な1操作にする、ファイルロック（他のプロセスが触れないように押さえる）やファイルディスクリプタ（開いたファイルを指す番号。開いた後は名前を差し替えられても同じ実体を指す）経由の操作に変えるなど、「隙間」自体をなくすことです。バッファ/整数オーバーフローはメモリ・数値演算の問題、SQL インジェクションは入力の問題で、シナリオと一致しません。流れの例: ①プログラムが /tmp/conf の権限を確認→OK ②その一瞬に攻撃者が /tmp/conf を /etc/shadow へのシンボリックリンク（別ファイルを指す「ショートカット」ファイル）に差し替え ③プログラムが高い権限で /tmp/conf を開くと、実際には /etc/shadow を開いてしまう。📖 復習: 第29章

</details>

**問9.** 社内アナリストは人事データベースの個別レコードへのアクセス権を持ちませんが、部門別の平均給与の照会を繰り返し条件を絞り込むことで、特定の1名の給与額を導き出しました。この問題と対策の組み合わせとして最も適切なのはどれでしょう？

1. 集計 (aggregation) — アクセスログの暗号化
2. 推論 (inference) — クエリ結果の最小件数制限やノイズ付加などの推論統制
3. SQL インジェクション — 入力検証
4. データマイニング — インデックスの削除

<details><summary>答えと解説</summary>

正解: **2**

許可された低感度の情報（統計値）から、許可されていない機密（個人の給与）を論理的に導き出すのは推論 (inference) 攻撃です。対策は結果が少数件になるクエリの拒否、ノイズの付加、ポリインスタンス化（同じ行を権限レベルごとに別の値で持たせる方法）などの推論統制です。集計 (aggregation) は「個々は無害な情報を大量に集めると全体として機密になる」という近縁だが別の概念で、本問は「導き出した」点が推論の決め手です。この2つの識別は D8 の超頻出ひっかけです。例: 「営業部の平均給与」と「営業部（Aさんを除く）の平均給与」を両方聞ければ、人数を掛けて差を取るだけで Aさんの給与が出ます。最小件数制限なら、対象が少なすぎる照会を拒否してこの差分計算を防げます。📖 復習: 第29章

</details>

1. テスト環境はファイアウォールの内側なのでコピーを許可する
2. 開発スピード優先で無条件に許可する

<details><summary>答えと解説</summary>

**問11.** 稼働中の Web アプリケーション内部で動作し、実行時の攻撃（インジェクション等）をアプリ自身の文脈で検知してその場でブロックする技術はどれでしょう？

1. RASP（ランタイムアプリケーション自己保護）

**問12.** 公開 REST API が自動化ツールによる大量リクエストでデータを根こそぎ取得（スクレイピング）されています。API を正規利用者に提供し続けながら悪用を抑えるための対策として最も適切な組み合わせはどれでしょう？

1. API の仕様書を非公開にする
2. API キー等による認証と、利用者単位のレート制限・クォータの適用
3. API サーバーの IP アドレスを毎週変更する
4. 全レスポンスを暗号化して返す

<details><summary>答えと解説</summary>

正解: **2**

悪用対策の基本は「誰が呼んでいるかを識別できるようにする（認証）」+「識別単位で呼び出し量を制御する（レート制限＝1分あたりなど短時間の上限、クォータ＝1日・1か月あたりの総量の上限）」の組み合わせです。これにより正規利用者への影響を抑えつつ、大量取得を構造的に抑止できます。仕様書の非公開は隠蔽による安全 (security by obscurity) にすぎず、IP 変更は正規利用者も巻き込む運用破綻、レスポンスの暗号化 (TLS) は盗聴対策であって認可された呼び出しの乱用には無力です。REST API は、URL と HTTP メソッド（GET/POST など）でデータを取得・更新する Web の窓口です。例: API キーごとに「1分60回まで」と決めれば、上限を超えた呼び出しには HTTP 429（Too Many Requests）を返して止められます。📖 復習: 第30章

</details>
