# 第34章 模試②（全ドメイン50問・出題比率準拠）

本試験1〜2週間前の総仕上げとして取り組む模試です。模試①より一段ひねった「2段階の思考」が必要な問題を多めに配置しています。間違えた問題は必ずにがて帳で解き直し、該当章の本文まで戻って「なぜその選択肢がBESTなのか」を自分の言葉で説明できるようにしましょう。

## 1. 模試② Part1: D1+D2（問1〜13）

模試②の前半戦です。Part1 はドメイン1「セキュリティとリスクマネジメント」から8問、ドメイン2「資産のセキュリティ」から5問の計13問。本試験の出題比率（D1 16%・D2 10%）に合わせています。

### 取り組み方

- 本試験ペースは **1問あたり約70〜90秒** です。13問を18分以内で解き切りましょう
- 模試②は「2段階の思考」を要する問題を多めにしています。シナリオの状況を整理→原則に当てはめる、の順で落ち着いて読んでください
- BEST/MOST/FIRST を問う問題は、**全選択肢が部分的に正しい**前提で「管理者として最も適切な一手」を選びます

💡 模試②で間違えた問題は、本試験までに必ず該当章へ戻って解き直しましょう。にがて帳からワンクリックで再挑戦できます。

### 確認問題

**問1.** ある企業の経営陣は、外部機関によるリスク評価を実施し、重大な脆弱性を列挙した報告書を受け取りました。しかしその後1年間、予算を理由に何の対策も指示しませんでした。この状況で欠けているものとして最も適切なのはどれでしょう？

1. デューデリジェンス (due diligence)
2. デューケア (due care)
3. 職務分掌 (separation of duties)
4. リスク移転 (risk transference)

<details><summary>答えと解説</summary>

正解: **2**

リスク評価を実施して「知る努力」をした点でデューデリジェンス（調査・把握）は果たされています。問題は、把握したリスクに対して合理的な行動を取っていないこと、つまりデューケア（思慮ある行動）の欠如です。この状態で侵害が起きると過失 (negligence) を問われます。職務分掌やリスク移転は本シナリオの論点ではありません。「調査した＝診断 (diligence)、行動した＝ケア (care)」とセットで覚え、どちらが欠けているかを状況から判定できるようにしましょう。

</details>

**問2.** 海外支社で使われている老朽化した業務システムについて、改修費用の見積りが年間予想損失 (ALE) を大きく上回り、しかも該当業務は本社システムへ統合可能なことがわかりました。リスクマネジメントの観点で最も適切な対応はどれでしょう？

1. サイバー保険に加入してリスクを移転する
2. 補償コントロールを追加してリスクを軽減する
3. システムを廃止し業務を本社へ統合してリスクを回避する
4. 現状を文書化してリスクを受容する

<details><summary>答えと解説</summary>

正解: **3**

対策費用が効果を上回り、かつその活動自体をやめられる（代替手段がある）場合は、リスクの原因となる活動を排除する「回避 (avoidance)」が最適です。軽減や移転はコストに見合わず、受容は統合という現実的な代替策があるのに損失可能性を放置する点で不適切です。「回避が選べるのは、やめても事業が成り立つとき」という条件まで読み取るのがポイントです。

</details>

**問3.** 資産価値 2,000万円のサーバーに対し、ある脅威の暴露係数 (EF) は 25%、年間発生率 (ARO) は 0.2 です。年間 60万円の対策を導入すると ALE が 20万円まで下がります。この対策の年間価値（費用対効果）はいくらでしょう？

1. 20万円
2. 40万円
3. 80万円
4. マイナス20万円

<details><summary>答えと解説</summary>

正解: **1**

SLE = 2,000万円 × 25% = 500万円、対策前 ALE = 500万円 × 0.2 = 100万円です。対策の価値 = 対策前ALE(100万) − 対策後ALE(20万) − 年間対策費用(60万) = 20万円。プラスなので導入する価値があります。40万円は対策費用の引き忘れ、80万円は対策後ALEの引き忘れによる誤答です。計算問題は「SLE→ALE→価値」の3段階を機械的に進めましょう。

</details>

**問4.** 多国籍企業のセキュリティポリシーが、新しく進出した国の個人データ保護法と矛盾していることが判明しました。セキュリティ責任者として最初に (FIRST) 取るべき行動はどれでしょう？

1. 本社ポリシーを優先し、現地でもそのまま適用する
2. 現地拠点だけポリシーの適用を免除する
3. 矛盾を文書化し、法務と連携して現地法に適合するようポリシーを改定する
4. 現地の法律が変わるまで事業を一時停止する

<details><summary>答えと解説</summary>

正解: **3**

法規制はポリシーより上位です。組織の内部ルールが法律と矛盾する場合は法律が優先され、ポリシー側を適合させる必要があります。その際は独断でなく法務部門と連携するのが管理者としての正しい手順です。本社ポリシーの強行は違法リスク、無条件の適用免除は統制の崩壊、事業停止は過剰反応です。「法律 > 規制 > ポリシー」の優先順位は試験全体で繰り返し問われます。

</details>

**問5.** BCP のテストとして、本番業務を止めずに代替サイトのシステムを実際に起動し、本番と並行して処理結果を検証する方式はどれでしょう？

1. 構造化ウォークスルー (structured walk-through)
2. シミュレーションテスト
3. パラレルテスト
4. フルインタラプションテスト

<details><summary>答えと解説</summary>

正解: **3**

パラレルテストは代替サイトを実際に稼働させつつ、本番業務は通常どおり継続する方式で、「実機検証」と「業務無停止」を両立します。構造化ウォークスルーは会議室での机上確認、シミュレーションはシナリオに沿った演習でシステムの実起動を伴わないか限定的、フルインタラプションは本番を実際に切り替える最もリスクの高いテストです。「本番を止めたか・代替サイトを動かしたか」の2軸で5方式を整理しましょう。

</details>

**問6.** 経理担当者が5年間ほとんど休暇を取らず、仕入先への支払処理を一人で完結させています。進行中かもしれない不正を「発見」するための管理策として最も効果的 (MOST) なのはどれでしょう？

1. 支払業務の手順書を整備する
2. 強制休暇 (mandatory vacation) を実施し、別の担当者に業務を引き継がせる
3. 支払システムに多要素認証を導入する
4. 本人にセキュリティ研修を受講させる

<details><summary>答えと解説</summary>

正解: **2**

強制休暇は、不正をしている本人を業務から引き離し、代わりの担当者が処理を行うことで隠蔽されていた不正が表面化する「発見的 (detective)」統制です。職務分掌は今後の不正を防ぐ予防的統制としては有効ですが、設問は「進行中の不正の発見」を求めています。手順書・MFA・研修はいずれもこのシナリオの不正発見には直接つながりません。問題文の「予防か発見か」という動詞を見逃さないようにしましょう。

</details>

**問7.** CISSP 保持者であるあなたは、顧客システムに重大な脆弱性を発見しました。顧客の担当役員は「公表も修正もせず黙っていてほしい。利用者への影響は当社が判断する」と指示しています。ISC2 倫理規範に照らして最も適切な行動はどれでしょう？

1. 契約相手である顧客の指示に従い、何もしない
2. 社会と公共の利益を第一に、組織内の適切なルートでエスカレーションし是正を働きかける
3. 利用者を守るため、ただちに SNS で脆弱性の詳細を公開する
4. 関与を避けるため理由を告げずに契約を打ち切る

<details><summary>答えと解説</summary>

正解: **2**

ISC2 倫理規範の4つのカノンは番号順に優先され、第1カノン「社会・公共の利益・インフラの保護」が依頼主への誠実なサービス（第3カノン）より上位です。したがって公共の利益を優先しつつ、無責任な暴露ではなく適切なエスカレーションで是正を促すのがBESTです。指示への盲従は第1カノン違反、SNS での即時公開は利用者をかえって危険にさらす無責任な開示、無言の契約打ち切りは問題を放置します。「カノンは番号順」が鉄則です。

</details>

**問8.** クラウドサービスの調達にあたり、稼働率 99.9% を下回った場合の返金条項を含む、法的拘束力のある合意を結びたいと考えています。最も適切な文書はどれでしょう？

1. SLA（サービスレベルアグリーメント）
2. MOU（覚書）
3. NDA（秘密保持契約）
4. BPA（事業パートナー契約）

<details><summary>答えと解説</summary>

正解: **1**

SLA は稼働率や応答時間といったサービス水準を数値で定義し、未達時のペナルティ（返金・違約金）まで定める法的拘束力のある契約です。MOU は意図の合意を示す文書で一般に拘束力が弱く、ペナルティ条項には不向きです。NDA は秘密情報の扱い、BPA はパートナー間の利益配分や責任分担を定めるもので、サービス水準の保証とは目的が異なります。「数値目標＋ペナルティ＝SLA」と覚えましょう。

</details>

**問9.** 極秘プロジェクトの終了に伴い、関連文書の機密区分を「社外秘」へ引き下げたいという依頼がありました。格下げ (declassification) の前に最も重要なステップはどれでしょう？

1. 文書をすべて暗号化する
2. カストディアンが独自の判断で速やかにラベルを貼り替える
3. データオーナーが格下げの妥当性をレビューし承認する
4. 文書を即座にシュレッダーで廃棄する

<details><summary>答えと解説</summary>

正解: **3**

分類と再分類（格下げを含む）の決定権限と責任はデータオーナーにあります。手続きなしに区分を下げると、保護が必要な情報が弱い管理下に流出する恐れがあるため、オーナーによるレビューと承認が必須です。カストディアンは日々の保護作業の実行者であり分類の決定者ではありません（超頻出のひっかけ）。暗号化や廃棄は格下げ判断そのものの代わりになりません。

</details>

**問10.** 政府系の情報分類で、漏えいした場合に国家安全保障へ「重大な損害 (serious damage)」を与えると想定される情報に付与される区分はどれでしょう？

1. Top Secret
2. Secret
3. Confidential
4. Unclassified

<details><summary>答えと解説</summary>

正解: **2**

政府分類は損害の程度で階層化されており、Top Secret は「例外的に重大な損害 (exceptionally grave damage)」、Secret は「重大な損害 (serious damage)」、Confidential は「損害 (damage)」に対応します。形容詞と区分の対応はそのまま出題される超頻出知識です。商用分類（Confidential/Private/Sensitive/Public など）との混同にも注意しましょう。

</details>

**問11.** リース満了で返却する SSD 搭載ノートPC 200台から、業務データを確実に読み出せなくしたいと考えています。機器を再利用可能な状態で返却する前提で、最も適切な方法はどれでしょう？

1. 強力な磁場をかける消磁 (degaussing) を行う
2. OS のゴミ箱を空にしてから初期化する
3. 暗号化消去 (crypto-erase) を実施し、結果を検証する
4. 各ドライブを物理的に粉砕する

<details><summary>答えと解説</summary>

正解: **3**

SSD はフラッシュメモリなので磁気に依存せず、消磁は無効です。またウェアレベリングにより上書き消去も完全性を保証できません。全領域を暗号化した鍵を破壊する暗号化消去なら、媒体を再利用可能なままデータを実質復元不能にでき、リース返却の要件に合致します。物理破壊は確実ですが「再利用可能な状態で返却」という前提に反します。ゴミ箱の削除は論理削除にすぎません。媒体の種類と廃棄方式の相性は超頻出です。

</details>

**問12.** 従業員が会社非公認のクラウドストレージ（シャドーIT）へ機密ファイルをアップロードしている実態を可視化し、ポリシーに基づいて利用を制御したいと考えています。最も適切なソリューションはどれでしょう？

1. ネットワーク型 DLP
2. CASB（クラウドアクセスセキュリティブローカー）
3. DRM（デジタル著作権管理）
4. SIEM

<details><summary>答えと解説</summary>

正解: **2**

CASB は組織とクラウドサービスの間に立ち、どのクラウドが使われているかの可視化（シャドーIT の発見）とポリシーベースの利用制御を担う、クラウド利用統制に特化したソリューションです。DLP は機密データの持ち出し検知が主目的で、未知のクラウドサービスの発見・制御は不得意です。DRM はファイル自体の利用権制御、SIEM はログの相関分析であり、どちらも「クラウド利用の可視化と制御」という要件には合いません。「クラウドの可視化なら CASB」が定石です。

</details>

**問13.** ある企業は「念のため」という理由で全従業員のメールを無期限に保存しています。この慣行がもたらす最大 (GREATEST) のリスクはどれでしょう？

1. ストレージ費用がわずかに増える
2. メールの検索速度が低下する
3. バックアップ時間が長くなる
4. 訴訟時の eディスカバリ対象と情報漏えい時の影響範囲が際限なく拡大する

<details><summary>答えと解説</summary>

正解: **4**

保持期間を定めず何でも保存すると、訴訟になった際に開示（eディスカバリ）すべきデータが膨大になり、コストと法的リスクが跳ね上がります。さらに侵害時に漏えいする情報量も増え続けます。これが「データは持っているだけでリスク」と言われる理由で、保持ポリシーに基づく計画的な廃棄 (defensible destruction) が正解の方向性です。費用・速度・バックアップ時間も影響はありますが、法的リスクに比べれば二次的です。

</details>

## 2. 模試② Part2: D3+D4（問14〜26）

Part2 はドメイン3「セキュリティアーキテクチャとエンジニアリング」から7問、ドメイン4「通信とネットワークのセキュリティ」から6問の計13問です（出題比率はともに13%）。

### このパートの頻出ポイント

- セキュリティモデルは「どの向きの読み書きを禁止するか」をルール名つきで即答できるか
- 暗号は「アルゴリズムの中身」より「攻撃の識別と運用（失効確認・鍵保護）」
- ネットワークは「そのプロトコル・機器が守れる範囲はどこまでか」（DNSSEC に機密性はない、AH に暗号化はない等）

💡 選択肢に迷ったら「このコントロールが『できないこと』は何か」を考えると、ひっかけを除外しやすくなります。13問を18分以内で解きましょう。

### 確認問題

**問1.** Bell-LaPadula モデルを実装したシステムで、Secret クリアランスのユーザーが Confidential（下位）レベルの文書へ書き込もうとしてブロックされました。このブロックの根拠となるルールはどれでしょう？

1. 単純セキュリティプロパティ（no read up）
2. スタープロパティ（no write down）
3. 単純完全性プロパティ（no read down）
4. 完全性スタープロパティ（no write up）

<details><summary>答えと解説</summary>

正解: **2**

Bell-LaPadula は機密性のモデルで、スタープロパティ（*-property）が上位レベルの主体から下位レベルへの書き込み（write down）を禁止します。上位の機密情報が下位区分へ流出するのを防ぐためです。単純セキュリティプロパティは「上を読むな」のルール。no read down と no write up は完全性モデル Biba のルールで、機密性のシナリオには適用されません。「BLP は機密性・Biba は完全性」「単純＝読み・スター＝書き」の2軸で整理すると混同しません。

</details>

**問2.** 「システム内のすべての主体から客体へのアクセスを例外なく仲介し、改ざんできず、検証可能なほど小さい」という要件を満たすべき抽象概念を、OS の中で実際に実装したものはどれと呼ばれるでしょう？

1. TCB（トラステッドコンピューティングベース）
2. セキュリティ境界 (security perimeter)
3. セキュリティカーネル (security kernel)
4. 保護リング (protection ring)

<details><summary>答えと解説</summary>

正解: **3**

設問前半の3要件（全アクセスの仲介・耐タンパ性・検証可能性）はリファレンスモニタの概念であり、それをハードウェア・ソフトウェアで実装したものがセキュリティカーネルです。TCB はセキュリティを担う構成要素全体の総称でより広い概念、セキュリティ境界は TCB とそれ以外の境目、保護リングは特権レベルの分離機構です。「概念＝リファレンスモニタ、実装＝セキュリティカーネル」の対応は超頻出です。

</details>

**問3.** ノートPC のフルディスク暗号化において、暗号鍵をマザーボード上の専用チップで保護し、ブート時にプラットフォームの改ざんがないことを検証したうえで鍵を解放したいと考えています。最も適切なコンポーネントはどれでしょう？

1. HSM（ハードウェアセキュリティモジュール）
2. TPM（トラステッドプラットフォームモジュール）
3. ソフトウェア鍵ストア
4. スマートカード

<details><summary>答えと解説</summary>

正解: **2**

TPM はマザーボードに搭載される暗号チップで、鍵の保護に加えてブート構成の測定値を保持し、プラットフォームが改ざんされていない場合のみ鍵を解放する（sealed storage）機能を持ちます。設問の「マザーボード上」「プラットフォーム検証」という2つの条件が TPM を指します。HSM は主にサーバー・データセンターで鍵を大量管理する外付け装置、ソフトウェア鍵ストアは耐タンパ性がなく、スマートカードは携帯型でプラットフォーム検証は行いません。

</details>

**問4.** 攻撃者が、内容は異なるがハッシュ値が同一になる2通の契約書を事前に用意し、無害な方に署名させてから悪意ある方へ差し替える攻撃を計画しています。この攻撃が悪用する性質はどれでしょう？

1. 誕生日攻撃による衝突 (collision)
2. レインボーテーブルによる逆算
3. 既知平文攻撃
4. ダウングレード攻撃

<details><summary>答えと解説</summary>

正解: **1**

同一ハッシュ値を持つ2つの異なる入力（衝突）を効率的に見つける手法が誕生日攻撃で、誕生日のパラドックスにより総当たりの半分程度の試行で衝突が見つかります。デジタル署名はハッシュ値に対して行われるため、衝突ペアを用意できれば署名の流用が可能になります。レインボーテーブルはハッシュからパスワードを逆引きする攻撃、既知平文攻撃は暗号鍵の解読、ダウングレードは弱いプロトコルへの誘導で、いずれも「衝突ペアの差し替え」というシナリオに合いません。

</details>

**問5.** TLS 通信で証明書の失効をリアルタイムに確認しつつ、クライアントが失効確認サーバーへ直接問い合わせることによる遅延とプライバシー露出を避けたいと考えています。最も適切な仕組みはどれでしょう？

1. CRL を毎週ダウンロードして照合する
2. 失効確認を省略する

<details><summary>答えと解説</summary>

正解: **4**

OCSP ステープリングでは、Web サーバー側が CA の OCSP レスポンダから署名済みの失効ステータスを定期取得し、TLS ハンドシェイク時にクライアントへ同梱（ステープル）します。クライアントは OCSP サーバーへ直接問い合わせずに最新の失効情報を検証でき、遅延もプライバシー露出も回避できます。週次の CRL では鮮度が足りず、失効確認の省略は論外、自己署名証明書は信頼チェーンを失わせる悪手です。

</details>

**問6.** 製造ラインを制御する SCADA システムに重大な脆弱性が見つかりましたが、ベンダーのサポートが終了しておりパッチは提供されません。ラインの停止も許されない場合、最も適切な対応はどれでしょう？

1. 脆弱性を文書化だけして運用を続ける
2. 業務時間外に最新 OS へ強制アップグレードする

<details><summary>答えと解説</summary>

正解: **3**

パッチ適用という本来のコントロールが使えない場合は、同等のリスク低減を別の手段で実現する補償コントロール (compensating control) を導入します。ICS/SCADA の定石はネットワーク分離・一方向通信・専用監視です。文書化だけでは軽減になっておらず、検証なしの強制アップグレードは制御系の可用性（と安全）を脅かし、外部からのリモート保守経路の追加は攻撃面をむしろ広げます。「パッチ不可→分離＋監視」のパターンは超頻出です。

</details>

**問7.** データセンターの消火設備を選定しています。誤作動による水損を避けたい一方、消防法上スプリンクラーの設置は必要です。最も適切な方式はどれでしょう？

1. プリアクション (preaction) 式スプリンクラー
2. 湿式 (wet pipe) スプリンクラー
3. 一斉開放 (deluge) 式スプリンクラー
4. 二酸化炭素 (CO2) の自動放出のみで代替する

<details><summary>答えと解説</summary>

正解: **1**

プリアクション式は、火災検知器の作動で初めて配管に水が充填され、さらにヘッドの熱作動で放水される2段階方式のため、誤作動や配管損傷による水損リスクが最小で、データセンターの定番です。湿式は常時加圧水が配管内にあり漏水リスクが高く、一斉開放式は全ヘッドから一斉放水するため被害が甚大です。CO2 は窒息の危険があり有人区画の自動放出は人命リスクが高く、スプリンクラー代替にもなりません。人の安全が常に最優先である点も思い出しましょう。

</details>

**問8.** DNSSEC を導入した場合に得られる保護として、正しい説明はどれでしょう？

1. DNS 応答が暗号化され、問い合わせ内容の盗聴を防げる
2. DNS 応答のなりすましと改ざんを、デジタル署名の検証で検知できる
3. DNS サーバーへの DDoS 攻撃を防げる
4. ゾーン転送が自動的に無効化される

<details><summary>答えと解説</summary>

正解: **2**

DNSSEC は DNS レコードにデジタル署名を付与し、応答の出所の真正性と完全性を検証可能にします。これによりキャッシュポイズニングのような改ざん・なりすましを検知できます。一方、応答は暗号化されないため盗聴（機密性）には無力で、それを補うのは DoH/DoT です。DDoS 防御やゾーン転送の制御も DNSSEC の機能ではありません。「DNSSEC＝署名＝完全性と真正性のみ、機密性なし」は超頻出のひっかけです。

</details>

**問9.** 拠点間 VPN で、経路上の盗聴からペイロードの内容を保護することが必須要件です。IPsec の構成として最も適切なのはどれでしょう？

1. AH をトンネルモードで使用する
2. AH をトランスポートモードで使用する
3. ESP をトンネルモードで使用する
4. IKE のみを使用する

<details><summary>答えと解説</summary>

正解: **3**

暗号化（機密性）を提供するのは ESP で、AH は完全性と認証のみで暗号化しません（超頻出のひっかけ）。また拠点間 VPN では元の IP ヘッダごとカプセル化するトンネルモードが標準です。したがって「ESP＋トンネルモード」が正解。IKE は鍵交換と SA 確立を担うプロトコルで、それ単体ではデータを運びません。「AH＝認証ヘッダ・暗号化なし」「サイト間＝トンネル」の2点で即答できます。

</details>

**問10.** 公開 Web アプリケーションに対する SQL インジェクションや XSS といった攻撃を、アプリケーションの手前で検査・遮断したいと考えています。最も適切な防御はどれでしょう？

1. ステートフルファイアウォールのルール強化
2. ネットワーク IDS の増設
3. ポートベースのACLをルーターへ追加

<details><summary>答えと解説</summary>

正解: **4**

SQL インジェクションや XSS は HTTP リクエストの中身（アプリケーション層）に仕込まれる攻撃なので、HTTP を解析してシグネチャ・ルールで遮断する WAF が最適です。ステートフルFWやポートACLは L3/L4 の制御であり、正規のポート443を通る攻撃ペイロードは素通りします。NIDS は検知のみで遮断しません（インラインの IPS ではない点に注意）。「攻撃がどの層か→対策もその層か」を常に確認しましょう。

</details>

**問11.** 侵害発生時の攻撃者による横移動 (lateral movement) をデータセンター内のワークロード単位で制限したいと考えています。最も効果的 (MOST) なアプローチはどれでしょう？

1. 境界ファイアウォールのインバウンドルールを厳格化する
2. ワークロード単位でポリシーを適用するマイクロセグメンテーションを導入する
3. 全サーバーを同一 VLAN に集約して管理を簡素化する
4. IDS のシグネチャを最新化する

<details><summary>答えと解説</summary>

正解: **2**

横移動は「すでに内部に入った攻撃者」の東西方向の通信なので、境界（南北方向）の防御強化では止められません。マイクロセグメンテーションはワークロード・サービス単位で通信ポリシーを強制し、侵害の影響範囲を最小化するゼロトラストの中核技術です。同一 VLAN への集約はむしろ横移動を容易にする逆効果、IDS の更新は検知の改善であって通信の制限ではありません。「境界型 vs 内部の東西制御」の対比を意識しましょう。

</details>

**問12.** カフェなどの公共スペースで、正規のアクセスポイントと同じ SSID を名乗る偽 AP（Evil Twin）に社員が接続してしまうリスクを低減したい。技術的対策として最も効果的なのはどれでしょう？

1. SSID をステルス化する
2. MAC アドレスフィルタリングを導入する
3. サーバー証明書を検証する 802.1X/EAP-TLS 認証と常時 VPN を併用する
4. パスフレーズをより長い WPA2-PSK に変更する

<details><summary>答えと解説</summary>

正解: **3**

Evil Twin 対策の本質は「接続先の AP・ネットワークが本物か」を検証することです。EAP-TLS では端末がサーバー証明書を検証するため偽 AP への認証が成立せず、さらに常時 VPN なら万一偽 AP に接続しても通信内容が保護されます。SSID ステルスや MAC フィルタは攻撃者が容易に回避でき（どちらも傍受で判明）、PSK の強化は自社 AP の話であって、攻撃者が自前で立てる偽 AP には無関係です。

</details>

**問13.** 自社ドメインをかたるなりすましメールへの対策として SPF・DKIM・DMARC を導入します。このうち DMARC が担う役割として正しいのはどれでしょう？

1. 送信元 IP アドレスが正規の送信サーバーかを DNS で検証する
2. メール本文とヘッダへの署名で改ざんを検知する
3. メール本文を暗号化して機密性を守る
4. SPF/DKIM の検証に失敗したメールの取り扱いポリシー（隔離・拒否）を宣言し、レポートを受け取る

<details><summary>答えと解説</summary>

正解: **4**

DMARC は SPF（送信元 IP の検証）と DKIM（署名による改ざん検知）の検証結果を踏まえ、不合格メールを none/quarantine/reject のどれで扱うかを DNS で宣言し、受信側から集計レポートを受け取る仕組みです。「送信元 IP アドレスが正規の送信サ…」は SPF、「メール本文とヘッダへの署名で改ざんを検知する」は DKIM の説明。メール本文の暗号化は S/MIME や PGP の役割で、SPF/DKIM/DMARC はいずれも機密性を提供しません。3つの役割分担表は超頻出です。

</details>

## 3. 模試② Part3: D5+D6（問27〜38）

Part3 はドメイン5「アイデンティティとアクセスの管理 (IAM)」から7問、ドメイン6「セキュリティの評価とテスト」から5問の計12問です（出題比率は D5 13%・D6 12%）。

### このパートの頻出ポイント

- 認証は「指標の向き」（FAR を下げると FRR が上がる）と「プロトコルの守備範囲」（OAuth は認可、認証ではない）
- アクセス制御モデルは「誰が・何を基準に許可を決めるか」で識別
- 評価とテストは「実施前の手続き」（交戦規定・書面の許可）と「報告書の種類」（SOC 2 Type Ⅱ）

💡 シナリオ問題では、技術的に可能な選択肢より「管理者として説明責任を果たせる選択肢」が正解になりがちです。12問を16分以内で解きましょう。

### 確認問題

**問1.** データセンターの入室管理に虹彩認証を導入します。許可されていない人物の入室を最小限にすることが最優先の要件である場合、しきい値の調整方針として正しいのはどれでしょう？

1. FRR（本人拒否率）を最小化する。FAR が上がるのは許容する
2. CER（交差エラー率）が最大になるよう調整する
3. FAR（他人受入率）を最小化する。FRR が上がるのは許容する
4. FAR と FRR を両方ともゼロにする

<details><summary>答えと解説</summary>

正解: **3**

許可されていない人物を通さないこと＝他人受入 (FAR、Type 2 エラー) の最小化が最優先です。しきい値を厳しくすると FAR は下がりますが、本人が拒否される FRR (Type 1) は上がるトレードオフが生じ、高セキュリティ施設ではこれを許容します。CER は FAR と FRR が交差する点で装置の精度比較に使う指標（低いほど高精度）であり、「最大化」は無意味です。両方ゼロは現実には不可能です。「守りたいものに合わせてどちらのエラーを許容するか」が問われます。

</details>

**問2.** 開発チームが「OAuth 2.0 を導入したのでユーザー認証は完了している」と報告してきました。セキュリティレビューアとして指摘すべき点はどれでしょう？

1. OAuth 2.0 は認可 (authorization) のフレームワークであり、認証には OIDC などの仕組みを追加する必要がある
2. OAuth 2.0 は暗号化を提供しないため TLS が不要になる点
3. OAuth 2.0 はオンプレミス環境では動作しない点
4. OAuth 2.0 はパスワードを平文で送信する点

<details><summary>答えと解説</summary>

正解: **1**

OAuth 2.0 は「ユーザーの代わりにアプリへ限定的なアクセス権を委譲する」認可のフレームワークで、ユーザーが誰かを保証する認証プロトコルではありません。認証が必要なら OAuth の上に ID トークン（JWT）を加えた OIDC (OpenID Connect) を使います。これは超頻出のひっかけです。他の選択肢は事実として誤り：TLS は引き続き必須、オンプレでも動作し、パスワードを平文送信する仕様でもありません。

</details>

**問3.** 数百台のネットワーク機器への管理者アクセスについて、コマンド単位の認可と通信全体の暗号化、認証・認可・アカウンティングの分離を要件としています。最も適切なプロトコルはどれでしょう？

1. RADIUS
2. TACACS+
3. LDAP
4. SAML

<details><summary>答えと解説</summary>

正解: **2**

TACACS+ は TCP 上で動作し、パケット全体を暗号化し、AAA（認証・認可・アカウンティング）を分離して扱えるため、コマンド単位の認可が必要な機器管理に最適です。RADIUS は UDP でパスワード部分しか暗号化せず、認証と認可が一体で細かな認可制御に不向き（ネットワークアクセス用途が主）。LDAP はディレクトリ参照、SAML は Web SSO のフェデレーションであり、機器管理 AAA の要件に合いません。RADIUS と TACACS+ の対比表は頻出です。

</details>

**問4.** 監視チームが「多数のアカウントに対し、少数のよくあるパスワードを低頻度で試すログイン失敗が広範囲で発生している」と報告しました。この攻撃と、それでも突破されないための最も効果的な対策の組み合わせはどれでしょう？

1. ブルートフォース攻撃 — アカウントロックアウトの強化
2. クレデンシャルスタッフィング — パスワード定期変更の義務化
3. 辞書攻撃 — SSID のステルス化
4. パスワードスプレー攻撃 — フィッシング耐性のある多要素認証の導入

<details><summary>答えと解説</summary>

正解: **4**

「多数アカウント×少数パスワード×低頻度」はロックアウトを回避するよう設計されたパスワードスプレー攻撃の典型パターンです。ロックアウト強化はこの攻撃にほぼ無力（1アカウントあたりの試行が閾値未満）なので、パスワードが破られても突破されない MFA が最も効果的です。クレデンシャルスタッフィングは「漏えい済みの ID/パスワードの組」を使い回す別の攻撃で、定期変更の強制は現代のベストプラクティスでもありません。攻撃パターンの識別と対策をセットで問う2段階問題です。

</details>

**問5.** 「経理部に所属し、社給の準拠端末を使い、平日9〜18時に国内からアクセスしている場合のみ決裁システムの承認操作を許可する」という要件を実装したい。最も適した制御モデルはどれでしょう？

1. DAC（任意アクセス制御）
2. MAC（強制アクセス制御）
3. ABAC（属性ベースアクセス制御）
4. 単純な RBAC（役割ベースアクセス制御）

<details><summary>答えと解説</summary>

正解: **3**

部署（主体属性）・端末の準拠状態（環境属性）・時間帯・場所という複数の属性を組み合わせて動的にアクセスを判断するのは ABAC の得意分野です。RBAC は役割だけで決めるため時間・場所・端末状態の条件を表現できず、DAC はオーナーの裁量ベース、MAC はラベルとクリアランスによる制御で、いずれも要件に合いません。「役割＋環境条件の動的な組み合わせ→ABAC」というパターン認識が有効です。

</details>

**問6.** システム管理者が常時 Domain Admin 権限を保有している現状を改善し、特権の悪用・窃取リスクを下げたいと考えています。最も効果的 (MOST) なアプローチはどれでしょう？

1. 管理者のパスワードをより複雑にする
2. PAM を導入し、承認に基づくジャストインタイム (JIT) の特権昇格と操作記録に切り替える
3. 管理者数を増やして負荷を分散する
4. 特権アカウントの命名規則を変更して推測しにくくする

<details><summary>答えと解説</summary>

正解: **2**

常時付与された強力な特権は、窃取されれば即座に最大の被害につながります。PAM によるジャストインタイム昇格なら、特権は必要な作業の間だけ承認を経て付与され、セッションは記録されるため、悪用の機会と攻撃対象時間 (attack window) が大幅に縮小します。パスワード強化や命名規則は常時特権という構造的問題を解決せず、管理者の増員はむしろ特権保有者を増やして逆効果です。

</details>

**問7.** アクセスレビューの結果、退職者のアカウント12個が90日以上有効なまま残っていたことが判明しました。再発防止として最も効果的なのはどれでしょう？

<details><summary>答えと解説</summary>

正解: **3**

休眠アカウントが残る根本原因は「退職イベントとアカウント無効化が人手で分断されている」ことなので、人事（権威ソース）と ID 管理を連動させた自動デプロビジョニングが根本対策です。棚卸し頻度の増加は発見を早めるだけの発見的統制で、90日の放置が45日になるにすぎません。一斉リセットや注意喚起は一時的・属人的で再発を防ぎません。「検出の高速化より、発生させない自動化」という優先順位が問われています。

</details>

**問8.** 脆弱性スキャンの方式を検討しています。OS 内部のパッチ適用漏れや設定不備まで検出したい場合、どの方式を選ぶべきでしょう？

1. 認証スキャン（credentialed scan）
2. 非認証スキャン（uncredentialed scan）

4. ポートスキャンのみ

<details><summary>答えと解説</summary>

正解: **1**

認証スキャンはスキャナに有効な資格情報を与えてシステム内部へログインさせる方式で、パッチレベル・設定・インストール済みソフトまで正確に検査でき、誤検知も減ります。非認証スキャンは攻撃者から見える外形のみの検査で内部の不備は見えません。パッシブスキャンはトラフィック観察のみ、ポートスキャンは開放ポートの列挙にすぎず、どちらも設定不備の検出には不十分です。「内部の状態まで見たい→認証スキャン」が定石です。

</details>

**問9.** 外部業者によるペネトレーションテストを計画しています。テスト開始前に最も重要 (MOST) なものはどれでしょう？

1. 最新の攻撃ツールの選定
2. テスト範囲・手法・時間帯・緊急連絡先を定めた交戦規定と、経営層による書面の許可
3. テスターへの社内システム管理者権限の付与
4. 全従業員へのテスト日時の周知

<details><summary>答えと解説</summary>

正解: **2**

許可なき侵入テストは不正アクセスと同じであり、範囲・手法・除外対象・中断条件・連絡体制を定めた交戦規定 (rules of engagement) と権限者による書面の事前承認が何より優先です。これがないとテスター・依頼側双方が法的リスクを負います。ツール選定は手段の話で後工程、管理者権限の付与はテスト種別（ホワイトボックス等）によるもので必須ではなく、全従業員への周知は検知対応を試すテストでは意図的に行わないこともあります。

</details>

**問10.** クラウドサービス事業者の内部統制が「一定期間にわたって有効に運用されていたこと」の独立した保証を得たい。要求すべき報告書はどれでしょう？

1. SOC 1 Type Ⅰ
2. SOC 3
3. ベンダー自身が作成したセキュリティホワイトペーパー
4. SOC 2 Type Ⅱ

<details><summary>答えと解説</summary>

正解: **4**

セキュリティ・可用性等のトラストサービス基準に関する統制を扱うのは SOC 2 で、Type Ⅱ は6〜12か月の期間にわたる運用の有効性を独立監査人がテストした報告書です。「ある時点の設計」しか見ない Type Ⅰ より保証水準が高く、デューデリジェンスの定番要求です。SOC 1 は財務報告に係る統制が対象、SOC 3 は一般公開用の要約で詳細を欠き、自作のホワイトペーパーは独立した保証ではありません。

</details>

**問11.** EC サイトの購入フローが正常に動作しているかを、実際の顧客に影響を与えずに24時間自動で監視したいと考えています。最も適切な手法はどれでしょう？

1. RUM（リアルユーザーモニタリング）
2. 合成トランザクション（synthetic transaction）
3. 本番データベースへの直接クエリ
4. 顧客アンケートの定期実施

<details><summary>答えと解説</summary>

正解: **2**

合成トランザクションは、スクリプト化したテスト用の操作（検索→カート→決済直前まで等）を定期実行して機能と応答を監視する手法で、実顧客が現れない深夜でも異常を検知できます。RUM は実ユーザーのアクセスを観測する受動的手法なので、トラフィックがない時間帯は何も分からず「顧客に影響が出てから」の検知になりがちです。本番 DB への直接クエリは購入フロー全体の動作確認にならず、アンケートはリアルタイム性がありません。

</details>

**問12.** セキュリティ態勢の報告指標を整備しています。「将来のリスク増大を早期に警告する先行指標」に該当するものはどれでしょう？

1. KRI — 例: パッチ未適用期間が SLA を超過しているシステムの増加数
2. KPI — 例: 先月完了したインシデント対応の件数
3. ROI — 例: セキュリティ投資の回収率
4. SLA — 例: 合意済みの復旧時間

<details><summary>答えと解説</summary>

正解: **1**

KRI（重要リスク指標）は「このまま行くと危ない」を先回りして示す先行指標で、パッチ遅延の増加・権限レビューの滞留などが典型です。KPI は達成度を測る事後（遅行）指標、ROI は投資対効果、SLA は合意された目標値そのものであり、いずれも将来リスクの早期警告という役割ではありません。経営層への報告では KPI（現在の成績）と KRI（将来の危険信号）を組み合わせるのが定石です。

</details>

## 4. 模試② Part4: D7+D8（問39〜50）

最終パートはドメイン7「セキュリティの運用」から7問、ドメイン8「ソフトウェア開発セキュリティ」から5問の計12問です（出題比率は D7 13%・D8 10%）。

### このパートの頻出ポイント

- 運用は「順序」を問う問題が多い（証拠の揮発性、インシデント対応の7段階、バックアップの復元手順）
- 法的シナリオでは「証拠能力を守る手続き」を踏んだ選択肢が BEST
- 開発は「技術の名前」より「どの工程・どの統制で防ぐか」

💡 これで模試②は終了です。50問中35問（70%）が安定して取れていれば、本試験の合格ラインが見えています。間違えた問題のドメインに偏りがないかも必ず確認しましょう。

### 確認問題

**問1.** 侵害が疑われるサーバーのフォレンジック調査を開始します。証拠の揮発性 (order of volatility) に従う場合、最初に (FIRST) 収集すべきものはどれでしょう？

1. ディスク上のログファイル
2. オフサイトのバックアップテープ
3. CPU のレジスタとキャッシュの内容
4. ネットワーク機器の設定ファイル

<details><summary>答えと解説</summary>

正解: **3**

証拠収集は揮発性の高い順に行います。CPU レジスタ・キャッシュ→メモリ→ネットワーク状態・実行中プロセス→ディスク→バックアップ媒体の順で、最も消えやすい CPU レジスタ・キャッシュが最優先です。ディスク上のログや設定ファイル、バックアップは電源断後も残るため後回しにできます。「電源を切った瞬間に失われるものから集める」と覚えると、順序の並べ替え問題にも対応できます。

</details>

**問2.** 自社を相手取る訴訟の通知が届き、法務部門から訴訟ホールド (litigation hold) の指示が出ました。IT 部門が最初に (FIRST) 行うべきことはどれでしょう？

1. 保持ポリシーに従い予定どおり古いメールの自動削除を続行する
2. 関連しうるデータの削除・自動廃棄を直ちに停止し、保全する
3. 関連データをすべて外部の弁護士へ即時送付する
4. 対象データを暗号化して誰も読めないようにする

<details><summary>答えと解説</summary>

正解: **2**

訴訟ホールドが発動したら、通常の保持ポリシーに基づく自動削除よりホールドが優先され、関連しうる情報 (ESI) の削除停止と保全が最優先です。削除を続行すると証拠隠滅 (spoliation) とみなされ制裁の対象になります。弁護士への送付は eディスカバリの後工程（収集・レビュー・提出）で、まず保全が先。暗号化で読めなくすることは保全ではなく、開示義務への妨げになります。「ホールド＞保持ポリシー」の優先関係が核心です。

</details>

**問3.** 社内ネットワークに、わざと魅力的に見える疑似サーバー（ハニーポット）を設置して攻撃者の手口を観察しています。この運用が合法的な「誘引 (enticement)」にとどまり、違法となりうる「罠にはめる行為 (entrapment)」にならないために重要な条件はどれでしょう？

1. もともと侵入の意図を持つ者に機会を見せるだけにとどめ、犯行をそそのかさない
2. ハニーポットに本物の顧客データを置いて現実味を高める
3. 攻撃者の端末へ逆侵入して証拠を収集する
4. 観察した手口を攻撃者本人へ通知する

<details><summary>答えと解説</summary>

正解: **1**

誘引 (enticement) は「すでに犯意を持つ者に機会を提示する」ことで合法とされ、証拠としても有効です。一方、犯意のなかった者をそそのかして犯行させるのは entrapment（違法な囮）で、証拠能力や訴追に問題が生じます。本物の顧客データを置くのはそれ自体がデータ保護義務違反、逆侵入（ハックバック）は自身が不正アクセスになる行為、手口の通知は無意味です。この対概念は D7 の超頻出論点です。

</details>

**問4.** CISSP の示すインシデント管理の7段階（検知→対応→軽減→報告→復旧→修復→教訓）において、「軽減 (mitigation)」の段階で行う活動として最も適切なのはどれでしょう？

1. 根本原因を恒久的に除去し、再発防止策を実装する
2. 感染した端末をネットワークから隔離し、被害の拡大を封じ込める
3. システムを通常運用の状態へ戻す
4. 対応の記録を振り返り、プロセスの改善点を文書化する

<details><summary>答えと解説</summary>

正解: **2**

軽減は「封じ込め (containment)」の段階で、感染端末の隔離やアカウントの無効化により被害の拡大を止めることが目的です。根本原因の恒久的な除去は修復 (remediation)、通常運用への回帰は復旧 (recovery)、振り返りは教訓 (lessons learned) の活動で、それぞれ段階が異なります。7段階は順序の並べ替えや「この活動はどの段階か」という形式で頻出なので、各段階の代表的な活動をセットで覚えましょう。

</details>

**問5.** 日曜夜にフルバックアップ、月〜土曜夜に増分 (incremental) バックアップを取得しています。木曜の朝にストレージ障害が発生した場合、完全復旧に必要なバックアップセットはどれでしょう？

1. 日曜のフルバックアップのみ
2. 日曜のフルバックアップと水曜の増分
3. 日曜のフルバックアップと月・火・水曜の増分すべて
4. 水曜の増分のみ

<details><summary>答えと解説</summary>

正解: **3**

増分バックアップは「前回の何らかのバックアップ以降」の変更だけを保存するため、復元にはフル＋障害直前までのすべての増分（月・火・水）が必要で、合計4セットを順に適用します。これが差分 (differential) なら「前回のフル以降」の変更を毎回含むため、フル＋最新の差分の2セットで済みます（「日曜のフルバックアップと水曜の増分」は差分の場合の答え）。「増分＝全部必要・差分＝最新1つ」のトレードオフ（バックアップは速いが復元が遅い）は計算形式で超頻出です。

</details>

**問6.** DR テストとして、本番システムを実際に停止して代替サイトへ切り替えるフルインタラプションテストを提案します。実施の前提として最も重要 (MOST) なのはどれでしょう？

1. テスト担当者の残業代の確保
2. 本番停止に伴う事業リスクを理解した経営陣による明示的な承認
3. 切り替え手順を担当者が暗記していること
4. テスト当日の天候の確認

<details><summary>答えと解説</summary>

正解: **2**

フルインタラプションテストは本番業務の実停止を伴う最もリスクの高いテストで、切り戻しに失敗すれば実害が出ます。したがって、そのリスクを受容できるのは経営陣だけであり、事前の明示的な承認が絶対条件です。読み合わせ→ウォークスルー→シミュレーション→パラレルと段階を踏んだ後に初めて実施するのが定石です。手順の暗記は文書化された手順書の存在より劣り（属人化はむしろリスク）、残業代や天候は本質ではありません。

</details>

**問7.** 深夜のデータセンターで、警備員が侵入者に脅され「異常なし」と定時連絡をするよう強要されています。このような状況に備えて事前に整備しておくべき仕組みはどれでしょう？

1. 連絡を2回繰り返すルール
2. 警備員の増員
3. 強要されていることを無言で伝える合図（duress コード）の取り決め
4. 定時連絡の廃止

<details><summary>答えと解説</summary>

正解: **3**

duress（強要）コードは、普段と違う特定の言い回しや偽のパスワードを使うことで「脅迫下にある」ことを相手に気づかれず本部へ伝える仕組みです。人の安全が常に最優先というCISSPの原則どおり、警備員は攻撃者に従うふりをしながら無言の警報を送れます。連絡の反復や増員はこの場面の解決にならず、定時連絡の廃止は異常検知の手段を自ら失う悪手です。人的安全のコントロールとして duress は頻出です。

</details>

**問8.** あるプログラムは、設定ファイルの権限を検査 (check) してから開く (use) までの間にわずかな時間差があり、攻撃者がその間にファイルをシンボリックリンクへ差し替えて権限昇格に成功しました。この脆弱性の分類と対策の組み合わせとして正しいのはどれでしょう？

1. バッファオーバーフロー — 境界チェックの追加
2. SQL インジェクション — パラメータ化クエリ
3. 整数オーバーフロー — 型の拡張
4. TOCTOU（検査時刻と使用時刻の差）による競合状態 — 検査と使用のアトミック化・ファイルロック

<details><summary>答えと解説</summary>

正解: **4**

検査 (Time of Check) と使用 (Time of Use) の間隙を突いて対象をすり替える攻撃は TOCTOU と呼ばれる競合状態 (race condition) の典型です。対策は検査と使用を不可分（アトミック）な1操作にする、ファイルロックやファイルディスクリプタ経由の操作に変えるなど、「隙間」自体をなくすことです。バッファ/整数オーバーフローはメモリ・数値演算の問題、SQL インジェクションは入力の問題で、シナリオと一致しません。

</details>

**問9.** 社内アナリストは人事データベースの個別レコードへのアクセス権を持ちませんが、部門別の平均給与の照会を繰り返し条件を絞り込むことで、特定の1名の給与額を導き出しました。この問題と対策の組み合わせとして最も適切なのはどれでしょう？

1. 集計 (aggregation) — アクセスログの暗号化
2. 推論 (inference) — クエリ結果の最小件数制限やノイズ付加などの推論統制
3. SQL インジェクション — 入力検証
4. データマイニング — インデックスの削除

<details><summary>答えと解説</summary>

正解: **2**

許可された低感度の情報（統計値）から、許可されていない機密（個人の給与）を論理的に導き出すのは推論 (inference) 攻撃です。対策は結果が少数件になるクエリの拒否、ノイズの付加、ポリインスタンス化などの推論統制です。集計 (aggregation) は「個々は無害な情報を大量に集めると全体として機密になる」という近縁だが別の概念で、本問は「導き出した」点が推論の決め手です。この2つの識別は D8 の超頻出ひっかけです。

</details>

**問10.** 開発チームが「本番の顧客データをそのままテスト環境へコピーして結合テストに使いたい」と申請してきました。セキュリティ管理者として最も適切 (BEST) な回答はどれでしょう？

1. テスト環境はファイアウォールの内側なのでコピーを許可する
2. 開発スピード優先で無条件に許可する
3. マスキングした匿名化データまたは合成データの使用を求め、本番データのコピーは原則禁止とする
4. 本番データベースを直接テストに使わせる

<details><summary>答えと解説</summary>

正解: **3**

テスト環境は本番より統制が緩く、アクセスする人員も広いため、生の顧客データを持ち込むと漏えいリスクと規制違反（GDPR 等の目的外利用）を招きます。マスキング・匿名化・合成データならテストの実効性を保ちつつリスクを除去できます。「FW の内側だから安全」は境界防御への過信、本番 DB の直接利用は可用性・完全性の両方を脅かす最悪の選択肢です。環境分離と本番データの保護は D8 の定番シナリオです。

</details>

**問11.** 稼働中の Web アプリケーション内部で動作し、実行時の攻撃（インジェクション等）をアプリ自身の文脈で検知してその場でブロックする技術はどれでしょう？

1. RASP（ランタイムアプリケーション自己保護）
2. SAST（静的アプリケーションセキュリティテスト）
3. SCA（ソフトウェアコンポジション解析）
4. ファジング

<details><summary>答えと解説</summary>

正解: **1**

RASP はアプリケーションのランタイムに組み込まれ、実行コンテキスト（どのクエリがどの入力で実行されたか）を見て攻撃を検知・遮断する防御技術です。SAST はソースコードを実行せずに解析する開発段階のテスト、SCA は依存ライブラリの既知脆弱性の検出、ファジングは異常入力を自動投入して欠陥を見つけるテスト手法で、いずれも「本番実行中にその場でブロック」という役割ではありません。テスト技術（SAST/DAST/IAST）と防御技術（RASP）の区別が問われます。

</details>

**問12.** 公開 REST API が自動化ツールによる大量リクエストでデータを根こそぎ取得（スクレイピング）されています。API を正規利用者に提供し続けながら悪用を抑えるための対策として最も適切な組み合わせはどれでしょう？

1. API の仕様書を非公開にする
2. API キー等による認証と、利用者単位のレート制限・クォータの適用
3. API サーバーの IP アドレスを毎週変更する
4. 全レスポンスを暗号化して返す

<details><summary>答えと解説</summary>

正解: **2**

悪用対策の基本は「誰が呼んでいるかを識別できるようにする（認証）」+「識別単位で呼び出し量を制御する（レート制限・クォータ）」の組み合わせです。これにより正規利用者への影響を抑えつつ、大量取得を構造的に抑止できます。仕様書の非公開は隠蔽による安全 (security by obscurity) にすぎず、IP 変更は正規利用者も巻き込む運用破綻、レスポンスの暗号化 (TLS) は盗聴対策であって認可された呼び出しの乱用には無力です。

</details>
