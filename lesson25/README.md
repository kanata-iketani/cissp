# 第25章 インシデント対応とマルウェア対策【D7】

インシデントは「起きるかどうか」ではなく「いつ起きるか」の問題です。この章では CISSP 公式の7段階インシデント管理プロセス、マルウェアの分類、エンドポイント防御、そしてパッチ運用までを学びます。D7 の中でも出題が多く、「次に何をすべきか (What should you do NEXT?)」形式のシナリオ問題の主戦場です。

## 1. インシデント管理のプロセス（7段階）

### イベントとインシデント

**イベント (event)** は観測可能なあらゆる出来事（ログイン、ファイルアクセスなど）で、それ自体は中立です。そのうち、機密性・完全性・可用性に**悪影響を与える、または与えるおそれのあるもの**が**インシデント (incident)** です。「イベント=すべて記録される出来事、インシデント=対応が必要な悪い出来事」と区別しましょう。

### CISSP 公式の7段階

| 段階 | 英語 | やること |
|---|---|---|
| 1. 検知 | Detection | IDS（第17章）・SIEM（第24章）・ユーザー報告などで異常に気づき、本物か（擬陽性＝正常なものを異常と誤判定したものでないか）を見極める |
| 2. 対応 | Response | CSIRT（インシデント対応の専門チーム）を招集し、**封じ込め (containment)** で被害拡大を止める。証拠保全のため電源は切らずネットワークから隔離が基本 |
| 3. 軽減 | Mitigation | 原因を特定し、被害の根を断つ（感染端末の隔離徹底など） |
| 4. 報告 | Reporting | 経営層・規制当局・顧客など**社内外への通知**。GDPR（第3章で見た EU の個人データ保護規則）の72時間通知のような法的義務も含む |
| 5. 復旧 | Recovery | システムを通常運用に戻す。再構築後は**元のセキュリティ状態に戻っているか検証**する |
| 6. 修復 | Remediation | 根本原因 (root cause) を分析し、再発防止策（パッチ、設定変更）を実装する |
| 7. 教訓 | Lessons Learned | 対応全体を振り返り、プロセス改善につなげる。**最終報告は経営層へ** |

> 💡 コツ：順序の並べ替え問題が超頻出です。「**け・た・け・ほ・ふ・しゅ・きょ**」ではなく英語の頭文字 **D-R-M-R-R-R-L** の流れで、「見つけて→止めて→弱めて→知らせて→戻して→直して→学ぶ」とストーリーで覚えましょう。

### 具体例: ランサムウェア1件を7段階で追う

| 段階 | この例でやること |
|---|---|
| 検知 | 月曜9時、EDR（第3節で見る端末監視ツール）が「経理PCのファイル名が次々 .locked に変わっている」と警報。担当者が実物を見て本物と判断 |
| 対応 | 経理PCの LAN ケーブルを抜く（電源は切らない）。同じ共有フォルダを使う端末も隔離 |
| 軽減 | 侵入口が添付ファイル付きメールと分かり、同じメールを全社のメールボックスから削除 |
| 報告 | 経営層へ報告。個人データ漏えいの疑いがあるため、法務経由で監督機関へ期限内に通知 |
| 復旧 | PC を初期化してバックアップから戻し、ウイルス対策や設定が元どおりか確認 |
| 修復 | 根本原因（文書ファイルのマクロ＝埋め込みプログラムが自由に動く設定）を直し、マクロを既定で無効化 |
| 教訓 | 振り返り会で「警報から隔離まで40分かかった」点を改善策にまとめ、経営層へ最終報告 |

### 試験でのポイント

- 侵害を発見した直後に「次にすべきこと」は**封じ込め**です。いきなり犯人探しや復旧をしない
- 電源を切ると、メモリ上の情報（実行中のプログラムや通信先など、電源を切ると消えるデータ）が失われます。だから「電源は入れたままネットワークから外す」が基本です
- 対応中も**証拠保全（第23章で見たチェーンオブカストディ＝証拠を誰がいつ扱ったかの記録）**を意識し、フォレンジックの可能性を残す
- 日々のアラート監視は SOC（Security Operations Center、セキュリティ監視の部署）が担い、インシデントと判断したら CSIRT が動きます
- CSIRT は技術者だけでなく**法務・広報・人事・経営**を含む部門横断チームです
- インシデント対応計画は**事前に**策定・訓練しておくもの。インシデント発生後に作るのでは遅い

### 確認問題

**問1.** SOC のアナリストが SIEM のアラートから社内サーバーへの不正アクセスを確認しました。インシデント対応として次に行うべき (NEXT) ものはどれでしょう？

1. 攻撃者を特定するためにログの完全な分析を開始する
2. 被害拡大を防ぐためにサーバーをネットワークから隔離する
3. バックアップからサーバーを復旧して業務を再開する
4. 全社員にパスワード変更を指示する

<details><summary>答えと解説</summary>

正解: **2**

検知 (Detection) の次は対応 (Response) であり、その中心は封じ込め (containment) ＝被害拡大の防止です。ネットワークからの隔離は証拠（メモリ上の情報など）を保全しつつ拡大を止める定石です。ログの完全分析や原因究明は封じ込めの後、復旧 (Recovery) はさらに後の段階です。パスワード変更は原因がクレデンシャル（ID・パスワードなどの認証情報）侵害と判明してから行う軽減策で、初動としては的外れです。「まず止血」が鉄則と覚えましょう。

</details>

**問2.** CISSP のインシデント管理プロセスで、「根本原因を分析し、再発防止策を実装する」段階はどれでしょう？

1. 軽減 (Mitigation)
2. 復旧 (Recovery)
3. 教訓 (Lessons Learned)
4. 修復 (Remediation)

<details><summary>答えと解説</summary>

正解: **4**

修復 (Remediation) は根本原因分析 (root cause analysis) に基づいて再発防止策を実装する段階です。軽減 (Mitigation) はインシデント進行中に被害を抑える活動、復旧 (Recovery) はシステムを通常運用に戻す活動で、どちらも「再発防止」までは踏み込みません。教訓 (Lessons Learned) は対応プロセス全体を振り返って改善点を洗い出す最終段階で、技術的対策の実装そのものではありません。MitigationとRemediationの混同を狙うひっかけが定番です。

</details>

**問3.** イベント (event) とインシデント (incident) の違いの説明として最も適切なものはどれでしょう？

1. インシデントはイベントのうち、セキュリティに悪影響を与えるか、そのおそれがあるもの
2. イベントは人間が起こしたもの、インシデントはシステムが起こしたもの
3. イベントとインシデントは同義であり、組織によって呼び方が違うだけ
4. インシデントは必ず外部の攻撃者によって引き起こされるもの

<details><summary>答えと解説</summary>

正解: **1**

イベントは観測可能なあらゆる出来事（正常なログインも含む）で、そのうち CIA に悪影響（またはそのおそれ）があるものがインシデントです。人間かシステムかという区別ではなく、また同義でもありません。インシデントの原因は外部攻撃に限らず、内部者の不正、操作ミス、自然災害でも起こり得ます。「全インシデントはイベントだが、全イベントがインシデントではない」という包含関係で覚えましょう。

</details>

**問4.** ランサムウェア感染への対応中、CSIRT が規制当局と顧客への侵害通知を行いました。これは7段階のどれに該当するでしょう？

1. 検知 (Detection)
2. 教訓 (Lessons Learned)
3. 報告 (Reporting)
4. 対応 (Response)

<details><summary>答えと解説</summary>

正解: **3**

規制当局・顧客・経営層への通知は報告 (Reporting) 段階の活動です。GDPR の「72時間以内の監督機関への通知」のように法的義務を伴うことも多く、法務・広報と連携して行います。検知は異常に気づく段階、対応は封じ込め中心の初動、教訓は事後の振り返りです。報告は「終わってからまとめて」ではなく、プロセスの途中で法定期限内に行う必要がある点もひっかけとして問われます。

</details>

**問5.** インシデント対応チーム (CSIRT) の構成として最も適切 (BEST) なものはどれでしょう？

1. 迅速な意思決定のため、セキュリティ技術者のみで構成する
2. 法務・広報・人事・経営層の代表を含む部門横断チームとする
3. コストを抑えるため、インシデント発生後に都度メンバーを募る
4. 独立性を保つため、すべて外部ベンダーに任せる

<details><summary>答えと解説</summary>

正解: **2**

インシデント対応には侵害通知（法務）、対外発表（広報）、内部犯対応（人事）、事業判断（経営）が絡むため、部門横断での構成が BEST です。技術者のみでは法的義務や対外対応に穴が開きます。チームと計画は事前に整備し訓練しておくもので、発生後の編成では初動が致命的に遅れます。外部ベンダー（MSSP＝セキュリティ監視を請け負う外部事業者 等）の活用はあり得ますが、意思決定の責任は組織に残るため「すべて任せる」は誤りです。

</details>

**問6.** 感染が疑われるサーバーを封じ込めるとき、電源を切らずにネットワークケーブルを抜いて隔離するのが基本とされる主な理由はどれでしょう？

1. 電源を切るとメモリ上の情報（実行中のプログラムや通信先など）が消え、調査の手がかりを失うため
2. 電源を切るとハードディスクのデータがすべて消去されるため
3. ネットワークから外せばマルウェアが自動的に削除されるため
4. 電源を切る操作には経営層の承認が必要なため

<details><summary>答えと解説</summary>

正解: **1**

メモリの中身は電源を切ると消えます。そこには実行中のマルウェアのプロセスや、攻撃者のサーバーとの通信先など、フォレンジックで重要な手がかりが残っています。ネットワークから外せば被害の拡大（外部への送信や他の端末への感染）は止まり、証拠も残せます。ハードディスクのデータは電源を切っても消えません。隔離してもマルウェアは消えないので、駆除は後の段階で行います。経営層の承認は電源操作の条件ではありません。

</details>

## 2. マルウェアの種類

### 三大分類 — ウイルス・ワーム・トロイの木馬

**マルウェア (malware)** は malicious software（悪意のあるソフトウェア）の略で、害を与える目的で作られたプログラムの総称です。まず「どうやって広がるか」で3つに分けます。

| 種類 | 増殖 | 特徴 |
|---|---|---|
| ウイルス (virus) | する | **宿主ファイル**（実行ファイル .exe や文書ファイルなど、寄生先のファイル）**に寄生**し、ユーザーの実行をきっかけに感染を広げる |
| ワーム (worm) | する | 宿主不要。**ネットワーク経由で自己増殖**し、人の操作なしで広がる |
| トロイの木馬 (Trojan horse) | しない | 便利なソフトに**偽装**してユーザー自身にインストールさせる |

「人手が要るか」「宿主が要るか」で判別する問題が超頻出です。

| シナリオ文の例 | 答え |
|---|---|
| USB で持ち込んだ .exe を開いたら、PC 内の他の .exe にも感染が広がった | ウイルス（宿主あり・人の実行あり） |
| 誰も操作していない夜間に、同じ脆弱性を持つサーバーへ次々に広がった | ワーム |
| 無料の PDF 変換ソフトを入れたら、裏で外部と通信していた | トロイの木馬 |

### その他の重要なマルウェア

- **ランサムウェア (ransomware)**: データを暗号化し身代金を要求。最良の備えは**オフライン（隔離）バックアップ**。身代金の支払いは復旧を保証せず、攻撃者に資金を与えるため原則払わない
- **ルートキット (rootkit)**: OS 深部（カーネル＝OS の中核でハードウェアを直接操る部分 等）に潜み、自身を隠蔽するため**検知が極めて困難**。感染した OS 自身が「異常なし」と嘘の結果を返すので、その OS 上での検査は信用できません。確実な駆除は**クリーンなメディアからの再インストール**
- **ロジックボム (logic bomb)**: 特定の日時や条件（「自分の退職処理」など）で発動。**内部犯**の仕込みが典型
- **ボット (bot)**: 攻撃者の C2 サーバー（Command and Control、命令を出す司令塔のサーバー）から遠隔操作される。多数集めたボットネットが DDoS（第17章で見た大量の通信によるサービス妨害）の発射台になる
- **スパイウェア/アドウェア**: 情報収集や広告表示。キーロガー（キー入力を記録して盗むもの）はスパイウェアの一種
- **ファイルレスマルウェア (fileless)**: ディスクにファイルを残さず**メモリ常駐**し、PowerShell（Windows 標準のコマンド実行ツール）など正規ツールを悪用（LotL: Living off the Land）。シグネチャ型 AV（既知マルウェアの特徴と照合するウイルス対策。次の節で詳しく見ます）では見つけにくい
- **ポリモーフィック型 (polymorphic)**: 感染のたびに自身のコードを変化させ、シグネチャ検知を回避
- **ブートセクタ型 (boot sector)**: ディスクの起動領域（電源を入れた直後に読まれる部分）に感染し、OS より先に動く
- **バックドア (backdoor)**: 正規の認証を通らずに後から入り込むための裏口。トロイの木馬が仕掛けることが多い

### ゼロデイ

**ゼロデイ (zero-day)** は、ベンダーがパッチを提供する前に悪用される脆弱性・攻撃のことです。シグネチャもパッチも存在しないため、多層防御・振る舞い検知・最小権限といった**基本の積み重ね**が唯一の緩和策になります。

> 💡 コツ：試験では「増殖するか」「偽装か寄生か」「条件起動か」といった**一語の違い**で正解が分かれます。シナリオ文の動詞（勝手に広がった→ワーム、インストールした覚えのあるソフトが→トロイ）に注目しましょう。

### 確認問題

**問1.** ユーザーの操作なしにネットワーク経由で自己増殖し、短時間で多数のサーバーに感染を広げるマルウェアはどれでしょう？

1. トロイの木馬
2. ロジックボム
3. ワーム
4. ウイルス

<details><summary>答えと解説</summary>

正解: **3**

宿主ファイルも人の操作も不要で、ネットワーク経由で自己増殖するのはワームの定義そのものです。ウイルスも増殖しますが宿主ファイルへの寄生とユーザーの実行が必要です。トロイの木馬は偽装によってユーザー自身にインストールさせるもので自己増殖しません。ロジックボムは条件が満たされたときに発動する仕掛けで、増殖機能はありません。「人手なしで勝手に広がる＝ワーム」が即答ポイントです。

</details>

**問2.** 便利なフリーソフトを装ってユーザーにインストールさせ、裏でバックドアを開くマルウェアはどれでしょう？

1. トロイの木馬
2. ワーム
3. ポリモーフィック型ウイルス
4. アドウェア

<details><summary>答えと解説</summary>

正解: **1**

正規ソフトに偽装してユーザー自身に導入させるのがトロイの木馬 (Trojan horse) です。自己増殖はしない点がウイルス・ワームとの決定的な違いです。ワームは偽装ではなく自己増殖で広がります。ポリモーフィック型はコードを変化させて検知を逃れるウイルスの性質であり、偽装とは別概念です。アドウェアは広告表示が主目的で、バックドア設置の文脈には合いません。「ユーザーが自分で入れてしまった」という記述がトロイのサインです。

</details>

**問3.** ランサムウェア対策として最も効果的 (MOST effective) なものはどれでしょう？

1. 身代金支払い用の暗号資産をあらかじめ準備しておく
2. シグネチャ型アンチウイルスを全端末に導入する
3. 全ファイルを同一サーバー上の別フォルダに日次コピーする
4. 定期的に取得し、ネットワークから隔離したオフラインバックアップを維持する

<details><summary>答えと解説</summary>

正解: **4**

ランサムウェアはオンラインの共有フォルダやバックアップまで暗号化するため、ネットワークから隔離された（オフライン/イミュータブルな）バックアップが最も効果的な備えです。同一サーバー上のコピーは本体と一緒に暗号化されるので無意味です。シグネチャ型 AV は新種・ポリモーフィック型に弱く十分ではありません。身代金の支払い準備は対策ではなく、支払っても復号の保証はなく攻撃者に資金を与えるため原則として行いません。

</details>

**問4.** 退職予定のシステム管理者が「自分のアカウントが削除されたら全データを消去する」スクリプトを仕込んでいました。これはどれに分類されるでしょう？

1. ルートキット
2. ロジックボム
3. ワーム
4. スパイウェア

<details><summary>答えと解説</summary>

正解: **2**

特定の条件（アカウント削除、特定日時など）が満たされたときに破壊活動を発動する仕掛けはロジックボム (logic bomb) です。内部者、特に権限を持つ管理者が仕込む典型例として頻出します。ルートキットは自身を隠蔽して潜伏するためのもの、ワームは自己増殖型、スパイウェアは情報収集型で、いずれも「条件起動の破壊」という特徴に合いません。対策には職務分掌、コードレビュー、退職プロセスの整備が有効という点もセットで問われます。

</details>

**問5.** ディスク上にファイルを残さず、PowerShell などの正規ツールを悪用してメモリ上で活動するマルウェアの説明として正しいものはどれでしょう？

1. ポリモーフィック型ウイルスと呼ばれ、シグネチャを変化させる
2. ブートセクタウイルスと呼ばれ、OS 起動前に実行される
3. ファイルレスマルウェアと呼ばれ、シグネチャ型検知を回避しやすい
4. ルートキットと呼ばれ、カーネルを改ざんして自身を隠す

<details><summary>答えと解説</summary>

正解: **3**

ディスクに実行ファイルを置かずメモリ常駐し、PowerShell や WMI など正規ツールを悪用する手口（LotL: Living off the Land）はファイルレスマルウェアです。スキャン対象のファイルが存在しないため、シグネチャ型 AV では検知しにくく、EDR のような振る舞い監視が有効です。ポリモーフィック型は「コードを変化させる」、ブートセクタ型は「起動領域に感染」、ルートキットは「深部に潜んで隠蔽」が特徴で、いずれも「ファイルを残さない」「正規ツール悪用」という本問のキーワードと一致しません。

</details>

**問6.** サーバーにルートキットが感染していることが判明しました。駆除の方法として最も確実なものはどれでしょう？

1. 感染したサーバー上でアンチウイルスのフルスキャンを繰り返す
2. 管理者パスワードを変更して様子を見る
3. ルートキットのファイルを手作業で探して削除する
4. クリーンなメディアから OS を再インストールし、検証済みのバックアップからデータを戻す

<details><summary>答えと解説</summary>

正解: **4**

ルートキットは OS の深部に潜み、ファイル一覧やプロセス一覧を改ざんして自分を隠します。感染した OS の上で動くスキャンや手作業の探索は、その「嘘をつく OS」の答えを信じることになるため確実ではありません。パスワード変更は侵入経路の一部を塞ぐだけで、潜伏しているルートキットは残ります。信頼できる状態に戻すには、クリーンなメディアからの再インストールが確実です。戻すデータも感染前のものか確認してから使います。

</details>

## 3. エンドポイント防御（AV・EDR・許可リスト）

### アンチウイルスの検知方式

**エンドポイント (endpoint)** とは、PC・スマートフォン・サーバーなど、ネットワークの末端で人や業務が直接使う機器のことです。その上で動く防御の中心がアンチウイルス（AV）です。

- **シグネチャ型 (signature-based)**: 既知マルウェアのパターンと照合。高速で誤検知が少ない一方、**新種・ゼロデイ・ポリモーフィック型に無力**。定義ファイル（既知マルウェアのパターン集。ベンダーが頻繁に配信）の常時更新が前提
  - 例: あるマルウェアのハッシュ値（第11章で見たファイルの指紋）や特徴的なバイト列を定義ファイルに登録しておき、同じものを見つけたら検知します。コードが1バイトでも変わればハッシュ値は別物になるので、ポリモーフィック型はすり抜けます
- **ヒューリスティック/振る舞い検知 (heuristic / behavior-based)**: 「正常な動き」からの逸脱や不審な挙動で判定。未知の脅威に対応できるが**誤検知 (false positive。正常なものを悪と判定すること) が増える**
  - 例: 「Word が PowerShell を起動し、その PowerShell が外部からファイルを取ってくる」という動きは、ファイルが未知でも怪しいと判定できます。一方、正規の管理スクリプトが似た動きをすると誤検知になります

### EDR・XDR・MDR

| 用語 | 意味 |
|---|---|
| EDR (Endpoint Detection and Response) | 端末の挙動を常時記録し、検知だけでなく**調査・隔離・対応**までを支援する |
| XDR | EDR をネットワーク・クラウド・メールまで広げて相関分析（第24章で見た、複数のログを突き合わせて1つの攻撃として結びつけること）する |
| MDR | EDR/XDR の運用を**外部の専門家に委託**するマネージドサービス |

EDR は「どのプログラムがどのプログラムを起動したか」という親子関係（**プロセスツリー**）を記録します。例えば次の記録が残ります。

```
WINWORD.EXE                          ← 利用者が添付の Word 文書を開いた
 └ powershell.exe -enc JABjAD0A...   ← Word が PowerShell を起動（-enc は命令を Base64 で読めない形にして渡すオプション）
    └ 203.0.113.5:443 へ通信          ← 攻撃者のサーバーから追加の命令を取ってくる
```

ディスクに怪しいファイルが1つもなくても、「Word が PowerShell を起動するのは普通ではない」と判断して端末を隔離できます。だからファイルレス攻撃や LotL の検知には、シグネチャ型 AV より EDR の振る舞い監視が有効です。

### 許可リストと拒否リスト

- **アプリケーション許可リスト (allowlisting)**: 承認済みソフト**だけ**実行を許可。未知のマルウェアも実行できないため**最も強力**。高セキュリティ環境向きだが運用負荷が高い
- **拒否リスト (denylisting/blocklisting)**: 既知の悪いものだけ禁止。運用は楽だが**リストにない脅威は素通し**

「デフォルト拒否 (default deny)」の思想は許可リスト側です。

### その他のエンドポイント対策

- **サンドボックス**: 疑わしいファイルを隔離環境で実行して挙動を観察。検知回避（サンドボックス検知型マルウェア）もある
- **HIDS/HIPS**: 第17章で見た IDS/IPS の、ホスト（個々のサーバーや PC）版。改ざん検知（ファイル完全性監視＝重要ファイルのハッシュ値を定期的に比べ、変わったら警報）も含む
- **リムーバブルメディア統制**: USB の利用制限・自動実行の無効化・持ち込みメディアの検疫
- **ハードニング**: 攻撃対象領域（attack surface。攻撃者が狙える入口の総量）を減らす作業。不要サービスの停止、不要ソフトの削除、セキュアベースライン適用、ホストファイアウォール有効化

> 💡 コツ：「未知の脅威に最も強いのは？」→許可リストや振る舞い検知。「誤検知が増えるのは?」→ヒューリスティック。長所と短所はつねにトレードオフで問われます。

### 確認問題

**問1.** シグネチャ型アンチウイルスの最大の弱点として正しいものはどれでしょう？

1. 定義ファイルにない新種やゼロデイのマルウェアを検知できない
2. 誤検知が多く、正常な業務アプリを頻繁に遮断してしまう
3. 動作が重く、エンドポイントの性能を大きく低下させる
4. 暗号化された通信をすべて復号する必要がある

<details><summary>答えと解説</summary>

正解: **1**

シグネチャ型は既知パターンとの照合なので、定義ファイルに存在しない新種・ゼロデイ・コードを変化させるポリモーフィック型には無力です。誤検知が多いのはむしろヒューリスティック/振る舞い検知の側の弱点で、シグネチャ型は誤検知が少ないのが長所です。性能低下や通信復号は本質的な弱点ではありません。「シグネチャ型=既知には強いが未知に弱い」「振る舞い検知=未知に強いが誤検知が増える」の対比で覚えましょう。

</details>

**問2.** 機密性の高い研究施設の端末で、未知のマルウェアを含むあらゆる未承認プログラムの実行を防ぎたいとき、最も効果的 (BEST) な対策はどれでしょう？

1. 最新の定義ファイルを適用したシグネチャ型アンチウイルス
2. 既知の悪性プログラムを列挙した拒否リスト
3. 承認済みプログラムのみ実行を許可するアプリケーション許可リスト
4. 全端末へのパーソナルファイアウォール導入

<details><summary>答えと解説</summary>

正解: **3**

許可リスト (allowlisting) は「承認したものしか動かない」デフォルト拒否の方式なので、未知のマルウェアであっても承認リストになければ実行できず、最も強力です。シグネチャ型 AV と拒否リストは「既知の悪いもの」しか止められず、未知の脅威は素通しです。パーソナルファイアウォールは通信の制御であり、プログラムの実行自体は止められません。運用負荷が高いという短所とセットで、「高セキュリティ環境なら許可リスト」と覚えましょう。

</details>

**問3.** ファイルレスマルウェアや正規ツールの悪用 (LotL) を検知する手段として最も適切なものはどれでしょう？

1. 定義ファイルベースのフルディスクスキャンを毎晩実行する
2. 端末の挙動を常時記録し異常な振る舞いを検知・対応する EDR を導入する
3. メールゲートウェイで添付ファイルの拡張子を制限する
4. 全端末のディスクを暗号化する

<details><summary>答えと解説</summary>

正解: **2**

ファイルレス攻撃はディスク上にスキャン対象のファイルを残さないため、ディスクスキャンでは捕捉できません。EDR はプロセスの挙動（PowerShell の不審な引数、異常なプロセスツリーなど）を常時記録・分析するため、この種の攻撃の検知と対応に最適です。添付ファイル制限は侵入経路の一部を塞ぐだけで、侵入後のメモリ上の活動には無力です。ディスク暗号化は盗難対策（保存データの機密性）であり、マルウェア検知とは目的が異なります。

</details>

**問4.** 疑わしい添付ファイルを隔離された仮想環境で実行し、その挙動を観察して悪性かどうか判定する技術はどれでしょう？

1. ハニーポット
2. HIDS
3. ジャンプサーバー
4. サンドボックス

<details><summary>答えと解説</summary>

正解: **4**

サンドボックス (sandbox) は隔離環境で検体を実行し、ファイル操作や通信などの挙動から悪性を判定する技術です。ハニーポット（第17章）は攻撃者をおびき寄せて観察するための囮システムで、検体解析の仕組みではありません。HIDS はホスト上の侵入検知であり、隔離実行はしません。ジャンプサーバーは管理者が重要サーバーに入るときに必ず経由させる中継用サーバーです。なお高度なマルウェアには仮想環境を検知して活動を止めるサンドボックス回避機能があることも、ひとこと添えて問われることがあります。

</details>

**問5.** エンドポイントのハードニング (hardening) に該当しない操作はどれでしょう？

1. 不要なサービスとポートを無効化する
2. セキュアベースライン構成を適用する
3. 業務に使わないソフトウェアを削除する
4. すべてのユーザーにローカル管理者権限を付与する

<details><summary>答えと解説</summary>

正解: **4**

ハードニングは攻撃対象領域 (attack surface) を減らす活動で、不要サービスの停止、不要ソフトの削除、ベースライン適用、パッチ適用、ホストファイアウォール有効化などが含まれます。全ユーザーへのローカル管理者権限付与は最小権限の原則に真っ向から反し、マルウェアに管理者権限で動く足場を与えるため、ハードニングの正反対の行為です。「〜に該当しないものはどれか」という否定形の設問は読み飛ばしやすいので、問題文の NOT を見落とさないようにしましょう。

</details>

**問6.** EDR が「WINWORD.EXE が powershell.exe を起動し、その PowerShell が外部のサーバーへ通信した」という記録をもとに警報を出しました。この検知の考え方として最も近いものはどれでしょう？

1. ファイルのハッシュ値が定義ファイルの既知マルウェアと一致した
2. 正規のプログラム同士でも、普段ありえない親子関係や振る舞いを異常と判断した
3. 拒否リストに登録された通信先と一致した
4. ディスク暗号化の設定が無効になっていることを検出した

<details><summary>答えと解説</summary>

正解: **2**

この記録に登場するのは Word と PowerShell という正規のプログラムだけです。シグネチャ（ハッシュ値の一致）では検知できません。EDR はプロセスツリー（どのプログラムがどれを起動したか）と振る舞いを記録しており、「文書ソフトがコマンド実行ツールを起動して外部と通信する」という普段ありえない流れを異常と判断します。これが振る舞い検知で、ファイルレス攻撃や LotL に強い理由です。拒否リストや暗号化設定はこの記録とは関係ありません。

</details>

## 4. パッチと脆弱性管理の運用

### パッチ管理のライフサイクル

パッチは「出たら即、本番へ」ではありません。CISSP では次のサイクルが正解の型です。

1. **評価 (evaluate)**: 自組織への該当有無と深刻度（CVSS＝脆弱性の深刻度を 0.0〜10.0 で採点する共通方式。第21章 等）を確認する
2. **テスト (test)**: **本番相当の検証環境**（本番と同じ OS・アプリ構成を持つテスト用の環境）で、業務アプリへの影響を確認する
3. **承認 (approve)**: 変更管理プロセス（第27章で詳しく見る、変更を申請・審査・記録する手続き）に載せ、承認を得る
4. **展開 (deploy)**: 段階的に配布する（パイロット＝まず一部の端末だけに当てて様子を見る→全体）
5. **検証 (verify)**: 適用されたことを確認する（スキャン・レポート）。未適用端末を追跡する

> 💡 コツ：「ベンダーから重要パッチが出た。まず何をすべきか?」→ **テスト環境で検証**が定番の正解です。「直ちに全端末へ展開」は、業務停止リスクを無視した誤答選択肢として毎回登場します。

### 緊急パッチと例外

- 活発に悪用されている脆弱性では、**適用しないリスクと適用による障害リスクを比較**し、緊急変更プロセス（事後承認を含む）で迅速に適用します。判断の軸はあくまで**リスク**です
- **仮想パッチ (virtual patching)**: IPS（第17章）や WAF（Web アプリへの攻撃を遮断する装置）で攻撃パターンを遮断し、正式パッチ適用までの時間を稼ぐ暫定保護
- **パッチできないシステム**（レガシー、第10章で見た工場・発電所などの制御システム ICS/SCADA、ベンダーサポート終了）には、ネットワーク分離・アクセス制限・監視強化などの**補償コントロール (compensating control。本来の対策が使えないとき、代わりにリスクを下げる対策)** を設けます

### 脆弱性管理との連携

脆弱性管理は「スキャン→優先順位付け（CVSS と資産の重要度）→対処（パッチ/補償/受容）→再スキャンで確認」の継続的なサイクルです。パッチ管理はその中核的な対処手段であり、**構成管理 (configuration management)**（資産とバージョンの正確な台帳）がなければ、どこに何を当てるべきかすら分かりません。

優先順位の付け方を小さな例で見てみます。

| 脆弱性 | CVSS | ある場所 | 優先度 |
|---|---|---|---|
| A: 外部から任意のコードを実行される | 9.8 | インターネットに公開した顧客向け Web サーバー | 最優先 |
| B: A と同じ脆弱性 | 9.8 | ネットワークから切り離した検証用 PC | 中 |
| C: 設定不備で一部の情報が漏れる | 5.3 | 顧客 DB サーバー | 高 |
| D: 画面の表示が崩れる不具合 | 3.1 | 社内掲示板 | 低 |

同じ 9.8 でも、攻撃者から届く場所にあるか、壊れたら事業にどれほど響くかで順番が変わります。

### EOL ソフトウェアのリスク

サポート終了 (EOL/EOS: End of Life / End of Support) のソフトウェアには**今後パッチが提供されない**ため、脆弱性が永久に残ります。原則は更改・移行の計画であり、やむを得ず使い続ける場合はリスク受容の正式な承認と補償コントロールが必要です。

### 確認問題

**問1.** ベンダーから基幹システムに関わる重要なセキュリティパッチがリリースされました。最初に行うべき (FIRST) ものはどれでしょう？

1. 業務影響を避けるため次回の年次メンテナンスまで適用を保留する
2. 全端末に直ちに一斉配布する
3. 脆弱性情報を社外に公表する
4. 検証環境でパッチを評価・テストする

<details><summary>答えと解説</summary>

正解: **4**

パッチ管理の型は「評価→テスト→承認→展開→検証」であり、本番適用の前に検証環境でのテストを行うのが FIRST の正解です。即時一斉配布はパッチ起因の障害で業務を止めるリスクを無視しており、CISSP では典型的な誤答です。年次メンテナンスまでの放置は悪用リスクを不当に受け入れる怠慢（デューケア欠如）です。脆弱性の社外公表は組織の役割ではありません。「急ぐときほどテストを飛ばさない、ただし緊急時はリスク比較で短縮判断」という軸で考えましょう。

</details>

**問2.** サポートが終了した制御システム (ICS) にパッチを適用できません。最も適切な (BEST) 対応はどれでしょう？

1. リスクはないものとして現状のまま運用を続ける
2. ネットワーク分離や監視強化などの補償コントロールを実装する
3. すべての脆弱性スキャンの対象から外して誤検知を減らす
4. 従業員に注意喚起のメールを送る

<details><summary>答えと解説</summary>

正解: **2**

パッチという本来のコントロールが使えない場合は、補償コントロール (compensating control) ＝ネットワーク分離、アクセス制限、IPS による仮想パッチ、監視強化などでリスクを許容水準まで下げるのが BEST です。「リスクなし」と見なすのは評価の放棄であり、スキャン対象から外すのはリスクを見えなくするだけです。注意喚起メールは管理的コントロールとして弱すぎ、技術的な露出を減らせません。「パッチ不可→分離と補償」は ICS/レガシー文脈の定番パターンです。

</details>

**問3.** 仮想パッチ (virtual patching) の説明として正しいものはどれでしょう？

1. 仮想マシンのスナップショットを取得してから適用するパッチのこと
2. ベンダーが提供する正式パッチを自動配布する仕組みのこと
3. IPS や WAF で脆弱性を突く攻撃を遮断し、正式パッチ適用までの暫定保護とすること
4. ソースコードを直接修正して脆弱性を恒久的に除去すること

<details><summary>答えと解説</summary>

正解: **3**

仮想パッチは、システム本体には手を入れず、IPS/WAF などのネットワーク層で当該脆弱性への攻撃パターンを遮断する暫定的な保護策です。テストに時間がかかる場合やパッチが存在しない場合の時間稼ぎとして使います。スナップショットや自動配布の仕組みそのものではなく、ソース修正のような恒久対策でもありません。「暫定 (temporary)」「正式パッチまでのつなぎ」というキーワードが判別ポイントで、恒久対策と混同させるひっかけが出ます。

</details>

**問4.** 脆弱性スキャンで数千件の検出結果が出ました。対処の優先順位を決める基準として最も適切なものはどれでしょう？

1. CVSS などの深刻度と、影響を受ける資産の重要度を組み合わせて判断する
2. 検出された順に上から対処する
3. 修正が最も簡単なものから対処する
4. スキャンベンダーの推奨設定に全面的に従う

<details><summary>答えと解説</summary>

正解: **1**

優先順位付けはリスクベースが原則です。脆弱性の深刻度 (CVSS) に加え、悪用可能性（実際に攻撃が観測されているか）や、その資産が事業にとってどれほど重要か・外部に露出しているかを組み合わせて決めます。検出順や修正の容易さは重要資産の危険な穴を後回しにしかねません。ベンダー推奨は参考情報にすぎず、自組織の資産価値を知らない外部の基準に丸投げするのはリスク管理の放棄です。「深刻度×資産重要度」という掛け算で覚えましょう。

</details>

**問5.** パッチを展開した後、パッチ管理プロセスとして次に行うべきことはどれでしょう？

1. 作業完了としてチケットをクローズする
2. スキャンやレポートで適用状況を検証し、未適用の端末を特定して追跡する
3. 次のパッチの情報収集に移る
4. パッチの配布サーバーを停止する

<details><summary>答えと解説</summary>

正解: **2**

展開 (deploy) の後には検証 (verify) が必須です。配布ジョブの成功率は 100% ではなく、オフライン端末や失敗端末が必ず残るため、脆弱性スキャンや管理ツールのレポートで適用状況を確認し、未適用端末を追跡します。検証せずにクローズすると「対処済みのはずの穴」が残り、インシデントの温床になります。次のパッチへの移行や配布サーバーの停止は検証完了後の話です。「展開して終わりではなく、当たったことを確認するまでがパッチ管理」です。

</details>

**問6.** CVSS 9.8 の同じ脆弱性が、(a) インターネットに公開された顧客向け Web サーバーと (b) ネットワークから切り離された検証用 PC の両方で見つかりました。対処の考え方として最も適切なものはどれでしょう？

1. CVSS が同じなので、どちらから対処しても同じである
2. 検証用 PC は台数が少なく手軽なので、先に対処する
3. 攻撃者から直接届き事業への影響も大きい (a) を優先して対処する
4. 検証用 PC にも脆弱性がある以上、両方直るまで (a) のサービスを止める

<details><summary>答えと解説</summary>

正解: **3**

優先順位は深刻度 (CVSS) だけでなく、資産の重要度と露出の度合いを組み合わせて決めます。(a) はインターネットから誰でも攻撃でき、顧客向けで事業影響も大きいため最優先です。(b) は外部から届かないので、同じ 9.8 でも緊急度は下がります（放置してよいわけではありません）。修正の手軽さで順番を決めると重要な穴が後回しになります。両方直るまでサービスを止めるのは過剰で、まずリスクに応じた順で対処するのが CISSP の考え方です。

</details>
