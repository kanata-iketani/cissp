# 第5章 脅威モデリングとサプライチェーンセキュリティ【D1】

CISSP のドメイン1の仕上げとして、脅威を体系的に洗い出す「脅威モデリング」と、取引先・調達経路に潜むリスクを管理する「サプライチェーンセキュリティ」を学びます。STRIDE の6分類と、SLA・MOU など契約文書の使い分けは本試験の超頻出論点です。「契約前に・文書で・拘束力を持たせて」というマネジメント視点の鉄則を、この章で体に染み込ませましょう。

## 1. 脅威モデリング（STRIDE・PASTA・DREAD）

### 脅威モデリングとは

**脅威モデリング (threat modeling)** は、「このシステムは誰に・どこを・どう攻撃されうるか」を体系的に洗い出す活動です。CISSP では「いつ実施するのが BEST か」が頻出で、答えは**設計段階**です。できあがった後に直すより、設計時にセキュリティを組み込む方が安く確実だからです（プロアクティブなアプローチ）。運用中も新しい脅威に合わせて見直すリアクティブな側面はありますが、出発点は常に設計です。

### 脅威を特定する3つの視点

- **攻撃者視点 (attacker-centric)**: 攻撃者の目標から逆算する
- **資産視点 (asset-centric)**: 価値の高い資産を起点に守るものを決める
- **ソフトウェア視点 (software-centric)**: システム構造やデータフローから弱点を探す

### 代表的な手法

| 手法 | 一言でいうと |
|---|---|
| **STRIDE** | 脅威を6分類するフレームワーク（Microsoft 発） |
| **PASTA** | ビジネス目標の定義から始まる7段階のリスク中心プロセス |
| **DREAD** | 脅威の深刻度を5項目で採点する評価モデル |
| **攻撃ツリー (attack tree)** | 攻撃者の最終目標を根に、手段を枝に分解する図 |

STRIDE の6分類は丸ごと覚えましょう。**S**poofing（なりすまし）、**T**ampering（改ざん）、**R**epudiation（否認）、**I**nformation Disclosure（情報漏えい）、**D**enial of Service（サービス妨害）、**E**levation of Privilege（権限昇格）です。

DREAD は Damage（被害の大きさ）、Reproducibility（再現性）、Exploitability（悪用の容易さ）、Affected Users（影響を受けるユーザー数）、Discoverability（発見のしやすさ）の5項目です。

### 還元分析

システムを信頼境界 (trust boundary)・データフローパス・入力点・特権操作・セキュリティ関連の詳細に**分解**して理解する手順を**還元分析 (reduction analysis / decomposition)** と呼びます。

💡 コツ: 「否認 (repudiation)」は「やったのに『やっていない』と言われること」。ログやデジタル署名による否認防止 (non-repudiation) で対抗します。日本語では直感的でないぶん、シナリオ問題で見抜けるようにしておきましょう。

### 確認問題

**問1.** ECサイトの脅威モデリングで「購入者が注文した後に『自分は注文していない』と主張して支払いを拒む」という脅威が挙がりました。STRIDE ではどれに分類されますか？

1. なりすまし (Spoofing)
2. 改ざん (Tampering)
3. 否認 (Repudiation)
4. 情報漏えい (Information Disclosure)

<details><summary>答えと解説</summary>

正解: **3**

行った行為の事実を後から否定されるのが否認 (Repudiation) です。ログの保全やデジタル署名による否認防止 (non-repudiation) で対抗します。なりすましは「他人のふりをする」、改ざんは「データを不正に書き換える」、情報漏えいは「見せてはいけない相手に情報が渡る」脅威で、いずれも「事実の否定」ではありません。「支払い」という言葉から金銭がらみの別分類を連想させるのがひっかけで、本質は『やっていないと言い張れてしまうこと』です。

</details>

**問2.** 脅威モデリングを実施するタイミングとして最も適切 (BEST) なのはどれですか？

1. システムの設計段階
2. 受入テストの直前
3. 本番リリース後の初回監査のとき
4. セキュリティインシデントが発生した後

<details><summary>答えと解説</summary>

正解: **1**

設計段階で行うのが最も安価で効果的です（プロアクティブなアプローチ）。工程が進むほど発見した問題の修正コストは跳ね上がります。受入テスト直前では設計の欠陥を直す余地がほぼなく、リリース後やインシデント後はリアクティブな対応になってしまいます。CISSP では「できるだけ早い工程（設計時）」が定番の正解パターンです。

</details>

**問3.** 脅威モデリング手法 PASTA の特徴を最もよく表しているのはどれですか？

1. 脅威を6種類に分類するチェックリスト型のフレームワーク
2. ビジネス目標の定義から始まる7段階のリスク中心プロセス
3. 脅威の深刻度を5項目で採点する評価モデル
4. 攻撃者の最終目標を根として手段を枝分かれさせて描く図

<details><summary>答えと解説</summary>

正解: **2**

PASTA (Process for Attack Simulation and Threat Analysis) は、ビジネス目標の定義から始まる7段階のプロセスで、リスク中心 (risk-centric) であることが最大の特徴です。6分類のチェックリストは STRIDE、5項目の採点は DREAD、枝分かれの図は攻撃ツリー (attack tree) の説明です。「7段階」「ビジネス目標起点」というキーワードが出たら PASTA と即答できるようにしましょう。

</details>

**問4.** 脅威の深刻度評価モデル DREAD の構成要素に含まれないものはどれですか？

1. 被害の大きさ (Damage)
2. 再現性 (Reproducibility)
3. 発見のしやすさ (Discoverability)
4. 説明責任 (Accountability)

<details><summary>答えと解説</summary>

正解: **4**

DREAD は Damage・Reproducibility・Exploitability・Affected Users・Discoverability の5項目で、説明責任 (Accountability) は含まれません。頭文字の A は Affected Users（影響を受けるユーザー数）です。A つながりで Accountability を混ぜるのが典型的なひっかけなので、5項目をフルスペルで覚えておくと確実です。

</details>

**問5.** 脅威モデリングの過程で、システムを信頼境界 (trust boundary) やデータフローパス、入力点などの要素に分解して理解する活動を指す用語として最も適切なのはどれですか？

1. 攻撃シミュレーション
2. 還元分析 (reduction analysis)
3. 定量的リスク分析
4. ギャップ分析

<details><summary>答えと解説</summary>

正解: **2**

システムを構成要素に分解 (decomposition) して理解する手順を還元分析 (reduction analysis) と呼びます。信頼境界・データフローパス・入力点・特権操作・セキュリティ関連の詳細の5つに着目するのが定石です。攻撃シミュレーションは実際に攻撃を模擬する活動、定量的リスク分析は金額でリスクを測る手法、ギャップ分析は現状と目標の差を洗い出す手法で、いずれも「分解して理解する」ことそのものではありません。

</details>

## 2. サプライチェーンリスク管理 (SCRM)

### サプライチェーンが狙われる理由

堅牢な企業を正面から攻めるより、セキュリティの弱い取引先・部品・ソフトウェア更新経路を踏み台にする方が簡単です。サプライチェーン全体の強度は「**最も弱い環 (weakest link)**」で決まります。**サプライチェーンリスク管理 (SCRM: Supply Chain Risk Management)** は、製品・サービスが手元に届くまでの全経路のリスクを管理する活動です。

### ハードウェアの真正性

- **偽造品 (counterfeit)**: 正規品を装った粗悪品・改造品です。メーカー認定の正規販売チャネルからの調達と、真正性 (authenticity) の検証で対抗します
- **ハードウェアインプラント**: 製造・輸送の途中で仕込まれる不正なチップや改造です。開封検知パッケージ、調達元の分散、受入時の検査が対策になります

### ソフトウェアの透明性 — SBOM

**SBOM (Software Bill of Materials: ソフトウェア部品表)** は、製品に含まれるライブラリやコンポーネントの一覧です。新しい脆弱性が公表されたとき「自社製品に該当部品が入っているか」を即座に特定でき、対応のスピードが大きく変わります。

### 第三者リスクの評価

ベンダー選定・契約の場面でやるべきことは次のとおりです。

- **最小限のセキュリティ要件 (minimum security requirements)** を契約に明記する。これがベンダー側のセキュリティのベースラインになります
- **第三者評価・オンサイト監査**: ベンダーの自己申告に頼らず、現地評価や独立した監査報告で検証します
- 認証制度の活用: 米国防総省の取引先に求められる **CMMC (Cybersecurity Maturity Model Certification)** のような成熟度認証も、客観的な確認手段になります

💡 コツ: CISSP では「ベンダーのセキュリティを確保する BEST の方法」として、**契約前のデューデリジェンスと契約書への要件明記**が好まれます。「ベンダーを信頼する」「問題が起きてから確認する」といった選択肢は、たいてい誤りです。

### 確認問題

**問1.** ネットワーク機器の調達において、偽造品 (counterfeit) をつかまされるリスクを下げる方法として最も適切 (BEST) なのはどれですか？

1. 最も安価な再販業者から購入してコストを抑える
2. メーカー認定の正規販売チャネルから調達し、真正性を検証する
3. 納品後にペネトレーションテストを実施する
4. 納品物の数量を入念に検品する

<details><summary>答えと解説</summary>

正解: **2**

偽造品対策の基本は、信頼できる正規チャネルからの調達と真正性 (authenticity) の検証です。安価な再販業者はまさに偽造品の混入リスクが高い経路です。ペネトレーションテストは脆弱性を探す手法であり、ハードウェアが本物かどうかの確認には向きません。数量の検品は「数が合っているか」しか確認できず、品物が本物かは分かりません。「テストすればいい」と思わせる選択肢がひっかけです。

</details>

**問2.** SBOM（ソフトウェア部品表）を整備しておく主な利点はどれですか？

1. ソフトウェアのライセンス費用が安くなる
2. 開発のスピードが上がる
3. 脆弱性が公表された際に、影響を受けるコンポーネントを迅速に特定できる
4. ソースコードの品質が自動的に向上する

<details><summary>答えと解説</summary>

正解: **3**

SBOM は製品に含まれるコンポーネントの一覧なので、新しい脆弱性（例: 広く使われるライブラリの欠陥）が公表されたとき「うちの製品に入っているか」を即座に調べられます。これが最大の利点です。ライセンス管理にも役立ちますが費用が安くなるわけではなく、開発速度やコード品質を直接向上させる仕組みでもありません。SBOM は「透明性のためのリスト」であって、品質改善ツールではない点に注意しましょう。

</details>

**問3.** サプライチェーン攻撃の説明として最も適切なのはどれですか？

1. 標的組織のファイアウォールを直接突破する攻撃
2. 標的組織の建物に物理的に侵入してサーバーを盗む攻撃
3. 大量のトラフィックを送り付けてサービスを停止させる攻撃
4. 標的組織が利用する取引先やソフトウェア供給元を踏み台にする攻撃

<details><summary>答えと解説</summary>

正解: **4**

サプライチェーン攻撃は、標的そのものではなく、標的が信頼している取引先・部品・ソフトウェア更新経路など「最も弱い環 (weakest link)」を経由する攻撃です。正面からの突破・物理的侵入・DoS 攻撃はいずれも標的を直接狙う手口であり、サプライチェーン攻撃の本質である「信頼関係の悪用」を含みません。信頼しているルートから入ってくるため検知が難しいのが怖いところです。

</details>

**問4.** 新しいベンダーに自社データの取り扱いを委託します。ベンダーに最小限のセキュリティ要件を守らせる方法として最も効果的 (MOST effective) なのはどれですか？

1. 契約書にセキュリティ要件を明記する
2. 契約締結後にメールで要件を依頼する
3. 実績のあるベンダーなので善意を信頼する
4. インシデントが発生した時点で改善を求める

<details><summary>答えと解説</summary>

正解: **1**

セキュリティ要件は契約書に明記して初めて法的な拘束力を持ち、ベンダーの義務になります。契約後のメール依頼は拘束力が弱く、ベンダーが応じる義務はありません。「信頼する」は管理策ではなく、インシデント後の対応は事後的 (reactive) で手遅れです。CISSP では「契約前に・文書で・拘束力を持たせて」が鉄板の考え方です。

</details>

**問5.** 米国防総省 (DoD) の取引先に求められる、サイバーセキュリティの成熟度を認証する制度はどれですか？

1. ISO 9001
2. PCI DSS
3. CMMC
4. FIPS 140-3

<details><summary>答えと解説</summary>

正解: **3**

CMMC (Cybersecurity Maturity Model Certification) は、米国防総省のサプライチェーンに参加する企業に求められるサイバーセキュリティ成熟度の認証制度です。ISO 9001 は品質マネジメントの規格、PCI DSS はクレジットカード情報を扱う事業者向けの基準、FIPS 140-3 は暗号モジュールの検証基準で、いずれも「国防関連の取引先向け成熟度認証」ではありません。略語のまま用途とセットで覚えましょう。

</details>

## 3. ベンダー管理と契約（SLA・MOU・SOC報告書）

### 契約・合意文書の使い分け（超頻出）

| 文書 | 正式名称 | 一言でいうと |
|---|---|---|
| **SLA** | Service Level Agreement | サービス水準（稼働率など）を**法的拘束力をもって**約束させ、未達ならペナルティ |
| **SLR** | Service Level Requirements | 契約前に顧客側が提示する要求水準 |
| **MOU / MOA** | Memorandum of Understanding / Agreement | 組織間の意向・協力内容の確認。**法的拘束力は弱い、またはない** |
| **NDA** | Non-Disclosure Agreement | 秘密保持。知り得た情報を漏らさない約束 |
| **BPA** | Business Partners Agreement | 共同事業での役割・責任・利益配分を定める |
| **ISA** | Interconnection Security Agreement | システムを相互接続する際の技術的セキュリティ要件 |

💡 コツ: 「数値目標+未達時の罰則」とくれば **SLA**、「拘束力のないお約束」とくれば **MOU** です。

### デューデリジェンスと監査権

契約前には、ベンダーの財務状況・実績・セキュリティ体制を調査する**デューデリジェンス (due diligence)** を行います。さらに契約には**監査権 (right to audit) 条項**を入れ、必要なときに自社または指定した第三者がベンダーの統制を検査できる権利を確保しておきます。

### SOC 報告書の活用

すべてのベンダーに毎回オンサイト監査をするのは現実的でないため、独立監査人による **SOC (System and Organization Controls) 報告書**で確認するのが実務の定番です。

- **SOC 1**: 財務報告に関わる内部統制が対象
- **SOC 2**: セキュリティ・可用性などのトラストサービス基準が対象。**Type I** は「ある時点」での統制の設計を、**Type II** は「一定期間（6〜12か月）」にわたる運用の有効性を評価
- **SOC 3**: SOC 2 の要約版。一般公開用

セキュリティ確認の観点では「**SOC 2 Type II** が最も証拠力が高い」が定番の答えです。

### ベンダーのオフボーディング

契約終了時には、アカウントとアクセス権の失効、貸与物の回収、そして**預けたデータの返却と完全削除の証明**を確認します。クラウド事業者の選定では、データの保管場所 (data location)・データの可搬性・契約終了時のデータの取り扱いを、契約前に確認しておくことが重要です。

### 確認問題

**問1.** クラウドベンダーに月間稼働率 99.9% を約束させ、未達の場合には利用料を減額させたいと考えています。利用すべき文書として最も適切なのはどれですか？

1. MOU
2. SLA
3. NDA
4. BPA

<details><summary>答えと解説</summary>

正解: **2**

数値で示したサービス水準を法的拘束力をもって約束させ、未達時のペナルティ（減額など）まで定めるのは SLA (Service Level Agreement) です。MOU は拘束力の弱い意向確認、NDA は秘密保持、BPA は共同事業の役割分担を定める文書で、サービス水準の保証はできません。「数値目標+罰則」というキーワードが出たら SLA と即答しましょう。

</details>

**問2.** 2つの組織が災害時の相互支援について、法的拘束力を持たせずに協力の意向を文書化したいと考えています。最も適切な文書はどれですか？

1. SLA
2. BPA
3. MOU
4. ISA

<details><summary>答えと解説</summary>

正解: **3**

法的拘束力を持たせない意向・協力内容の確認には MOU (Memorandum of Understanding) が適しています。SLA は拘束力とペナルティを伴うサービス水準の合意、BPA は共同事業の役割と利益配分の取り決め、ISA はシステム相互接続時の技術的セキュリティ要件の合意です。「拘束力なし」「紳士協定的」というニュアンスが MOU の目印です。

</details>

**問3.** クラウドベンダーのセキュリティ統制が、過去1年間にわたって有効に運用されていたことを確認したいと考えています。入手すべき報告書として最も適切 (MOST appropriate) なのはどれですか？

1. SOC 2 Type II 報告書
2. SOC 2 Type I 報告書
3. SOC 1 報告書
4. SOC 3 報告書

<details><summary>答えと解説</summary>

正解: **1**

「一定期間にわたる運用の有効性」を評価するのは SOC 2 Type II です。Type I は特定時点での統制の設計しか見ないため「1年間運用されていたか」は分かりません。SOC 1 は財務報告に関する統制が対象でセキュリティの確認には不向き、SOC 3 は SOC 2 の要約版で詳細な証拠力に欠けます。「時点なら Type I・期間なら Type II」の対比が最大のポイントです。

</details>

**問4.** ベンダーとの契約を交渉中です。将来、ベンダーのセキュリティ統制を自社が直接検証できるようにしておくために、契約に含めるべき条項として最も適切なのはどれですか？

1. 自動更新条項
2. 監査権 (right to audit) 条項
3. 競業避止条項
4. 準拠法条項

<details><summary>答えと解説</summary>

正解: **2**

監査権 (right to audit) 条項を契約に入れておくと、自社または指定した第三者がベンダーの統制を検査する権利を確保できます。契約後に「監査させてほしい」と頼んでも、条項がなければベンダーは拒否できます。自動更新・競業避止・準拠法はいずれも一般的な契約条項ですが、セキュリティ統制の検証とは関係ありません。「契約前に権利を確保しておく」というプロアクティブな発想が CISSP 流です。

</details>

**問5.** クラウドベンダーとの契約を終了することになりました。情報セキュリティの観点で最も重要 (MOST important) な確認事項はどれですか？

1. 最終請求書の金額が正しいこと
2. 後継ベンダーの料金が安いこと
3. 預けたデータが返却され、ベンダー側で完全に削除されたことが証明されること
4. 解約手続きの書類がそろっていること

<details><summary>答えと解説</summary>

正解: **3**

契約終了後もベンダー側にデータが残っていれば、漏えいリスクは残り続けます。データの返却と完全削除の証明（削除証明書など）を得ることが、オフボーディングで最も重要なセキュリティ確認です。請求金額・後継ベンダーの料金・書類の完備は事務的には大切ですが、情報セキュリティの観点ではありません。「問題の軸はどれか（お金の話かセキュリティの話か）」を見極めるのが CISSP の問題の読み方です。

</details>
