# 第27章 セキュリティ運用管理（変更・構成・パッチ・特権）【D7】

セキュリティ運用の「日々の規律」を学ぶ章です。変更管理・構成管理で環境を統制し、職務分掌や特権管理で人の不正と事故を防ぎ、メディアと人的安全の運用で物理面を守ります。派手さはありませんが、CISSP では「プロセスを守っているか」が繰り返し問われる得点源です。

## 1. 変更管理と構成管理

### 障害の多くは「攻撃」ではなく「無断変更」から

本番環境の障害やセキュリティホールの多くは、誰かが勝手に加えた変更が原因です。そこで**変更管理 (change management)** は、すべての変更を決まったプロセスに通すことを求めます。

### 変更管理のプロセス（超頻出）

| 順序 | ステップ | ポイント |
|---|---|---|
| 1 | 申請 (request) | 変更内容と理由を文書で提出 |
| 2 | 影響評価 (impact assessment) | セキュリティ・業務への影響を分析 |
| 3 | 承認 (approval) | **変更諮問委員会 (CAB: Change Advisory Board)** が審査 |
| 4 | テスト | 本番前に検証環境で確認 |
| 5 | 実装 | **ロールバック計画 (rollback plan)** を必ず用意 |
| 6 | 文書化 | 構成情報を最新に更新 |
| 7 | レビュー | 事後に効果と問題を振り返る |

緊急変更 (emergency change) は例外的に「先に実施」が許されますが、**事後に必ず文書化と承認**を行います。「緊急だから記録不要」は誤りです。

### 構成管理 (configuration management)

- **ベースライン (baseline)**: 承認済みの標準構成。ここからの逸脱を検知します
- **CMDB**: 構成情報のデータベース。資産と構成の正を一元管理します
- **ハードニング (hardening)**: 不要なサービス・アカウントの停止、デフォルトパスワードの変更など、攻撃面を減らす初期設定
- **イメージによる標準化**: 検証済みのゴールドイメージから展開し、構成のばらつきを防ぎます
- **自動検証とバージョニング**: ツールでベースラインとの差分を定期チェックし、構成ファイルは版管理します

💡 コツ: 試験で「本番環境に今すぐパッチを当てるべきか」と問われたら、答えはほぼ常に「**変更管理プロセスを通す**」です。技術的に正しい変更でも、無承認なら不正な変更です。

### 確認問題

**問1.** 重大な脆弱性への修正パッチが公開されました。セキュリティ管理者が本番サーバーへ適用する前に、最初に (FIRST) 行うべきことはどれでしょう？

1. 全サーバーへ直ちにパッチを適用する
2. 変更管理プロセスに従って申請し、影響評価とテストを行う
3. ベンダーに追加の割引を交渉する
4. 次回の定期メンテナンスまで対応を保留する

<details><summary>答えと解説</summary>

正解: **2**

緊急性が高くても、本番への変更は変更管理プロセス（申請→影響評価→承認→テスト→実装）を通すのが原則です。直ちに適用すると、パッチ起因の障害で可用性を損なうおそれがあります。保留はリスク放置で、割引交渉は無関係です。ひっかけ: 「重大な脆弱性」という言葉で焦らせて「直ちに適用」を選ばせるのが定番です。緊急変更手続きがある場合でも、事後の文書化と承認は必須です。

</details>

**問2.** 変更諮問委員会 (CAB) の主な役割として最も適切なものはどれでしょう？

1. 提案された変更の影響を審査し、承認または却下する
2. 変更作業を実際に実施する
3. インシデント発生時に調査を指揮する
4. システムのバックアップを毎日取得する

<details><summary>答えと解説</summary>

正解: **1**

CAB (Change Advisory Board) は、変更の業務影響・セキュリティ影響を多部門の視点で審査し、承認可否を判断する組織です。実施するのは担当チームであり、CAB は「審査と承認」に徹します。インシデント調査はインシデント対応チーム、バックアップは運用チームの仕事です。ひっかけ: 「承認する人」と「実施する人」を分けるのは職務分掌の考え方でもあります。

</details>

**問3.** 深夜にシステム停止を引き起こす障害が発生し、復旧には設定変更が必要です。緊急変更 (emergency change) の扱いとして最も適切なものはどれでしょう？

1. 緊急時は変更管理の対象外なので、記録せずに修正してよい
2. CAB の正式承認が得られるまで、復旧作業を数日間待つ
3. まず復旧のための変更を実施し、事後すみやかに文書化と承認手続きを行う
4. 変更を避けるため、システムを停止したまま翌朝の会議を待つ

<details><summary>答えと解説</summary>

正解: **3**

緊急変更は「先に実施、事後に文書化・承認」が正しい扱いです。可用性の回復を優先しつつ、変更管理の統制からは外しません。「記録せずに修正」は無断変更そのもので、後の障害調査や監査を不可能にします。数日間待つ・翌朝まで放置は事業影響を無視しています。ひっかけ: 緊急変更でも文書化は免除されない、という点が問われます。

</details>

**問4.** 新しいサーバーを本番投入する前に行う「ハードニング (hardening)」に含まれる作業として最も適切な組み合わせはどれでしょう？

1. メモリ増設と CPU のアップグレード
2. 全ポートの開放と管理者パスワードの共有
3. ウイルス対策ソフトのライセンス購入のみ
4. 不要なサービスの停止、デフォルトパスワードの変更、不要アカウントの削除

<details><summary>答えと解説</summary>

正解: **4**

ハードニングは攻撃面 (attack surface) を減らす初期設定の総称で、不要サービス停止・デフォルト認証情報の変更・不要アカウント削除・最新パッチ適用などを含みます。ポート全開放やパスワード共有は逆に攻撃面を広げます。ハードウェア増強は性能の話で、ライセンス購入だけでは何も守れません。ひっかけ: 「デフォルト設定のまま使う」ことが脆弱性になる、という視点が問われます。

</details>

**問5.** 構成管理において「ベースライン (baseline)」を維持する主な目的として最も適切なものはどれでしょう？

1. ソフトウェアライセンスの費用を削減するため
2. 承認済みの標準構成からの逸脱を検知し、無断変更や設定ミスを発見するため
3. ユーザーの操作ログをすべて保存するため
4. ネットワーク帯域の使用量を最適化するため

<details><summary>答えと解説</summary>

正解: **2**

ベースラインは「あるべき承認済み構成」の基準点です。現状と比較することで、無断変更・マルウェアによる改変・設定ミスを検知できます。自動ツールで定期的に差分チェックするのが現代的な運用です。ライセンス費用や帯域最適化は構成管理の主目的ではなく、操作ログの保存は監査ログの役割です。ひっかけ: ベースラインは D2 の「セキュリティベースライン(統制の最低ライン)」と文脈で使い分けが必要です。

</details>

## 2. 運用の原則 — 職務分掌・特権管理・不正の発見

### 「人」を統制する運用の原則

セキュリティ運用の土台は、一人の人間に力を集中させないことです。CISSP では次の原則の**使い分け**が繰り返し問われます。

| 原則 | 内容 | ねらい |
|---|---|---|
| 知る必要性 (need to know) | 業務に必要な**情報**だけにアクセス | 情報漏えいの最小化 |
| 最小権限 (least privilege) | 業務に必要な**権限**だけを付与 | 誤操作・悪用の最小化 |
| 職務分掌 (separation of duties) | 重要な業務を複数人に分割 | 一人での不正を防ぐ |
| 二人制御 (two-person control) | 1つの重要操作に**2人の承認・立会い**を要求 | 単独での重大操作を防ぐ |
| ジョブローテーション (job rotation) | 定期的に担当を交代 | 不正の**発見**・属人化の解消 |
| 強制休暇 (mandatory vacation) | 連続休暇を義務付け、代理が業務を実施 | 継続型の不正を**発見** |

💡 コツ: 職務分掌は「分けて**予防**」、ローテーションと強制休暇は「交代して**発見**」です。「長年同じ担当者の不正を見つけるには？」と聞かれたら発見系を選びます。

### 特権アカウントの運用

- 管理者は**通常業務用と管理作業用のアカウントを分離**し、特権アカウントの利用は常に記録・監視します
- 特権操作のログは本人が消せないよう、別システムに転送します
- 特権の付与は期限付き・承認制にし、定期的に棚卸し（アクセスレビュー）します

### 説明責任と SLA

すべての重要操作は「誰が・いつ・何を」したかを一意の ID で追跡できるようにします（説明責任 accountability）。また、運用委託では SLA の達成状況を継続的に測定し、未達時の対応を契約に基づいて行います。

### 確認問題

**問1.** 経理担当者が10年間同じ業務を一人で担当しており、不正送金の疑いがあります。この種の継続的な不正を発見する (detect) のに最も効果的な管理策はどれでしょう？

1. パスワードポリシーの強化
2. ウイルス対策ソフトの導入
3. 強制休暇とジョブローテーション
4. 入退室管理の強化

<details><summary>答えと解説</summary>

正解: **3**

強制休暇 (mandatory vacation) 中は別の担当者が業務を引き継ぐため、継続型の不正（毎日の操作で隠蔽しているもの）が表面化します。ジョブローテーションも同様に発見効果があります。パスワード強化や入退室管理は本人の正規アクセスによる不正には無力で、ウイルス対策は人の不正を検知しません。ひっかけ: 職務分掌は不正の「予防」、休暇・ローテーションは「発見」という機能の違いを問うのが定番です。

</details>

**問2.** 「知る必要性 (need to know)」と「最小権限 (least privilege)」の関係について、最も適切な説明はどれでしょう？

1. need to know は情報へのアクセスを、最小権限はシステム上の権限や操作を必要最小限にする原則である
2. 両者は完全に同じ意味で、言い換えにすぎない
3. need to know は物理セキュリティ、最小権限は論理セキュリティにのみ適用される
4. 最小権限は管理者だけに適用され、一般ユーザーには適用されない

<details><summary>答えと解説</summary>

正解: **1**

need to know は「その情報を業務上知る必要があるか」という情報アクセスの原則、最小権限は「業務に必要な権限（読み取り・変更・削除などの操作能力）だけを与える」という権限付与の原則です。クリアランスがあっても know する必要がなければアクセスさせない、が need to know の肝です。両者は近い概念ですが同一ではなく、物理/論理の区別でも、対象者の区別でもありません。ひっかけ: 「クリアランスを持っていれば何でも見られる」は誤りです。

</details>

**問3.** 核ミサイルの発射や、ルート CA の秘密鍵操作のように、1つの重要な操作そのものに2人以上の関与を必須とする管理策はどれでしょう？

1. ジョブローテーション
2. 二人制御 (two-person control)
3. 職務分掌 (separation of duties)
4. デューデリジェンス

<details><summary>答えと解説</summary>

正解: **2**

二人制御は「1つの操作」を2人が同時に承認・立会いしないと実行できなくする仕組みです（鍵の分割保管など）。職務分掌は「業務の流れ」を複数の役割に分割する考え方で、申請者と承認者を分けるのが典型です。似ていますが、単一操作か業務プロセスかで区別します。ローテーションは担当交代、デューデリジェンスは事前調査で無関係です。ひっかけ: two-person control と separation of duties の判別は頻出です。

</details>

**問4.** システム管理者の特権アカウント運用として最も適切 (BEST) なものはどれでしょう？

1. 利便性のため、管理者権限アカウントでメール確認や Web 閲覧も行う
2. 管理者全員で1つの共有 admin アカウントを使い、パスワードを定期変更する
3. 退職した管理者のアカウントは、後任が来るまでそのまま使い続ける
4. 通常業務用と管理作業用のアカウントを分離し、特権操作をすべて記録・監視する

<details><summary>答えと解説</summary>

正解: **4**

特権アカウントは管理作業専用に分離し、利用を常に記録・監視するのが原則です。特権アカウントで日常業務を行うと、フィッシングやマルウェアの被害がそのまま特権侵害になります。共有アカウントは「誰がやったか」の説明責任 (accountability) を失わせ、退職者アカウントの使い回しは論外です。ひっかけ: 「パスワードを定期変更すれば共有してよい」という選択肢に流れないこと。一意の ID が説明責任の前提です。

</details>

**問5.** 購買システムで「発注を申請する人」「承認する人」「支払いを実行する人」を別の社員に分けました。この管理策の主な目的はどれでしょう？

1. 業務処理のスピードを向上させる
2. 従業員の教育コストを削減する
3. 一人の従業員が単独で不正（架空発注と支払い）を完結できないようにする
4. システムの可用性を高める

<details><summary>答えと解説</summary>

正解: **3**

これは職務分掌 (separation of duties) の典型例です。不正を完結させるには複数人の共謀 (collusion) が必要になり、不正のハードルが大きく上がります。処理は人が増えるぶんむしろ遅くなりがちで、教育コストや可用性とは無関係です。ひっかけ: 職務分掌を破る手段が「共謀」であり、共謀への対策としてローテーションや強制休暇を組み合わせる、という流れまで押さえると応用問題にも対応できます。

</details>

## 3. メディア・物理運用と人的安全

### メディア管理 (media management)

バックアップテープや外付けディスクなどの記録媒体は、データそのものと同じ強度で守ります。

- **ラベリング**: 分類ラベルを貼り、内容と取扱レベルを明示します
- **保管環境**: 施錠された保管庫で温度・湿度・磁気から保護します。**メディアライブラリアン (media librarian)** が貸出・返却を記録します
- **持ち出し統制**: 承認制にし、持ち出し・返却のログを残します
- **輸送時の保護**: オフサイト保管への輸送中は**暗号化**し、信頼できる輸送手段を使います

### 物理運用

入退室記録やカメラ映像は「取るだけ」では意味がなく、**定期的にレビュー**して不審なアクセスを発見します。警備員・ファシリティ部門との連携も運用の一部です。

### 人的安全は常に最優先 (超頻出)

CISSP の鉄則どおり、**人命・安全 (personnel safety) はどんな資産よりも優先**されます。

| 場面 | 対策 |
|---|---|
| 強要 (duress) | 強盗に脅されて開錠する際などに使う**無言の警報コード**（通常と違う解除番号で通報）をあらかじめ決めておく |
| 緊急事態 | 避難経路の整備と訓練、全員の安否確認 (accounting for personnel) |
| 出張 | 貸与専用 PC を持参し帰国後に初期化、公共 Wi-Fi を避け VPN を使用、国境でのデバイス検査を想定し機密データを持ち込まない、旅程を公開しない |

💡 コツ: 「災害時にまず何をするか」「強盗に脅されたらどうするか」と問われたら、**従業員の安全確保**が常に最初です。データ保護を優先する選択肢はひっかけです。

### 確認問題

**問1.** 深夜勤務の警備員が、侵入者に銃で脅されてサーバールームの解錠を強要されています。この状況に備える管理策として最も適切 (BEST) なものはどれでしょう？

1. 解錠を物理的に不可能にする時限ロックのみを導入する
2. 警備員に侵入者へ抵抗するよう訓練する
3. 通常とは異なる解除コードを入力すると無言で通報される duress コードを用意しておく
4. サーバールームの場所を全従業員に秘密にする

<details><summary>答えと解説</summary>

正解: **3**

強要 (duress) への備えは、脅されている本人の安全を守りながら異常を通報できる仕組み、つまり duress コード（無言警報）が最適です。人命が最優先なので、抵抗させる訓練は論外です。時限ロックのみでは侵入者を刺激して警備員を危険にさらすおそれがあり、場所の秘匿は内部勤務者には成立しません。ひっかけ: 「資産を守る」選択肢より「人を守りつつ通報する」選択肢が CISSP の正解です。

</details>

**問2.** バックアップテープをオフサイト保管施設へ定期輸送します。輸送中のデータ保護として最も重要な対策はどれでしょう？

1. テープに会社のロゴを大きく印刷する
2. テープ上のデータを暗号化し、施錠された容器で信頼できる手段により輸送する
3. 輸送回数を増やして1回あたりの本数を減らす
4. テープの代わりに紙に印刷して運ぶ

<details><summary>答えと解説</summary>

正解: **2**

輸送中のメディアは紛失・盗難のリスクが最も高いため、データの暗号化が最重要です。暗号化されていれば、万一紛失しても情報漏えいにはなりにくく、侵害通知義務の扱いも軽減される場合があります。ロゴの印刷はむしろ標的にされ、回数を増やせば露出機会も増えます。紙への印刷は保護になりません。ひっかけ: 「施錠容器だけ」で安心させる選択肢が出たら、暗号化を含む選択肢を優先します。

</details>

**問3.** メディアライブラリアン (media librarian) の役割として最も適切なものはどれでしょう？

1. 記録媒体の貸出・返却・保管を一元管理し、追跡記録を維持する
2. バックアップデータの内容を監査し、改ざんを検出する
3. 媒体に保存するデータの分類レベルを決定する
4. 故障した媒体を修理する

<details><summary>答えと解説</summary>

正解: **1**

メディアライブラリアンは媒体の保管庫を管理し、誰がいつどの媒体を持ち出し・返却したかを記録・追跡する役割です。データの分類を決めるのはデータオーナーの責任であり、内容の監査は監査人、修理はベンダーの領域です。ひっかけ: 「ライブラリアン=分類を決める人」と誤認させる選択肢が定番です。カストディアン系の役割は『管理・記録』、オーナー系の役割は『決定』と覚えましょう。

</details>

**問4.** 機密情報を扱う役員が、サイバー諜報活動が懸念される国へ出張します。情報セキュリティ部門の助言として最も適切 (MOST) なものはどれでしょう？

1. 普段の業務 PC をそのまま持参し、現地ホテルの Wi-Fi で業務を続ける
2. 必要最小限のデータだけを入れた貸与専用 PC を持参し、帰国後に初期化する
3. 出張の予定と訪問先を SNS で共有し、連絡を取りやすくする
4. 機密データを USB メモリにコピーして衣類に隠して運ぶ

<details><summary>答えと解説</summary>

正解: **2**

ハイリスク地域への出張では、通常端末を持ち込まず「使い捨て前提の貸与 PC + 最小限のデータ」が原則です。帰国後は侵害を疑って初期化します。普段の PC と ホテル Wi-Fi は盗聴・改ざんのリスクが高く、旅程の公開は物理的な標的化を招きます。USB の隠匿は国境検査で没収・摘発のリスクがあり、そもそも機密を持ち込まないのが正解です。ひっかけ: 「利便性を保つ」選択肢は出張セキュリティでは誤りです。

</details>

**問5.** データセンターで火災が発生し、消火システムが作動し始めました。運用責任者が最初に (FIRST) 行うべきことはどれでしょう？

1. 重要サーバーのシャットダウン手順を開始する
2. バックアップテープを保管庫から運び出す
3. 全員の避難を指示し、安否を確認する
4. 保険会社へ被害状況を連絡する

<details><summary>答えと解説</summary>

正解: **3**

人命・安全は常に最優先です。火災時はまず避難と安否確認 (accounting for personnel) を行い、設備やデータの保護はその後です。サーバー停止やテープ搬出のために人を危険にさらすことは、CISSP では常に誤答です。保険連絡は復旧フェーズの作業です。ひっかけ: 「ビジネスへの影響を最小化する」もっともらしい選択肢が並びますが、人の安全より優先されるものはありません。

</details>
