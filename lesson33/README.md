# 第33章 模試①（全ドメイン50問・出題比率準拠）

本試験の出題比率に合わせた全50問の模試です。タイマーを用意し、1問あたり70〜90秒・合計60〜75分を目安に、戻らず一気に解き切ってください。間違えた問題はにがて帳に自動記録されるので、模試後に該当章へ戻って復習し、数日空けてから模試②に挑みましょう。

## 1. 模試① Part1: D1+D2（問1〜13）

### 模試① Part1 — セキュリティとリスクマネジメント + 資産のセキュリティ

ここからは本試験と同じ緊張感で解きましょう。範囲は **D1 セキュリティとリスクマネジメント（8問）** と **D2 資産のセキュリティ（5問）** です。ガバナンス、GDPR、リスク計算、BIA、人的セキュリティ、倫理規範、脅威モデリング、サプライチェーン、データの分類・役割・保護・廃棄までを一気に横断します。

### 解き方のルール

- 1問 **70〜90秒** を目安に即断します。本試験の CAT（正答状況に応じて次の問題が変わる出題方式。第1章）は前の問題に戻れないので、ここでも「選んだら次へ」を徹底しましょう
- BEST/MOST/FIRST 問題は「全部正しそうな選択肢から、マネジメント視点で一番を選ぶ」のが鉄則です。技術的に正しくても順序が後のものはワナです
- 迷ったら「人命 > 事業 > 資産」「まずリスク評価」「ポリシーと経営層の支持が先」を思い出してください

💡 コツ：模試は「解けたか」より「ペースを守れたか」「迷い方が正しかったか」の確認です。終わったらにがて帳で間違いの傾向をつかみましょう。

### 確認問題

**問1.** 新任の CISO として、セキュリティプログラムをゼロから立ち上げることになりました。最初に（FIRST）行うべきことはどれですか？

1. 最新のファイアウォールと EDR を導入して技術的な防御を固める
2. 組織のビジネス目標を理解し、経営層の支持を取り付ける
3. 全従業員向けのセキュリティ意識向上トレーニングを開始する
4. ペネトレーションテストを実施して現状の脆弱性を洗い出す

<details><summary>答えと解説</summary>

正解: **2**

セキュリティガバナンス（経営層がセキュリティの方向を決めて監督する仕組み）はトップダウンが大原則で、プログラムはビジネス目標との整合（alignment）と経営層の支持なしには機能しません。技術導入（ファイアウォールや EDR＝端末上の不審な動きを見張る製品）・教育・テスト（ペネトレーションテスト＝許可を得て実際に攻撃してみる検査）はどれも「いつかやること」ですが、方針と支持という土台より先に行うのは順序が逆です。FIRST 問題では「技術より先にガバナンス」を思い出してください。CISO（最高情報セキュリティ責任者）の最初の仕事は、製品選びではなく「会社が何を守りたいか」を経営層と合わせることです。📖 復習: 第2章

</details>

**問2.** EU 居住者の個人データを扱う自社サービスで、データベースへの不正アクセスにより個人データの漏えいが確認されました。GDPR 上、原則としていつまでに・誰に通知する必要がありますか？

1. 24時間以内に、影響を受けるデータ主体全員へ
2. 7日以内に、EU 本部と加盟国すべての警察へ
3. 72時間以内に、監督機関へ
4. 30日以内に、自社の株主へ

<details><summary>答えと解説</summary>

正解: **3**

GDPR（EU の一般データ保護規則。EU 居住者の個人データを扱う組織に、EU 域外でも適用）では個人データ侵害を認識してから原則 **72時間以内に監督機関（supervisory authority。各国のデータ保護当局）へ通知** する義務があります。データ主体（そのデータが指す本人）への連絡は「高リスクの場合に不当な遅滞なく」であり、全員へ24時間以内ではありません。72時間という数字と通知先（監督機関）の組み合わせは超頻出です。📖 復習: 第3章

</details>

**問3.** 資産価値（AV）4,000万円のデータセンターについて、火災が起きた場合の露出係数（EF）は 25%、年間発生率（ARO）は 0.1 と見積もられました。年間損失予測（ALE）はいくらですか？

1. 100万円
2. 400万円
3. 1,000万円
4. 40万円

<details><summary>答えと解説</summary>

正解: **1**

AV は資産の価値、EF は1回の事故で失う割合、ARO は1年に起きる回数の見込み（0.1 は10年に1回）です。SLE = AV × EF = 4,000万円 × 0.25 = 1,000万円。ALE（1年あたりの損失見込み）= SLE × ARO = 1,000万円 × 0.1 = **100万円** です。1,000万円は SLE（1回あたりの損失）であり、ALE と混同させるのが定番のワナです。式を2段階で確実に適用しましょう。📖 復習: 第4章

</details>

**問4.** BIA の結果、ある決済システムの MTD（最大許容停止時間）が 24時間と決まりました。このシステムの RTO の設定として最も適切（MOST appropriate）なのはどれですか？

1. 48時間 — 余裕を持たせて MTD の2倍にする
2. 24時間 — MTD と同じ値にする
3. 16時間 — MTD より短くする
4. RTO は RPO が決まるまで設定できない

<details><summary>答えと解説</summary>

正解: **3**

BIA（業務が止まったときの影響を洗い出す分析）で決まる MTD は「事業が耐えられる停止時間の限界」です。RTO（目標復旧時間）は **MTD より短く** 設定しなければなりません。復旧作業には想定外の遅れがつきものなので、MTD ちょうど（24時間）では間に合わないリスクが残り、MTD 超え（48時間）は論外です。RPO はデータ損失許容量の指標（何時点前までのデータに戻れればよいか）で、RTO の前提条件ではありません。RTO < MTD の不等式は超頻出です。たとえば MTD 24時間に対して RTO 16時間なら、残り8時間を想定外の遅れや業務再開の確認に充てられます。📖 復習: 第6章

</details>

**問5.** 経理担当者の長期にわたる横領を発見するためのコントロールとして、最も効果的（MOST effective）なものはどれですか？

1. 採用時のバックグラウンドチェックを強化する
2. 強制休暇（mandatory vacation）を義務付け、不在中に別の担当者が業務を引き継ぐ
3. 経理システムへのアクセスに多要素認証を導入する
4. 退職時の出口面談を徹底する

<details><summary>答えと解説</summary>

正解: **2**

継続中の不正は、本人が業務を離れたときに別の人が引き継ぐことで発覚します。これが **強制休暇** の狙いで、ジョブローテーションと並ぶ「発見的」人的コントロール（すでに起きた不正を見つけ出す統制。起きる前に防ぐのは「予防的」）です。バックグラウンドチェック（採用前の経歴・犯罪歴などの確認）は採用時の予防であり既に雇用中の不正には効かず、MFA（パスワード＋スマホなど種類の違う要素で本人確認する方式）は本人の正当なアクセスによる横領を防げません。📖 復習: 第6章

</details>

**問6.** ISC2 倫理規範（Code of Ethics）のカノン同士が衝突する状況では、どのように優先順位を判断すべきですか？

1. 依頼主（クライアント）への義務を常に最優先する
2. 専門職の発展への貢献を最優先する
3. カノンの記載順（社会と公共の利益が先頭）に従って優先する
4. その都度 ISC2 に問い合わせて個別に判断を仰ぐ

<details><summary>答えと解説</summary>

正解: **3**

ISC2 の4つのカノン（倫理規範の柱となる4つの条文）は **記載された順番がそのまま優先順位** です。第1カノン「社会・公共の利益・インフラの保護」が依頼主への義務（第3カノン）より上位に来ます。たとえば顧客の違法行為を発見した場合、顧客への忠誠より公共の利益が優先されます。4つは順に ①社会・公共の利益・インフラの保護 ②誠実・公正・責任ある合法的な行動 ③依頼主への勤勉で有能なサービス ④専門職の発展と保護 です。📖 復習: 第6章

</details>

**問7.** 脅威モデリングの演習で「攻撃者がログを書き換えて自分の操作の痕跡を消す」というシナリオが挙がりました。STRIDE ではどの脅威に分類されますか？

1. Spoofing（なりすまし）
2. Repudiation（否認）
3. Information Disclosure（情報漏えい）
4. Elevation of Privilege（権限昇格）

<details><summary>答えと解説</summary>

正解: **2**

STRIDE（脅威を6種類に分ける枠組み。Spoofing なりすまし・Tampering 改ざん・Repudiation 否認・Information Disclosure 情報漏えい・Denial of Service サービス妨害・Elevation of Privilege 権限昇格の頭文字）で考えます。「行為の痕跡を消して『やっていない』と主張できる状態にする」のは **Repudiation（否認）** です。ログの書き換えなので Tampering（改ざん）と迷いますが、目的が「誰がやったか分からなくすること」なら否認に分類するのが STRIDE の考え方です。対策は改ざん防止されたログ（いつ・誰が・何をしたかの記録を、書き換えられない場所に残す）と否認防止（後から「やっていない」と言えなくする性質）（デジタル署名など）です。📖 復習: 第5章

</details>

**問8.** 重要システムの開発を外部ベンダーに委託するにあたり、サプライチェーンリスクを低減する方法として最も効果的（BEST）なのはどれですか？

1. 契約締結前にデューデリジェンスを実施し、セキュリティ要件と監査権を契約に明記する
2. 納品後に受け入れテストで脆弱性スキャンを実施する
3. ベンダーの営業担当者から口頭でセキュリティ体制の説明を受ける
4. 国内の大手ベンダーだけを選定対象にする

<details><summary>答えと解説</summary>

正解: **1**

サプライチェーン管理の鉄則は「**契約前に・文書で・拘束力を持たせて**」です。契約前のデューデリジェンス（相手のセキュリティ体制を事前に調べて確かめること）と、セキュリティ要件・監査権条項（委託先を点検・監査できる権利）の契約への明記が最も効果的です。納品後のテストでは手遅れの問題があり、口頭説明には拘束力がなく、会社の規模はセキュリティの保証になりません。📖 復習: 第5章

</details>

**問9.** 社内の情報分類制度を新設するにあたり、各情報資産の分類レベルを決定する責任を負うべきなのは誰ですか？

1. データカストディアン
2. 情報システム部門の管理者
3. データオーナー
4. 外部監査人

<details><summary>答えと解説</summary>

正解: **3**

分類レベル（例: 極秘・社外秘・公開のような区分）の決定は **データオーナー**（その情報に業務上の責任を持つ経営側の人間）の責務です。カストディアンはオーナーが決めた方針に従って日々の保護作業（バックアップ、アクセス設定）を実施する側で、決定権はありません。「決めるのはオーナー、実行するのはカストディアン」の役割分担は超頻出です。📖 復習: 第7章

</details>

**問10.** EU 顧客向け EC サイトを運営する A 社は、注文データの分析業務をクラウド事業者 B 社のサービス上で行っています。GDPR の用語で、処理の目的と手段を決定している A 社の立場はどれですか？

1. データプロセッサー
2. データコントローラー
3. データカストディアン
4. データサブジェクト

<details><summary>答えと解説</summary>

正解: **2**

処理の **目的と手段を決定する** 組織が **データコントローラー** です。B 社のように委託を受けて処理を実行する側がデータプロセッサー、データ本人がデータサブジェクトです。「決めているのは誰か」で判定するのがコツで、インフラを提供しているかどうかは関係ありません。選択肢のデータカストディアン（第7章で見た、保護作業の実行担当）は GDPR の用語ではありません。📖 復習: 第7章

</details>

**問11.** 機密データを扱う SaaS の利用が増えたため、会社が許可していないクラウドサービスへのデータアップロードを可視化・制御したいと考えています。最も適切（BEST）なソリューションはどれですか？

1. DRM（デジタル著作権管理）
2. ネットワーク IDS
3. フルディスク暗号化
4. CASB（クラウドアクセスセキュリティブローカー）

<details><summary>答えと解説</summary>

正解: **4**

**CASB** はユーザーとクラウドサービスの間に立ち、シャドー IT（会社が許可していないクラウドサービスを社員が勝手に使うこと）の可視化・ポリシー適用・データ保護を行う専用ソリューションです。DRM はファイル単位の利用制御、IDS は攻撃検知（不審な通信を見つけて知らせるだけ）、フルディスク暗号化は端末紛失対策であり、「クラウド利用の可視化と制御」という要件には合いません。要件のキーワードから製品カテゴリを選ばせる問題は頻出です。CASB は通信の経路上に置く方式や、クラウド側の API（外部から操作するための窓口）と連携する方式で、「誰がどのサービスに何を送ったか」を見ます。SaaS（Web メールのようにネット経由で使うアプリ）が増えるほど必要になります。📖 復習: 第8章

</details>

**問12.** リース期間が終了する SSD 搭載のサーバーを返却する前に、保存されていた機密データを読み取れなくしたいと考えています。最も適切（BEST）な方法はどれですか？

1. 消磁装置（degausser）にかける
2. 暗号化消去（crypto-erase）を実施するか、ベンダー指定のサニタイズコマンドを使う
3. OS からすべてのファイルを削除してごみ箱を空にする
4. パーティションを削除してクイックフォーマットする

<details><summary>答えと解説</summary>

正解: **2**

SSD はフラッシュメモリなので磁気を使う **消磁（強い磁気で磁気媒体の記録を壊す方法）は無効** です（これが定番のワナ）。ウェアレベリング（書き込みを全体に散らして寿命を延ばす SSD の仕組み。上書きしたつもりの古いデータが別の場所に残る）により上書きも不完全になり得るため、暗号鍵を破棄してデータを復元不能にする **暗号化消去（crypto-erase）** や、ベンダーのサニタイズ機能が適切です。ファイル削除やフォーマットはデータ残留（remanence）がそのまま残ります。暗号化消去は、SSD が常にデータを暗号化して書いている前提で、その鍵だけを消す方法です。鍵がなければ残ったデータは読めない乱数の塊になります。📖 復習: 第8章

</details>

**問13.** 法務部門から「訴訟に備えて関連データの保持を確実にせよ」という指示（リーガルホールド）が届きました。ちょうどそのデータは保持期間満了で廃棄予定でした。どう対応すべきですか？

1. 保持ポリシーどおり予定どおり廃棄する — ポリシーは社内規程として優先される
2. 廃棄を停止し、対象データをリーガルホールドの解除まで保全する
3. 廃棄はするがバックアップテープだけ残しておく
4. データを匿名化してから廃棄する

<details><summary>答えと解説</summary>

正解: **2**

**リーガルホールド（litigation hold。訴訟に関係しうるデータの削除を止めて保全させる指示）は保持ポリシーに優先** します。訴訟関連データを予定どおりでも廃棄すると証拠隠滅（spoliation）とみなされ、法的制裁を受けるおそれがあります。ホールド対象の特定・廃棄プロセスの停止・保全の記録が正しい対応です。「ポリシーより法的義務が上」という優先関係を押さえましょう。📖 復習: 第8章・第23章

</details>

## 2. 模試① Part2: D3+D4（問14〜26）

### 模試① Part2 — セキュリティアーキテクチャとエンジニアリング + 通信とネットワークのセキュリティ

このパートの範囲は **D3 セキュリティアーキテクチャとエンジニアリング（7問）** と **D4 通信とネットワークのセキュリティ（6問）** です。設計原則、セキュリティモデル、評価基準、暗号、クラウド/仮想化、物理・火災対策、そしてプロトコル・ファイアウォール・ゼロトラスト・無線・攻撃対策まで、技術色の強い13問が続きます。

### 解き方のルール

- 技術問題でも CISSP の答えは「暗記した仕様」より「**どの対策がその要件に合うか**」です。問題文の要件キーワード（機密性か完全性か、検知か防止か）に下線を引くつもりで読みましょう
- 対比表で覚えた知識（AH と ESP、IDS と IPS、消火剤の種類）は選択肢を2つまで絞る武器になります
- ペース維持を忘れずに。1問 70〜90秒です

💡 コツ：計算や細かい仕様で迷ったら仮答えで前進。本試験の CAT では「止まらないこと」自体がスコアを守ります。

### 確認問題

**問1.** データセンターの入室管理システムを設計しています。停電が発生した場合のドアの挙動として最も適切（BEST）なのはどれですか？

1. 非常口は解錠（フェイルオープン）し、人の退避を可能にしたうえで、警備員配置などの補償コントロールを用意する
2. すべてのドアを施錠状態で固定し、資産を保護する
3. すべてのドアを解錠し、復電まで入退室を自由にする
4. ドアの挙動は停電時間の長さに応じてランダムに決める

<details><summary>答えと解説</summary>

正解: **1**

CISSP の鉄則は **人命・安全が常に最優先** です。非常口を施錠固定（フェイルセキュア＝故障時に安全側＝施錠側に倒す設計）にすると停電時に人が閉じ込められるため、避難経路はフェイルオープン（故障時に解錠側に倒す設計）にし、セキュリティ低下は警備員などの補償コントロール（本来の対策が使えないときに代わりに置く対策）で埋めます。「資産保護を理由に人を閉じ込める」選択肢は必ず誤りです。📖 復習: 第9章・第13章

</details>

**問2.** Bell-LaPadula モデルの「*（スター）プロパティ」が禁止しているのはどの操作ですか？

1. 自分より上位の機密レベルの文書を読むこと
2. 自分より下位の機密レベルへ書き込むこと
3. 自分と同じ機密レベルの文書を読むこと
4. 自分より上位の機密レベルへ書き込むこと

<details><summary>答えと解説</summary>

正解: **2**

Bell-LaPadula は機密性のモデルで、単純セキュリティプロパティが「上読み禁止（no read up）」、*プロパティが「**下書き禁止（no write down）**」です。上位の機密情報を下位レベルに書き出すと漏えいになるためです。Biba（完全性）はちょうど逆向き（no read down / no write up）なので、どちらのモデルの話かをまず確認するのがコツです。たとえば「極秘」の人が「社外秘」の文書へ書き込めると、極秘の内容を社外秘側へ写して誰でも読める状態にできてしまいます。これを止めるのが下書き禁止です。📖 復習: 第9章

## 3. 模試① Part3: D5+D6（問27〜38）

### 模試① Part3 — アイデンティティとアクセスの管理 + セキュリティの評価とテスト

このパートの範囲は **D5 アイデンティティとアクセスの管理（7問）** と **D6 セキュリティの評価とテスト（5問）** です。IAAA、認証要素と MFA、バイオメトリクス指標、アクセス制御モデル、Kerberos とフェデレーション、ID ライフサイクル、そして脆弱性評価・ペネトレーションテスト・SOC 報告書・監査まで、「誰に・何を・どう許し、それが機能しているかをどう確かめるか」を横断します。

### 解き方のルール

- D5 の頻出ひっかけは「**同じ要素を2つ使っても MFA ではない**」「**OAuth は認可であって認証ではない**」の2つ。選択肢にそれらしい言葉が出たら要注意です
- D6 では「テストの前にまず **書面の承認（交戦規定）**」「クラウドベンダーの実力を見るなら **SOC 2 Type Ⅱ**」が鉄板パターンです
- 引き続き1問 70〜90秒。迷ったら仮答えで前進しましょう

💡 コツ：「最も信頼できる証拠はどれか」型の問題は、自己申告 < 文書 < 第三者の実地検証、の順で強くなります。

### 確認問題

**問1.** 監査で「操作ログはあるが、全員が共有アカウント admin で作業しているため誰の操作か特定できない」と指摘されました。欠けているセキュリティの性質はどれですか？

1. 説明責任（accountability）
2. 可用性（availability）
3. 機密性（confidentiality）
4. 認可（authorization）

<details><summary>答えと解説</summary>

正解: **1**

第18章の IAAA（識別・認証・認可・説明責任）の最後の段です。**説明責任（accountability）は「一意の識別 + 認証 + 監査ログ」がそろって初めて成立** します。共有アカウントではログがあっても個人に行為を紐づけられず、説明責任が崩れます。認可（何を許すか）の問題ではなく「誰がやったか」の問題である点がポイントです。たとえばログに「10:02 admin が顧客テーブルを削除」と残っていても、admin を5人で共有していれば誰の操作かは分かりません。📖 復習: 第18章

</details>

**問2.** 「パスワードに加えて4桁の暗証番号（PIN）の入力を必須にしたので、当社は多要素認証を導入済みです」という主張の問題点はどれですか？

1. PIN は4桁では短すぎるため、6桁にすれば多要素認証になる
2. パスワードと PIN はどちらも知識要素（something you know)であり、要素が1種類しかない
3. 多要素認証にはバイオメトリクスが必須である
4. 問題はない — 2つの認証手段があるので多要素認証である

<details><summary>答えと解説</summary>

正解: **2**

MFA は **異なる種類の要素**（知識＝パスワード、所持＝スマホや IC カード、生体＝指紋や顔）を組み合わせることが条件です。パスワードも PIN も知識要素なので、2つ使っても単一要素認証（SFA）のままです。これは CISSP 最頻出のひっかけの1つ。バイオメトリクスは MFA の選択肢の1つであって必須ではありません。📖 復習: 第18章

</details>

**問3.** データセンターの入室に使うバイオメトリクス装置を選定しています。「権限のない人を誤って通してしまうこと」を最小化したい場合、注目すべき指標はどれですか？

1. FRR（本人拒否率）を最小化する
2. CER（交差エラー率）を最大化する
3. FAR（他人受入率）を最小化する
4. 登録時間（enrollment time）を最小化する

<details><summary>答えと解説</summary>

正解: **3**

「権限のない人を通す」エラーは **FAR（False Acceptance Rate、Type 2 エラー）** です。高セキュリティ施設では FAR の最小化を優先し、利便性が犠牲になる（FRR が上がる）ことを受け入れます。CER（FAR と FRR が等しくなる点の値）は装置の総合精度比較の指標で「低いほど高精度」なので最大化は逆です。数値例: 他人が1,000回試して2回通れば FAR 0.2%、本人が1,000回試して30回はじかれれば FRR 3% です。判定のしきい値を厳しくすると FAR は下がり、FRR は上がります。📖 復習: 第18章

</details>

**問4.** 数百人規模の会社で、人事異動のたびにアクセス権の設定ミスが多発しています。部署と職務に応じて権限を自動的に付け替えられるようにしたい場合、最も適切（BEST）なアクセス制御モデルはどれですか？

1. DAC — 各リソースのオーナーが異動のたびに権限を付け替える
2. MAC — 全リソースにセキュリティラベルを付与する
3. ルールベース — 全員一律のルールで制御する
4. RBAC — 職務に対応するロールに権限をまとめ、ユーザーのロールを異動時に変更する

<details><summary>答えと解説</summary>

正解: **4**

職務（ロール）単位で権限を束ね、異動時はロールの付け替えだけで済む **RBAC**（役割に権限を付け、人には役割を割り当てる方式）がこの要件に最適です。DAC（リソースのオーナーが自分の裁量で権限を配る方式）はオーナー任せで統制がきかず設定ミスがむしろ増え、MAC（システムがラベルとクリアランスで強制する方式）は軍用レベルの厳格さで商用の人事異動対応には過剰、ルールベースは個人の職務差を表現できません。「異動が多い組織 → RBAC」は定番パターンです。例: 営業から経理へ異動した人は、「営業」ロールを外して「経理」ロールを付けるだけで権限が丸ごと入れ替わります。📖 復習: 第19章

</details>

**問5.** Kerberos 認証で、チケットにタイムスタンプが含まれ、クライアントと KDC の時刻同期が必須とされている主な理由はどれですか？

1. 古いチケットの再利用（リプレイ攻撃）を防ぐため
2. ログの時刻を正確にそろえて監査を容易にするため
3. パスワードの有効期限を強制するため
4. ネットワーク遅延を測定して最適な KDC を選ぶため

<details><summary>答えと解説</summary>

正解: **1**

Kerberos（チケットで認証する仕組み。KDC＝チケットを発行する鍵配布センター）では、ログイン時に KDC から TGT（チケットをもらうためのチケット）を受け取り、それを見せて各サービス用のチケットをもらいます。チケットは有効期間が短く設定され、タイムスタンプ検証により **盗んだチケットを後から再利用するリプレイ攻撃** を防ぎます。時刻が大きくずれると正当なチケットも拒否されるため時刻同期（通常5分以内）が必須です。監査やパスワード期限は Kerberos の時刻同期の主目的ではありません。📖 復習: 第20章

</details>

**問6.** 自社 Web サービスに「Google アカウントでログイン」機能を追加します。ユーザーの「認証」を外部 IdP に委ねるために使うべきプロトコルはどれですか？

1. OAuth 2.0 単体 — 認可フレームワークがそのまま認証にも使える
2. OIDC（OpenID Connect）— OAuth 2.0 の上に認証レイヤーを追加したもの
3. RADIUS — ネットワーク機器の AAA プロトコル
4. SCIM — ユーザー情報のプロビジョニング規格

<details><summary>答えと解説</summary>

正解: **2**

**OAuth 2.0 は「認可（リソースへのアクセス許可の委譲）」の仕組みであり、単体では認証プロトコルではありません** — これが超頻出のひっかけです。「誰であるか」を確認するには OAuth の上に ID トークン（JWT＝署名付きの JSON 形式のデータで、「この人は誰で、いつ認証したか」を書いた証明）による認証を載せた **OIDC** を使います。RADIUS はネットワークアクセスの AAA（認証・認可・アカウンティング＝利用記録）、SCIM はアカウントの自動プロビジョニング（アカウントの作成・変更・削除）規格です。IdP（ID 提供者。ここでは Google）がログインを確かめ、その結果を自社サービスへ渡す形です。OAuth のアクセストークンは「何をしてよいか」の許可証で、「誰か」は書かれていません。📖 復習: 第20章

</details>

**問7.** 退職が決まった従業員のアカウントの扱いとして、最初に（FIRST）行うべき操作はどれですか？

1. アカウントを直ちに削除し、痕跡を残さない
2. パスワードを本人に変更してもらう
3. アカウントを無効化し、データとログを保全したうえで所定の手順で処理する
4. 退職後30日間は様子を見てから対応を決める

<details><summary>答えと解説</summary>

正解: **3**

即時の **無効化（disable）** が正解です。削除してしまうと本人のファイル・メール・監査証跡（後から操作をたどるための記録）へのアクセスが失われ、調査や引き継ぎができなくなります（「削除より無効化が先」は頻出）。本人にパスワード変更させるのは制御になっておらず、30日放置は論外です。無効化はログインできなくするだけで、アカウントとその中のデータは残ります。📖 復習: 第20章

</details>

**問8.** 外部業者にペネトレーションテストを依頼することになりました。テスト開始前に最初に（FIRST)整えるべきものはどれですか？

1. テスト対象システムの完全バックアップ
2. テスト結果を公開するためのプレスリリース
3. テスターへの社内システムの管理者権限の付与
4. テスト範囲・時間帯・手法・緊急連絡先を定めた交戦規定（RoE）と書面による承認

<details><summary>答えと解説</summary>

正解: **4**

ペネトレーションテストは実際に攻撃を行うため、**書面による権限者の承認と交戦規定（rules of engagement）** なしに始めると法的問題と事業被害を招きます。バックアップは有用ですが承認より先ではなく、管理者権限の付与はテスト種別（ブラック/グレー/ホワイトボックス＝テスターに渡す内部情報が 無し/一部/全部）の設計次第、結果は公開するものではありません。📖 復習: 第21章

</details>

**問9.** 脆弱性スキャンの結果、数百件の検出項目が報告されました。修正の優先順位付けの方法として最も適切（BEST）なのはどれですか？

1. CVSS スコアに加え、資産の重要度と悪用可能性を考慮してトリアージする
2. 検出された順に上から修正する
3. すべての項目を同時に修正するまでシステムを停止する
4. 誤検知の可能性があるため、監査で指摘されるまで保留する

<details><summary>答えと解説</summary>

正解: **1**

優先順位付けは **CVSS スコア（脆弱性の深刻度を 0〜10 で表す共通の採点方式） × 資産価値 × 実際の悪用可能性（エクスプロイト＝脆弱性を突く攻撃コードの存在、外部公開か）** で行うのが原則です。CVSS だけでも機械的で、検出順はさらに無意味です。全停止は可用性を自ら破壊し、放置はデューケア（知ったリスクに合理的な対策を取る義務）違反になります。「リスクベースで優先順位」が D6 の基本思想です。トリアージは、重要度で処理する順番を決めることです。📖 復習: 第21章

</details>

**問10.** クラウドサービス事業者のセキュリティ統制が「一定期間にわたって有効に運用されていたこと」を確認したい場合、入手すべき報告書はどれですか？

1. SOC 1 Type Ⅰ
2. SOC 2 Type Ⅱ
3. SOC 2 Type Ⅰ
4. SOC 3

<details><summary>答えと解説</summary>

正解: **2**

SOC 報告書は、外部の監査人が委託先の内部統制を評価した報告書です。セキュリティ等の Trust サービス基準（セキュリティ・可用性・処理のインテグリティ・機密性・プライバシーの5つ）を扱うのは **SOC 2**、そして「ある時点の設計」を見るのが Type Ⅰ、「**期間を通じた運用の有効性**」を検証するのが **Type Ⅱ** です。SOC 1 は財務報告に関わる統制、SOC 3 は一般公開用の要約で詳細な評価には使えません。「期間 + 運用有効性 = Type Ⅱ」で即断できます。📖 復習: 第22章

</details>

**問11.** EC サイトの注文フローが正常に動作しているかを、実際の顧客に影響を与えずに24時間自動で確認したいと考えています。最も適切な手法はどれですか？

1. RUM（リアルユーザーモニタリング）
2. ファズテスティング
3. 合成トランザクション（synthetic transaction）
4. 静的コード解析（SAST）

<details><summary>答えと解説</summary>

正解: **3**

**合成トランザクション** は擬似ユーザーの操作スクリプトを定期実行し、実ユーザーに依存せず正常系の動作を監視する手法です。RUM は実際の利用者のトラフィックを観測するため「顧客に依存せず24時間」という要件に合いません。ファジングは異常入力（壊れた値やランダムな値）を大量に送る脆弱性探し、SAST はコードの静的解析で、稼働監視ではありません。例: 5分ごとにスクリプトが「ログイン→商品をカートへ→決済画面の手前まで」を自動で操作し、失敗や遅延があれば通知します。📖 復習: 第22章

</details>

**問12.** 内部監査チームがセキュリティ運用部門の統制を監査することになりました。監査の信頼性を確保するうえで最も重要（MOST important）なのはどれですか？

1. 監査結果を被監査部門の管理職だけに報告すること
2. 監査人がセキュリティ運用部門の元メンバーで業務に精通していること
3. 監査期間をできるだけ短くして業務影響を抑えること
4. 監査人が被監査部門から独立しており、利害関係がないこと

<details><summary>答えと解説</summary>

正解: **4**

監査の価値は **独立性と客観性** に依存します。自分（or 利害関係者）の仕事を自分で監査すると評価が歪むため、報告ラインも被監査部門から独立させます（経営層や監査委員会＝取締役会に置かれる監査担当の委員会へ報告）。業務精通は有益でも独立性より優先されず、期間短縮や報告先の限定は信頼性の要件ではありません。📖 復習: 第22章

</details>

## 4. 模試① Part4: D7+D8（問39〜50）

### 模試① Part4 — セキュリティの運用 + ソフトウェア開発セキュリティ

最終パートの範囲は **D7 セキュリティの運用（7問）** と **D8 ソフトウェア開発セキュリティ（5問）** です。証拠の扱い、フォレンジック、インシデント対応の7段階、マルウェア、バックアップと DR、そして SDLC・開発手法・OWASP・セキュリティテスト・ソフトウェア調達までを締めくくります。

### 解き方のルール

- D7 のシナリオ問題は「**今どの段階か**」を見極めるのがコツです。検知→対応（封じ込め）→軽減→報告→復旧→修復→教訓、の順序を頭に置いて読みましょう
- 証拠が絡む問題では「オリジナルに触らない」「チェーンオブカストディ」「揮発性の高い順に収集」が鉄板です
- D8 は「セキュリティは後付けでなく **早い段階から**（シフトレフト）」「**開発者は本番に触れない**」が頻出の軸です

💡 コツ：最後まで同じペースを守れたかも採点対象だと思って解きましょう。終わったら、にがて帳の間違いを該当章に戻って潰してから模試②へ。

### 確認問題

**問1.** 不正アクセスが疑われる稼働中のサーバーから証拠を収集します。揮発性（volatility）の考え方に基づき、最初に（FIRST）保全すべきものはどれですか？

1. メモリ（RAM）の内容と実行中プロセスの状態
2. ハードディスク上のログファイル
3. 外付けバックアップテープ
4. プリンタに残った印刷物

<details><summary>答えと解説</summary>

正解: **1**

証拠収集は **揮発性（電源断などで消えやすい度合い）の高い順**（レジスタ/キャッシュ＝CPU 内部の一時記憶 → メモリ・プロセス・ネットワーク状態 → ディスク → バックアップ → 印刷物）で行います。メモリの内容は電源断で失われるため最優先で保全します。ディスクやテープ、紙は後からでも採取できます。「電源を切ると消えるものから」と覚えましょう。📖 復習: 第23章

</details>

**問2.** 押収したディスクをフォレンジック分析する際の手順として正しいものはどれですか？

1. オリジナルのディスクを直接マウントして素早く調査する
2. ライトブロッカーを介してビット単位のイメージを作成し、ハッシュ値で同一性を証明したうえでコピーを分析する
3. オリジナルのディスクをデフラグしてから分析し、読み取りを高速化する
4. 必要なファイルだけをコピーして、残りは削除して保管容量を節約する

<details><summary>答えと解説</summary>

正解: **2**

大原則は **オリジナルに手を加えない** こと。ライトブロッカー（書き込み防止装置）を介してビット単位の完全イメージ（削除済み領域や空き領域も含め、ディスク全体を1ビットずつ写したもの）を取り、取得前後のハッシュ値（1ビットでも違えば値がまったく変わる要約値。SHA-256 など）の一致で「改変していない」ことを証明し、分析はコピーに対して行います。直接マウント（OS にディスクをつないで読み書きできる状態にすること）やデフラグ（ファイルの断片を並べ直す整理）はタイムスタンプ等を書き換えて証拠能力（admissibility）を失わせます。📖 復習: 第23章

</details>

**問3.** ランサムウェアの感染が1台の端末で検知されました。CISSP のインシデント管理プロセスにおいて、検知（Detection）の次に行うべき「対応（Response）」の中心となる活動はどれですか？

1. 教訓をまとめて再発防止計画を作成する
2. 規制当局と顧客への正式な通知文書を発送する
3. 対象端末をネットワークから隔離するなど、被害拡大を防ぐ封じ込めを行う
4. バックアップからすべてのデータを復元して業務を再開する

<details><summary>答えと解説</summary>

正解: **3**

7段階（検知→対応→軽減→報告→復旧→修復→教訓）の「対応」では CSIRT（インシデント対応の専門チーム）を招集し、**封じ込め（隔離）による被害拡大防止** が最優先です。このとき証拠保全も意識します（電源を切るとメモリ上の証拠が消えるため、電源断より隔離が推奨されます）。報告・復旧・教訓はそれぞれ後の段階であり、順序を入れ替えさせるのがこの型の定番ワナです。ランサムウェアはファイルを暗号化して身代金を要求するマルウェアで、ネットワーク経由で他の端末や共有フォルダへ広がります。📖 復習: 第25章

</details>

**問4.** ランサムウェア対策として最も効果的（BEST）なバックアップ戦略はどれですか？

1. 本番サーバーと同じネットワーク上の NAS に毎時レプリケーションする
2. 各従業員が重要ファイルを自分の USB メモリに随時コピーする
3. RAID 1 のミラーリングで全ディスクを二重化する
4. オフラインまたはイミュータブル（変更不可）なバックアップを含む 3-2-1 構成とし、復元テストを定期実施する

<details><summary>答えと解説</summary>

正解: **4**

ランサムウェアはオンラインの共有やレプリカも暗号化するため、**攻撃者が触れないオフライン/イミュータブルのコピー** が決め手です（3-2-1: 3コピー・2種類の媒体・1つはオフサイト）。復元テストをして初めてバックアップは有効と言えます。RAID 1（2台のディスクに同じ内容を同時に書く方式）は障害対策であってバックアップではなく（暗号化された状態もそのままミラーされる）、USB 運用は統制不能です。NAS（ネットワーク経由で使う共有ディスク装置）へのレプリケーション（データを別の場所へ自動で複製し続けること）も同じ理由で、暗号化されたファイルがそのまま複製されてしまいます。📖 復習: 第25章・第26章

</details>

**問5.** SOC チームが「検知アラートへの定型的な初動対応（IP の遮断、チケット起票、関係者通知）をプレイブックで自動化したい」と考えています。導入すべきソリューションはどれですか？

1. SOAR
2. UEBA
3. NetFlow コレクタ
4. ハニーポット

<details><summary>答えと解説</summary>

正解: **1**

**SOAR（Security Orchestration, Automation and Response）** はプレイブック（アラートの種類ごとの対応手順書）に沿って対応作業を自動化・半自動化し、アラート疲れを軽減します。UEBA は振る舞いの異常検知（ユーザーや機器の普段の動きからの外れを見つける、検知側）、NetFlow は通信の可視化、ハニーポット（おとりのサーバー）は攻撃者の誘引・観察で、いずれも「対応の自動化」ではありません。SIEM（各所のログを集めて突き合わせ＝相関分析し、攻撃の兆候を検知する製品）と SOAR（対応自動化）の役割分担も整理しておきましょう。ここでの SOC はセキュリティ監視センターのことで、第22章の SOC 報告書とは別物です。チケット起票は、対応案件を管理システムに登録することです。📖 復習: 第24章

</details>

**問6.** 毎週日曜にフルバックアップ、月〜土曜に増分（incremental）バックアップを取得しています。木曜の朝にディスク障害が発生した場合、復元に必要なバックアップはどれですか？

1. 日曜のフルバックアップだけ
2. 日曜のフルバックアップと、月・火・水曜のすべての増分バックアップ
3. 日曜のフルバックアップと水曜の増分バックアップだけ
4. 水曜の増分バックアップだけ

<details><summary>答えと解説</summary>

正解: **2**

**増分バックアップは「前回のバックアップ以降」の変更だけ** を保存するため、復元にはフル + 障害直前までの全増分が必要です（この例では日+月+火+水の4本）。差分（differential）なら「前回フル以降」の累積なのでフル + 最新の差分の2本で済みます。取得が速いのは増分、復元が速いのは差分、というトレードオフは超頻出です。日ごとに見ると、月曜の増分＝月曜1日分の変更、火曜の増分＝火曜1日分…なので、木曜朝には「日曜フル → 月 → 火 → 水」の順に重ねて戻します。📖 復習: 第26章

</details>

**問7.** DR 計画のテスト手法のうち、本番システムを実際に停止して代替サイトへ切り替える「フルインタラプションテスト」を実施する際に、最も重要（MOST important）な前提条件はどれですか？

1. テスト費用を最小化するため、業務のピーク時間帯に実施すること
2. 現場の判断だけで抜き打ち実施し、実戦に近い状況を作ること
3. 事業停止リスクを伴うため、経営層の承認と綿密な計画・ロールバック手順を整えること
4. 読み合わせテストを省略して時間を節約すること

<details><summary>答えと解説</summary>

正解: **3**

フルインタラプションは最も忠実なテストですが **本物の事業停止を引き起こすリスク** があるため、経営層の承認・入念な計画・失敗時のロールバック（元の状態へ戻すこと）手順が前提です。段階的に読み合わせ（手順書を各自で確認）→ウォークスルー（集まって机上で手順をたどる）→シミュレーション（想定シナリオで演習）→パラレル（本番を止めずに代替サイトを実際に動かす）と成熟させてから実施します。ピーク時間帯や抜き打ちは事業へのリスクを不必要に高めるだけです。DR（災害復旧）計画は、システムを代替サイトなどで立ち上げ直すための計画です。📖 復習: 第26章

</details>

**問8.** 開発プロジェクトでセキュリティ上の欠陥を修正するコストを最小にするには、セキュリティ活動をいつ始めるべきですか？

1. リリース直前の受け入れテストの段階
2. コーディング完了後のコードレビューの段階
3. 本番稼働後、実際に脆弱性が悪用されてから
4. 要件定義・設計の段階から（シフトレフト）

<details><summary>答えと解説</summary>

正解: **4**

欠陥の修正コストは発見が遅いほど指数的に増えます。**要件・設計段階からセキュリティ要件定義や脅威モデリング（設計を見て、どこがどう攻撃されうるかを洗い出す作業）を行う（シフトレフト）** のが最も安価で効果的です。テストやレビュー段階の対策も必要ですが「最小コスト」の答えとしては遅く、稼働後対応は最悪のケースです。例: 設計段階なら設計書を直すだけで済みますが、リリース後だと改修・再テスト・再配布・顧客対応まで必要になります。📖 復習: 第28章

</details>

**問9.** 監査で「開発者が本番環境に自由にアクセスし、直接コードを修正できる」状態が指摘されました。これが問題とされる主な理由はどれですか？

1. 職務分掌が崩れ、テストや承認を経ない無統制な変更・不正の機会が生まれるため
2. 開発者の作業効率が落ちるため
3. 本番環境のライセンス費用が増えるため
4. 開発者の雇用契約に違反するため

<details><summary>答えと解説</summary>

正解: **1**

開発と本番運用の分離は **職務分掌（separation of duties）** の典型です。開発者が本番を直接変更できると、変更管理（変更を申請・テスト・承認・記録してから本番に入れる手順）をバイパスした無統制な変更や不正・隠蔽が可能になります。対策は環境分離・デプロイ（本番環境へプログラムを配置して動かすこと）権限の分離・変更管理プロセスの強制です。📖 復習: 第27章・第28章

</details>

**問10.** Web アプリケーションの入力フォームに「' OR 1=1 --」のような文字列を入力され、データベースの全レコードが取得される攻撃を受けました。最も効果的（BEST）な対策はどれですか？

1. JavaScript によるクライアント側の入力チェックを強化する
2. パラメータ化クエリ（プリペアドステートメント）とサーバー側の入力検証を実装する
3. データベースのテーブル名を推測されにくい名前に変更する
4. エラーメッセージを日本語化して攻撃者に読めなくする

<details><summary>答えと解説</summary>

正解: **2**

SQL インジェクション（入力値に SQL の一部を混ぜて、意図しない命令を実行させる攻撃）の根本対策は **パラメータ化クエリ** でデータとコードを分離し、サーバー側で入力検証することです。クライアント側チェックは攻撃者が容易にバイパスできるため防御になりません（超頻出ひっかけ）。テーブル名変更やメッセージの言語変更は「隠すだけ」で対策ではありません。例: アプリが `SELECT * FROM users WHERE name = '入力値'` のように文字列をつなげて SQL を作っていると、入力 `' OR 1=1 --` で `WHERE name = '' OR 1=1 --'` になります。`1=1` は常に真なので全行が条件に合い、`--` 以降はコメント扱いで無視されます。パラメータ化クエリでは入力を「値」としてだけ渡すので、この文字列もただの名前として扱われ、SQL の構文になりません。📖 復習: 第29章

</details>

**問11.** CI/CD パイプラインに「実行中のアプリケーションに外部からリクエストを送り、実行時の脆弱性を検出するテスト」を追加したいと考えています。該当する手法はどれですか？

1. SAST — ソースコードを静的に解析する
2. SCA — 依存ライブラリの既知脆弱性を照合する
3. DAST — 稼働中のアプリケーションを外部から動的にテストする
4. コードレビュー — 人間がソースを読んで確認する

<details><summary>答えと解説</summary>

正解: **3**

**DAST（動的アプリケーションセキュリティテスト）** は実行中のアプリに疑似攻撃リクエストを送り、実行時にしか現れない問題（設定・認証・インジェクションの実挙動）を検出します。SAST はソースコードの静的解析（開発早期向き）、SCA はサードパーティ依存（自社で使っている外部ライブラリ）の既知脆弱性チェックです。「静的=コード、動的=稼働中」で判別しましょう。CI/CD パイプラインは、コードの変更を自動でビルド（実行できる形に組み立てること）・テスト・本番反映する一連の流れです。📖 復習: 第30章

</details>

**問12.** OSS ライブラリを多数利用する自社製品について、利用しているコンポーネントとそのバージョンを一覧化し、新たな脆弱性公表時に影響範囲を即座に特定できるようにしたいと考えています。整備すべきものはどれですか？

1. SLA（サービスレベル合意）
2. BIA（ビジネス影響分析）
3. NDA（秘密保持契約）
4. SBOM（ソフトウェア部品表）

<details><summary>答えと解説</summary>

正解: **4**

**SBOM（Software Bill of Materials）** はソフトウェアを構成するコンポーネントの「部品表」で、Log4j（Java で広く使われるログ出力ライブラリ。2021年に深刻な脆弱性が見つかった）のような脆弱性公表時に「自社のどの製品が影響を受けるか」を即座に特定できます。SLA はサービス水準の合意、NDA は秘密保持、BIA は事業影響分析であり、コンポーネントの可視化とは無関係です。サプライチェーン対策の頻出用語です。OSS（ソースコードが公開され自由に使えるソフト）は、ライブラリがさらに別のライブラリを使う入れ子構造なので、一覧がないと自社がどれを使っているか分かりません。📖 復習: 第5章・第30章

</details>
