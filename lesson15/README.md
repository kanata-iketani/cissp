# 第15章 ネットワーク機器・セグメンテーション・ゼロトラスト【D4】

ネットワークを「どう区切り、どこで通信を検査するか」はD4の中心テーマです。この章ではファイアウォールの世代、セグメンテーションの手法、SDNなどの仮想化技術、そして試験でも実務でも主役になりつつあるゼロトラストとNACを学びます。

## 1. ファイアウォールの進化

### 基礎の基礎 — 機器は「どのヘッダの何を見るか」で違う

L14で見たとおり、データは送信時に層ごとのヘッダで包まれます(カプセル化)。社内の PC (192.0.2.10) が外部の Web サーバー (203.0.113.5) へ HTTPS で送る1つのフレームの中身は、たとえば次のとおりです。

| 層 | ヘッダの項目 | 値の例 |
|---|---|---|
| L2 イーサネット | 宛先 MAC / 送信元 MAC | 00:00:5e:00:53:01 (出口のルータ) / 00:00:5e:00:53:10 (PC) |
| L3 IP | 送信元 IP / 宛先 IP | 192.0.2.10 / 203.0.113.5 |
| L4 TCP | 送信元ポート / 宛先ポート / フラグ | 51514 / 443 / SYN (接続開始) |
| L7 | 中身 (ペイロード) | TLS で暗号化された HTTP |

**MAC アドレス**は NIC (ネットワークにつなぐ部品) ごとの番号で、同じ LAN の中での宛先です。**IP アドレス**はネットワークをまたいだ最終的な宛先、**ポート番号**は「その機器のどのサービス宛てか」(443=HTTPS、22=SSH など) を表します。送信元ポート 51514 は、PC が接続のたびに適当に選ぶ大きな番号です。宛先 MAC が Web サーバーではなくルータなのは、別のネットワークへ出るときは、まず出口のルータ (デフォルトゲートウェイ) に渡すからです。

| 機器 | 層 | 見るもの | 判断のしかた |
|---|---|---|---|
| ハブ | L1 | 何も見ない | 届いた信号を全ポートへそのままコピー。つながっている全員に届く |
| スイッチ | L2 | 宛先 MAC | MAC アドレステーブル (例: 00:00:5e:00:53:01 → ポート24) を引き、そのポートだけに出す |
| ルータ | L3 | 宛先 IP | ルーティングテーブル (例: 203.0.113.0/24 → 回線A) を引き、次の転送先を決める |
| ファイアウォール | L3/L4 (世代により状態・L7 も) | 送信元/宛先 IP・ポートなど | ルール表と照合して通す/捨てる |

スイッチとルータは「どこへ送るか」を決める機器で、「通してよいか」を決めるのがファイアウォールです。

### ファイアウォールの世代

ファイアウォール (firewall) は「どの層の情報まで見て判断するか」で世代分けできます。この対比は超頻出です。

| 世代 | 見るもの | 特徴 |
|---|---|---|
| パケットフィルタ (static packet filtering) | IPアドレス・ポート番号 (L3/L4) | ルール表で1パケットずつ判断。速いが文脈を見ない |
| ステートフルインスペクション (stateful inspection) | 接続状態テーブル | 「確立済み通信の応答か」を判断できる。現在の標準 |
| アプリケーションレベル (proxy firewall) | アプリ層の中身 (L7) | 通信を代理終端して検査。精密だが遅い |
| 次世代FW (NGFW) | DPI (中身まで解析する検査)・アプリ識別・ユーザー識別 | IPS・URLフィルタ等を統合した多機能型 |

「代理終端」とは、利用者とサーバーの間で FW がいったん通信を受け取り、FW 自身が改めてサーバーへ接続し直すことです。利用者とサーバーが直接つながらないので、中身を組み立て直して検査できます。

Web アプリ専用に SQL インジェクションや XSS (Web アプリへの代表的な攻撃。L29 で扱います) を検査するのが **WAF (Web Application Firewall)** です。

### ルール表の読み方 — 上から評価し、最初に一致した行で決まる

ファイアウォールのルール (ACL: アクセス制御リスト) は、**上の行から順に照合し、最初に一致した行の動作で決まります。それより下の行は見ません**。どの行にも一致しなければ、最後の**暗黙の拒否 (implicit deny)** で捨てられます。`any` は「何でもよい」、`198.51.100.0/24` は「先頭 24 ビットが同じ範囲」、つまり 198.51.100.0〜198.51.100.255 の 256 個を表します。

| # | 送信元 IP | 宛先 IP | プロトコル/宛先ポート | 動作 |
|---|---|---|---|---|
| 1 | any | 203.0.113.10 (公開 Web) | TCP/443 | 許可 |
| 2 | 198.51.100.0/24 | any | any | 拒否 |
| 3 | 192.0.2.0/24 (社内) | any | TCP/443 | 許可 |
| (暗黙) | any | any | any | 拒否 |

このルール表に4つのパケットを当てはめると、次のようになります。

| パケット (送信元 → 宛先) | 照合の流れ | 結果 |
|---|---|---|
| 198.51.100.7:50001 → 203.0.113.10:443 | 1行目に一致。2行目は見ない | **許可** |
| 198.51.100.7:50002 → 203.0.113.10:22 | 1行目は宛先ポートが違う → 2行目に一致 | 拒否 |
| 203.0.113.99:40000 → 192.0.2.20:3389 | 1〜3行目のどれにも一致しない | 暗黙の拒否 |
| 192.0.2.20:51514 → 198.51.100.80:443 | 1行目・2行目は不一致 → 3行目に一致 | 許可 |

1つ目に注目してください。2行目で 198.51.100.0/24 を締め出したつもりでも、より上の1行目が先に一致するため、443 番には届いてしまいます。止めたいなら拒否の行を1行目より上に置きます。「**狭く具体的な行を上、広い行を下**」が並べ方の基本です。

### ステートフルは「行き」を覚えて「帰り」を通す

上の4つ目のパケットに対して、Web サイトからは 198.51.100.80:443 → 192.0.2.20:51514 という**戻りのパケット**が来ます。

- 静的パケットフィルタ: 1パケットずつしか見ないので、戻りを通すには「送信元ポート 443 から社内の 1024 番以上のポートへは許可」のような広い穴を開けるしかありません。攻撃者が送信元ポートを 443 にしただけのパケットも通ってしまいます
- ステートフルインスペクション: 行きのパケットを通した時点で、**状態テーブル**に次の1行を記録します

| プロトコル | 内側 | 外側 | 状態 |
|---|---|---|---|
| TCP | 192.0.2.20:51514 | 198.51.100.80:443 | ESTABLISHED (確立済み) |

戻りのパケットはこの行と一致するので通し、どの行とも一致しない「応答のふりをしたパケット」(例: 198.51.100.80:443 → 192.0.2.20:52000) は捨てます。ルール表には行きの許可だけを書けばよくなります。

### 設計の基本

- ルールの最後は**デフォルト拒否 (implicit deny)**。明示的に許可した通信以外はすべて拒否します
- 公開サーバー(Web・メール・DNS)は内部LANに置かず、外部FWと内部FWで挟んだ**スクリーンドサブネット (screened subnet、いわゆるDMZ)** に置きます。例: インターネット → 外部FW → DMZ (Web サーバー 203.0.113.10) → 内部FW → 社内 LAN (192.0.2.0/24)。外部FW は DMZ の Web の 443 番だけを許可し、内部FW は DMZ から社内への通信を原則拒否します (必要な DB 接続1本だけ許可する、など)。こうすると Web サーバーが乗っ取られても、社内へは簡単に進めません
- 内→外の通信を絞る**エグレスフィルタリング (egress filtering)** は、マルウェアの C2 通信 (攻撃者のサーバーから指令を受ける通信) や情報持ち出しの発見に有効です。たとえば外向きは「社内からプロキシ経由の 443 番だけ許可」にしておくと、次のような拒否ログが残ります

```
2026-11-13 02:14:07 DENY TCP 192.0.2.35:49822 -> 198.51.100.66:4444 rule=implicit-deny
```

左から、日時・動作 (DENY=拒否)・プロトコル・送信元 → 宛先・一致したルール (暗黙の拒否) です。深夜 2 時に社内 PC (192.0.2.35) が、見慣れない外部アドレスの 4444 番へ直接つなごうとして止められた、と読めます。業務で使う理由のない通信なので、感染端末の C2 通信を疑うきっかけになります

💡 コツ: 試験で「侵害された公開サーバーから内部への被害を最小化する構成は?」と来たらスクリーンドサブネット、「社内からの不審な外向き通信を見つけたい」と来たらエグレスフィルタリングが正解筋です。

### 確認問題

**問1.** ステートフルインスペクション型ファイアウォールが静的パケットフィルタより優れている点として、最も適切なものはどれですか。

1. アプリケーション層のペイロードを完全に復号して検査できる
2. 通信を代理終端するため内部ネットワークを完全に隠蔽できる
3. 接続状態テーブルを保持し、確立済みセッションの応答かどうかを文脈で判断できる
4. ルールを設定しなくても自動的に不正通信を学習して遮断できる

<details><summary>答えと解説</summary>

正解: **3**

ステートフルインスペクションは接続状態 (state) を記録し、「この戻りパケットは内部から始まった正当なセッションの応答か」を判断できます。これが静的フィルタとの決定的な違いです。アプリ層の中身まで見るのはプロキシ型や NGFW の DPI、代理終端はプロキシ型の特徴で、自動学習はファイアウォール一般の機能ではありません。試験では「どの世代が何を見るか」を入れ替えて出すひっかけが定番です。

</details>

**問2.** ファイアウォールのルールが上から「1: 送信元 any → 宛先 203.0.113.10 TCP/443 許可」「2: 送信元 198.51.100.0/24 → 宛先 any すべて 拒否」の順に並び、最後は暗黙の拒否です。パケット 198.51.100.7:50001 → 203.0.113.10:443 はどう扱われますか。

1. 拒否のルールが常に優先されるため、2行目で拒否される
2. 1行目に一致した時点で許可され、2行目は評価されない
3. どの行にも一致しないため、暗黙の拒否で捨てられる
4. 許可と拒否の両方に一致するため、管理者に判断が委ねられる

<details><summary>答えと解説</summary>

正解: **2**

ファイアウォールのルールは上から順に照合し、最初に一致した行の動作で決まります。このパケットは宛先 203.0.113.10・TCP/443 なので1行目に一致し、その時点で許可されます。「拒否が常に優先」という仕組みはなく、2行目は評価されません。1行目に一致している以上「どの行にも一致しない」も誤りで、管理者に判断を委ねる動作もありません。198.51.100.0/24 を確実に止めたいなら、拒否の行を1行目より上に置く必要があります。ルールの順番ミスは実務でも試験でも定番の論点です。

</details>

**問3.** インターネットに公開する Web サーバーを設置する場所として、最も適切 (BEST) なのはどれですか。

1. 外部ファイアウォールと内部ファイアウォールに挟まれたスクリーンドサブネット
2. 利便性を考慮した社内 LAN の内部セグメント
3. ファイアウォールを介さずインターネットに直結した境界の外側
4. 経営層専用ネットワークと同一のセグメント

<details><summary>答えと解説</summary>

正解: **1**

公開サーバーは侵害される前提で、外部からはアクセスさせつつ内部 LAN からは分離するスクリーンドサブネット (DMZ) に置くのが定石です。社内 LAN に置くと侵害時に内部へ横展開され、境界の外に直結すると保護が一切なく、経営層ネットワークとの同居は論外です。「公開サーバー=DMZ」は反射で答えられるようにしましょう。

</details>

**問4.** 次世代ファイアウォール (NGFW) を従来型と区別する特徴として、最も適切なものはどれですか。

1. IP アドレスとポート番号のみで高速に通信を制御する
2. ディープパケットインスペクションによるアプリケーション識別と IPS 等の統合機能を持つ
3. 磁気媒体を消磁してデータ残留を防止する
4. 接続状態を一切保持しないことで単純性を高めている

<details><summary>答えと解説</summary>

正解: **2**

NGFW はポート番号に頼らず DPI (deep packet inspection) で「どのアプリの通信か」を識別し、IPS・URL フィルタ・ユーザー識別などを1台に統合します。IP とポートのみの制御はパケットフィルタの説明、消磁はデータ廃棄の話でネットワークと無関係、状態を保持しないのはむしろ旧世代の特徴です。「ポート 443 だから安全とは言えない」場面で NGFW のアプリ識別が活きます。

</details>

**問5.** ファイアウォールのルール設計における「デフォルト拒否 (implicit deny)」の意味として正しいものはどれですか。

1. 管理者の通信だけは常に無条件で許可する
2. 営業時間外はすべての通信を拒否する
3. 拒否ルールに一致した通信のみを拒否し、それ以外は許可する
4. 明示的に許可されていない通信は、最終的にすべて拒否する

<details><summary>答えと解説</summary>

正解: **4**

デフォルト拒否は「許可リストに載っていないものはすべて拒否」という設計原則で、最小権限の考え方をネットワークに適用したものです。「拒否ルールに一致した通信のみを拒否し…」はその逆のデフォルト許可 (default allow) で危険な設計です。管理者の無条件許可は特権の濫用リスクがあり、時間帯による拒否は単なるルールの一種にすぎません。「allow list が基本、deny list は漏れる」という感覚を持ちましょう。

</details>

**問6.** マルウェア感染端末から外部の C2 サーバーへの通信を発見・遮断する目的で導入する対策として、最も適切 (MOST) なのはどれですか。

1. 外部から内部へのインバウンド通信の全面許可
2. ネイティブ VLAN の変更
3. 内部から外部への通信を必要最小限に絞るエグレスフィルタリング
4. スイッチのポートミラーリングの無効化

<details><summary>答えと解説</summary>

正解: **3**

エグレスフィルタリング (egress filtering) は内→外の通信を検査・制限する対策で、C2 通信やデータ持ち出しの発見に直結します。多くの組織は外→内ばかり守り、内→外が素通しになりがちです。インバウンド全面許可は論外、ネイティブ VLAN 変更は VLAN ホッピング対策、ポートミラーリング無効化はむしろ監視能力を下げます。「出ていく通信も疑う」のが CISSP 的視点です。

</details>

**問7.** スイッチが、受け取ったフレームをどのポートへ出すかを決めるときに見る情報として、正しいものはどれですか。

1. 宛先 IP アドレスとルーティングテーブル
2. 宛先ポート番号とファイアウォールのルール表
3. 何も見ずに、全ポートへコピーする
4. 宛先 MAC アドレスと MAC アドレステーブル

<details><summary>答えと解説</summary>

正解: **4**

スイッチは L2 の機器で、フレームの宛先 MAC アドレスを MAC アドレステーブルで引き、該当するポートだけに出します。宛先 IP とルーティングテーブルで次の転送先を決めるのは L3 のルータ、宛先ポート番号をルール表と照合するのはファイアウォール、何も見ずに全ポートへコピーするのは L1 のハブです。「ハブ=見ない、スイッチ=MAC、ルータ=IP、FW=IP・ポートと通してよいか」の順に、見る情報が増えていくと押さえましょう。

</details>

## 2. ネットワークセグメンテーション

### なぜ区切るのか

セグメンテーション (segmentation) の目的は3つです。①侵害時の**影響範囲の限定**(横展開の防止)、②ブロードキャストを減らす**性能向上**、③カード情報環境 (CDE: カード会員データを扱うシステム群。PCI DSS という業界基準の監査対象) の分離など**コンプライアンス対応**(監査範囲の縮小)。

### 基礎の基礎 — ブロードキャストドメインと VLAN

**ブロードキャスト**は、同じネットワークの全員宛てに一斉に送ることです (L14で見た ARP の「192.0.2.1 の MAC アドレスを持つのは誰?」という問い合わせなど)。スイッチはブロードキャストを全ポートへ配るので、それが届く範囲を**ブロードキャストドメイン**と呼びます。VLAN は、1台のスイッチのポートを設定でグループ分けし、このドメインを分ける技術です。

| スイッチのポート | VLAN | 用途 | IP アドレスの範囲 |
|---|---|---|---|
| 1〜12 | 10 | 営業 | 192.0.2.0/25 (192.0.2.0〜127) |
| 13〜22 | 20 | 経理 | 192.0.2.128/25 (192.0.2.128〜255) |
| 24 | トランク (10 と 20) | 上位のスイッチ・ルータへ | — |

- **アクセスポート** (1〜22): 1つの VLAN に属し、端末をつなぐポート。営業の PC が出したブロードキャストは経理のポートには届きません
- **トランクポート** (24): 複数の VLAN のフレームを1本で運ぶポート。どの VLAN のフレームかを示す **802.1Q タグ** (VLAN 番号を入れた 4 バイトの札) をフレームに付けて送ります。VLAN 番号は 12 ビットなので、使えるのは 1〜4094 です
- **ネイティブ VLAN**: トランク上でタグを付けずに送る VLAN。既定値は VLAN 1 です
- VLAN 10 と VLAN 20 の間の通信は、ルータ (または L3 スイッチ) を経由しないと届きません。だからそこにファイアウォールのルールをかけて、営業→経理の通信を制御できます

VLAN はスイッチの設定で分けているだけなので、設定の不備を突かれると越えられます。それが後で見る VLAN ホッピングです。

### 代表的な手法

| 手法 | 分離のレベル |
|---|---|
| サブネット分割 | L3。ルータ/FW で通信を制御 |
| VLAN | L2。スイッチ上で**ブロードキャストドメインを論理分割** |
| マイクロセグメンテーション (microsegmentation) | ワークロード (VM・コンテナなど1つ1つの処理単位) 単位。データセンター内の東西 (east-west、L14で見たサーバー間の通信) トラフィックも個別に制御 |
| エアギャップ (air gap) | 物理的に接続しない**最強の分離**。ただし運用コスト大 |

マイクロセグメンテーションの例: 同じサブネットにある Web サーバー2台 (192.0.2.11・192.0.2.12)、アプリサーバー (192.0.2.21)、DB サーバー (192.0.2.31) に対し、「Web → アプリ TCP/8080 だけ許可」「アプリ → DB TCP/5432 だけ許可」「それ以外はすべて拒否」とサーバーごとに決めます。Web-1 が乗っ取られても、隣の Web-2 や DB へ直接は進めません。

- **イントラネット**は内部専用、**エクストラネット**は取引先など限定された外部に開放する中間領域です
- 機器の管理用通信は本番トラフィックと分けた**帯域外管理 (out-of-band management)** が推奨です。機器の設定変更に使う管理用ポートを、業務の通信とは別の専用ネットワークにつなぐ方式で、業務ネットワークが攻撃されても管理経路は奪われにくくなります

### VLAN ホッピング対策

攻撃者がタグを偽装して別 VLAN に侵入する VLAN ホッピングには、未使用ポートの無効化、ポートのトランク自動ネゴシエーション無効化、**ネイティブ VLAN をデフォルト (VLAN 1) から変更**するなどで対抗します。手口は2つあります。

- **スイッチスプーフィング**: 攻撃者の PC がスイッチのふりをして、トランクの自動交渉 (Cisco の DTP など) のメッセージを送ります。ポートがトランクになってしまうと、全 VLAN のフレームを受け取れます。対策は自動交渉の無効化と、端末用ポートをアクセスポートに固定することです
- **二重タグ付け (double tagging)**: タグを2枚重ねて、別の VLAN へフレームを送り込みます。次の順で進みます

1. 攻撃者は、ネイティブ VLAN と同じ VLAN 1 のアクセスポートにいる
2. 外側に VLAN 1、内側に VLAN 20 の2枚のタグを付けたフレームを送る
3. 1台目のスイッチは外側の VLAN 1 を見て、トランクへ出すときに「ネイティブ VLAN はタグなし」なので外側のタグだけ外す
4. 2台目のスイッチは残った内側のタグ 20 を読み、VLAN 20 のポートへ届けてしまう

応答は攻撃者に戻らない一方通行ですが、攻撃パケットは届きます。ネイティブ VLAN を利用者が使わない番号 (例: 999) に変えれば、外側のタグが外されなくなり成立しません。

💡 コツ: 「監査範囲 (スコープ) を減らしたい」「感染の横展開を止めたい」と来たらセグメンテーション。「絶対に外部と接続してはならないシステム」と来たらエアギャップが正解筋です。

## 3. SDN・SD-WAN・仮想ネットワーク

### SDN — ネットワークをソフトウェアで定義する

**SDN (Software-Defined Networking)** の本質は、経路判断を行う**コントロールプレーン**と、実際にパケットを転送する**データプレーン**の分離です。判断機能を集中させた **SDN コントローラ**がネットワーク全体を一元管理します。

ルータで言えば、「203.0.113.0/24 宛ては回線 A へ」という経路表を作る判断の部分がコントロールプレーン、届いたパケットを経路表どおりに次へ流す作業の部分がデータプレーンです。従来は1台ごとに両方を持っていましたが、SDN では判断をコントローラに集め、各スイッチは指示された表どおりに転送するだけになります。OpenFlow でコントローラがスイッチに書き込む1行 (フローエントリ) は、たとえば「一致条件: 宛先 IP 203.0.113.10・TCP/443 → 動作: ポート3へ転送」のような形です。

API は、プログラム同士が命令やデータをやり取りするための決まった窓口です。

| API | つなぐもの | 例 |
|---|---|---|
| サウスバウンド API | コントローラ ⇔ ネットワーク機器 | OpenFlow |
| ノースバウンド API | コントローラ ⇔ 管理アプリ | REST API |

セキュリティ上の要点: コントローラは**単一障害点であり最重要の攻撃対象**です。乗っ取られればネットワーク全体を支配されるため、アクセス制御・冗長化・通信の暗号化が必須です。

### 関連技術

- **SD-WAN**: MPLS 専用線 (L14で見た、通信事業者の閉域網) とインターネット回線など複数の WAN 回線を、アプリ要件に応じてポリシーで使い分ける仮想 WAN
- **NFV (Network Functions Virtualization)**: FW やルータなどの機能を、専用アプライアンス (その機能専用の箱型機器) から仮想マシン上のソフトウェアへ移す
- **VXLAN**: L2 ネットワークを L3 上に延伸するカプセル化。VLAN 番号は 12 ビットで 4094 個までですが、VXLAN の識別番号は 24 ビットで約 1,600 万個まで使えます
- クラウドでは **VPC** で仮想ネットワークを作り、インスタンス (クラウド上の仮想マシン) 単位の仮想 FW である**セキュリティグループ**で通信を制御します。たとえば Web サーバー用に「受信: TCP/443 送信元 0.0.0.0/0 (すべての IPv4 アドレス) 許可」「受信: TCP/22 送信元 192.0.2.0/24 (社内) 許可」の2行だけを書けば、それ以外の受信は拒否されます。ステートフルなので、許可した通信の戻りは自動で通ります

💡 コツ: SDN の問題は「何と何を分離するか」と「何を最優先で守るか(=コントローラ)」の2点がほぼすべてです。

## 4. ゼロトラストとNAC

### ゼロトラスト — 「社内だから安全」をやめる

従来の境界型防御は「外は危険、中は安全」という前提でした。**ゼロトラスト (zero trust)** はこれを捨て、「**決して信頼せず、常に検証する (never trust, always verify)**」を原則とします。NIST SP 800-207 では、アクセスのたびにユーザー・デバイス・文脈を評価して**資産単位で最小権限のアクセス**を許可します。許可を判断する**ポリシー決定点 (PDP)** と、通信を実際に通す/止める**ポリシー実施点 (PEP)** という概念で整理されます。

たとえば社員 user01 が社内の経費システムを開こうとしたとき、PDP は次の情報をまとめて判断し、PEP (経費システムの手前のゲートウェイなど) がその結果どおりに通します。

| 確認する項目 | 値の例 | 判断 |
|---|---|---|
| 利用者 | user01 (パスワード + スマホの承認で認証済み) | OK |
| 端末 | 会社支給 PC、OS 更新は 3 日前 | OK |
| 場所・時刻 | 自宅回線 198.51.100.23、平日 09:12 | 普段どおり |
| 対象 | 経費システムの申請画面だけ | 許可 (人事システムなどは別途判断) |

同じ user01 でも、OS 更新が 60 日止まった私物 PC からなら拒否、または閲覧のみに制限されます。社内 LAN からのアクセスでも、この評価は省略しません。

**SASE (Secure Access Service Edge)** は、SD-WAN に SWG (Web へのアクセスを検査するゲートウェイ)・CASB (クラウドサービスの利用を可視化・制御する仕組み)・ZTNA (ゼロトラスト方式のリモートアクセス) などのセキュリティ機能を加えてクラウドサービスとして提供するモデルで、場所を問わない働き方とゼロトラストを支えます。

### NAC と 802.1X

**NAC (Network Access Control)** は、端末がネットワークに接続する時点で認証と**ポスチャ評価**(パッチ・ウイルス対策の状態確認)を行い、基準を満たさない端末を**検疫 (quarantine) ネットワーク**に隔離します。例: 「OS 更新が 30 日以上未適用」の PC は検疫用の VLAN 99 に入れられ、そこからは更新配信サーバーにしか届きません。更新を当てて再評価に合格すると、通常の VLAN 10 に戻されます。

認証の標準が **IEEE 802.1X** で、3つの登場人物を押さえましょう(超頻出)。

| 役割 | 実体 |
|---|---|
| サプリカント (supplicant) | 接続したい端末側のソフト |
| オーセンティケータ (authenticator) | スイッチや無線 AP |
| 認証サーバー (authentication server) | RADIUS サーバー (利用者の認証可否を答えるサーバー。L18 で詳しく扱います) |

有線で PC をスイッチにつないだときの流れは次のとおりです。

1. ポートは最初「未認証」状態で、認証用のフレーム (EAPOL) 以外は通しません。DHCP でのアドレス取得も Web 閲覧もできません
2. スイッチ (オーセンティケータ) が「身元を名乗ってください」(EAP-Request/Identity) を送ります
3. PC (サプリカント) が「user01」と答えます
4. スイッチはその EAP メッセージを RADIUS の Access-Request に包んで、RADIUS サーバー (例: 192.0.2.5) へ中継します。スイッチ自身は中身を判定しません
5. PC と RADIUS サーバーの間で、決められた方式 (パスワード、証明書など) で本人確認のやり取りをします
6. RADIUS サーバーが Access-Accept (成功) か Access-Reject (失敗) を返します。Accept には「この端末は VLAN 10 に入れる」といった指示も載せられます
7. スイッチはポートを「認証済み」に切り替え、通常の通信を通します

💡 コツ: MAC アドレスフィルタリングは MAC が容易に偽装できるため**単独では不十分**です。「手軽な対策 vs 本物の認証 (802.1X)」の対比で出題されます。

### 確認問題

**問1.** ゼロトラストアーキテクチャの基本原則として、最も適切なものはどれですか。

1. 社内ネットワークからのアクセスは信頼し、社外からのアクセスのみ検証する
2. ネットワーク上の位置にかかわらず、アクセス要求のたびに検証して最小権限で許可する
3. 一度認証に成功した端末は、以後すべてのリソースへ自由にアクセスできるようにする
4. 境界ファイアウォールを強化すれば内部の制御は不要になる

<details><summary>答えと解説</summary>

正解: **2**

ゼロトラストは「社内=安全」という暗黙の信頼を排除し、場所を問わずアクセスごとにユーザー・デバイス・文脈を検証して資産単位の最小権限を適用します。社内を無条件に信頼する、一度の認証で全リソース開放、境界だけ強化という選択肢はすべて従来の境界型防御の発想で、ゼロトラストの対極です。「never trust, always verify」を言い換えた選択肢を選べるようにしましょう。

**問2.** IEEE 802.1X においてオーセンティケータの役割を担う機器はどれですか。

1. 接続を要求する利用者の端末
2. 認証情報を検証する RADIUS サーバー
3. ディレクトリ情報を保管する LDAP サーバー
4. 端末が接続するスイッチや無線アクセスポイント

<details><summary>答えと解説</summary>

正解: **4**

802.1X の3要素は、端末側のサプリカント、中継役のオーセンティケータ(スイッチ・無線 AP)、検証役の認証サーバー(RADIUS)です。オーセンティケータは自分では認証を判断せず、サプリカントと認証サーバーの間を取り次いでポートの開閉だけを行います。「オーセンティケータ=認証サーバー」と誤解させるのが定番のひっかけなので、名前に惑わされないようにしましょう。

</details>

**問3.** IEEE 802.1X を有効にしたスイッチのポートに PC をつないだ直後、認証が完了する前のポートの状態として正しいものはどれですか。

1. すべての通信を通し、認証は後から並行して行われる
2. DHCP と Web 閲覧だけは許可され、それ以外が遮断される
3. 認証用のフレーム (EAPOL) だけを通し、それ以外の通信は遮断される
4. ポートが物理的に通電せず、リンクランプも点灯しない

<details><summary>答えと解説</summary>

正解: **3**

802.1X のポートは認証が成功するまで「未認証」状態で、サプリカントとオーセンティケータの間の認証用フレーム (EAPOL) だけを通します。RADIUS サーバーから Access-Accept が返って初めて通常の通信が通ります。すべての通信を先に通すのでは認証の意味がなく、DHCP や Web 閲覧も認証前は通りません。リンク自体は確立しており、物理的に通電しないわけではありません。「つないだだけでは何も使えない」点が、MAC フィルタなどとの違いです。

</details>

**問4.** NAC のポスチャ評価で OS パッチが未適用と判定された端末の扱いとして、最も適切 (BEST) なのはどれですか。

1. 検疫ネットワークに隔離し、修復後に本番ネットワークへの接続を許可する
2. 業務影響を避けるため、そのまま本番ネットワークへの接続を許可する
3. 端末を即座に初期化して全データを消去する
4. 利用者のアカウントを恒久的に削除する

<details><summary>答えと解説</summary>

正解: **1**

NAC の標準的な動作は、基準を満たさない端末を検疫 (quarantine) ネットワークへ隔離し、パッチ適用などの修復 (remediation) を行ってから本番への接続を許可する流れです。そのまま接続させては NAC の意味がなく、即初期化やアカウント恒久削除は業務影響に対して過剰です。「隔離→修復→再評価」という、セキュリティと業務継続のバランスを取る選択肢が CISSP の正解筋です。

</details>

**問5.** SASE (Secure Access Service Edge) の説明として、最も適切なものはどれですか。

1. データセンター内の物理サーバーを集約する仮想化基盤
2. SD-WAN と SWG・CASB・ZTNA 等のセキュリティ機能をクラウドサービスとして統合提供するモデル
3. 建物の入退室管理と監視カメラを統合した物理セキュリティ製品
4. バックアップデータを遠隔地に複製する災害対策サービス

<details><summary>答えと解説</summary>

正解: **2**

SASE はネットワーク機能 (SD-WAN) とセキュリティ機能 (セキュア Web ゲートウェイ、CASB、ゼロトラストネットワークアクセスなど) をクラウドのエッジで統合提供するモデルです。利用者がどこにいても同じポリシーを適用でき、ゼロトラストの実現手段として出題が増えています。仮想化基盤・物理セキュリティ・バックアップはいずれも無関係です。

</details>

**問6.** 無線 LAN のアクセス制御として MAC アドレスフィルタリングのみを使うことの問題点として、最も適切なものはどれですか。

1. MAC アドレスは暗号化されるため管理者が登録作業をできない
2. MAC アドレスフィルタリングを使うと通信速度が半分になる
3. MAC アドレスは容易に偽装できるため、単独では実質的な認証にならない
4. MAC アドレスフィルタリングは法律で使用が禁止されている

<details><summary>答えと解説</summary>

正解: **3**

MAC アドレスは電波上で平文のまま見えるため、攻撃者は正規端末の MAC を観測して自端末に設定(スプーフィング)できます。したがって MAC フィルタは手軽ですが実質的な認証にはならず、802.1X のような本物の認証と併用すべきです。MAC が暗号化される、速度が半減する、法律で禁止という事実はありません。「手軽な対策の限界」を問う典型問題です。

</details>
