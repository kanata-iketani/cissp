# 第23章 調査とデジタルフォレンジック【D7】

セキュリティインシデントが起きたとき、「犯人を特定して処分・訴追できるか」は証拠の扱い方で決まります。この章では、調査の種類と立証基準、法廷で通用する証拠の要件、チェーンオブカストディと揮発性の順序、そしてデジタルフォレンジックと eディスカバリの流れを学びます。CISSP では「技術的にどう解析するか」よりも「証拠能力を失わない手順はどれか」が問われることを意識しましょう。

## 1. 調査の種類と証拠の要件

### 調査には4つの種類がある

同じ「不正の調査」でも、誰が何のために行うかで、求められる厳密さ(立証基準)がまったく違います。立証基準とは、裁判などで事実を認めてもらうのに必要な確からしさの水準です。この対比は超頻出です。

| 調査の種類 | 主体・目的 | 立証基準 |
|---|---|---|
| 行政・内部調査 (administrative) | 組織内。ポリシー違反や業務上の問題の解明 | 最も緩い(組織の判断で足りる) |
| 刑事調査 (criminal) | 警察・検察。犯罪の訴追(起訴して裁判にかけること) | **合理的疑いを超える証明 (beyond a reasonable doubt)** = 最も厳格 |
| 民事調査 (civil) | 当事者間。損害賠償などの民事訴訟 | **証拠の優越 (preponderance of evidence)** = 「どちらがより確からしいか」 |
| 規制調査 (regulatory) | 監督官庁。法令・規制違反の確認 | 根拠法によって異なる |

💡 コツ: 「刑事=人の自由を奪いうるから最も厳格」「民事=50%を超えればよい」とセットで覚えます。内部調査でも、後で刑事事件に発展する可能性があれば、最初から厳格な証拠の扱いをするのが BEST です。

### 法廷で使える証拠の3要件

証拠として採用される (admissible) には、次の3つを満たす必要があります。

- **関連性 (relevant)**: 争点の事実と関係があること
- **重要性 (material)**: 事件の結論に影響すること
- **証拠能力 (competent)**: **適法な手段で収集された**こと(違法収集は説得力があっても不可)

### 伝聞証拠と最良証拠の原則

- **伝聞証拠 (hearsay)**: 法廷外での発言の又聞きは原則、証拠にできません。ただし**通常業務の過程で作られたビジネス記録(business records exception)**は例外として認められ、システムログもこの扱いを狙って「通常業務として」取得・保全します
- **最良証拠の原則 (best evidence rule)**: 文書の内容を証明するには原本が最良。コピーで代える場合は正当な理由が必要です
- 証拠の形態には、口頭証拠 (testimonial。証人の証言)、書面証拠 (documentary。契約書・メール・ログなど)、実物証拠 (real/physical。押収したPC本体など)、説明用のデモンストレーティブ証拠 (demonstrative。時系列図や模型) があります

伝聞の例: 同僚が「Aさんが顧客データを持ち出したと、Bさんから聞いた」と証言しても、Bさん本人の発言ではないので原則として証拠にできません。一方、次のような認証ログが毎日自動で記録・保管されていれば、ビジネス記録として扱われえます。

```
2026-05-10T02:14:03+09:00 web01 sshd[2311]: Accepted password for alice from 198.51.100.7
```

左から、日時(+09:00 は日本時間)、記録したサーバー名、記録したプログラム(sshd は遠隔ログインを受け付けるプログラム、2311 はその処理番号)、内容(alice がパスワードでログインに成功、接続元は 198.51.100.7)です。

### 確認問題

**問1.** 刑事訴追で求められる立証基準として、正しいものはどれでしょう？

1. 証拠の優越
2. 組織のポリシーに照らした合理的判断
3. 合理的疑いを超える証明
4. 明白かつ説得力のある証明があれば常に足りる

<details><summary>答えと解説</summary>

正解: **3**

刑事事件は被告人の自由や財産を奪いうるため、「合理的疑いを超える証明 (beyond a reasonable doubt)」という最も厳格な基準が課されます。「証拠の優越」は民事訴訟の基準、「組織のポリシーに照らした判断」は行政・内部調査の水準です。「明白かつ説得力のある証明 (clear and convincing evidence)」は民事と刑事の中間にあたる基準で、一部の民事事件で使われるものであり、刑事で「常に足りる」わけではありません。ひっかけとして民事と刑事の基準を入れ替えた選択肢がよく出るので、「刑事=最も厳格」をまず固定しましょう。

</details>

**問2.** 従業員が社内の利用規程 (AUP) に違反して業務PCを私的利用していた疑いがあり、人事部門が事実関係を調べることになりました。この調査の種類として最も適切なものはどれでしょう？

1. 行政・内部調査
2. 刑事調査
3. 規制調査
4. 民事調査

<details><summary>答えと解説</summary>

正解: **1**

組織が自らのポリシー違反を解明するために行う調査は行政・内部調査 (administrative investigation) です。刑事調査は法執行機関による犯罪捜査、規制調査は監督官庁によるもの、民事調査は訴訟の当事者間のものなので該当しません。なお、内部調査の途中で犯罪の証拠が見つかり刑事事件に発展することもあるため、最初から証拠を丁寧に扱うのが CISSP 的な BEST です。

</details>

**問3.** 証拠の3要件のうち「証拠能力 (competent)」の意味として、最も適切なものはどれでしょう？

1. 証拠が争点の事実と関係していること
2. 証拠が事件の結論を左右するほど重要であること
3. 証拠の内容が技術的に高度で説得力があること
4. 証拠が適法な手段で収集されていること

<details><summary>答えと解説</summary>

正解: **4**

証拠能力 (competent) とは、法的に有効な方法=適法な手段で収集されたことを指します。争点との関係は「関連性 (relevant)」、結論への影響は「重要性 (material)」です。「説得力がある」は要件ではありません——どれほど決定的な内容でも、違法に収集された証拠は採用されない、という点がこの論点のひっかけどころです。

</details>

**問4.** 退職した元従業員に対して営業秘密の持ち出しによる損害賠償を求める訴訟を起こします。この民事訴訟で原告に求められる立証基準はどれでしょう？

1. 合理的疑いを超える証明
2. 証拠の優越
3. 監督官庁の認定
4. 本人の自白

<details><summary>答えと解説</summary>

正解: **2**

民事訴訟の立証基準は「証拠の優越 (preponderance of evidence)」で、相手方の主張より確からしい(50%超)と判断されれば勝訴できます。「合理的疑いを超える証明」は刑事の基準で、民事には要求されません。監督官庁の認定や自白は立証基準そのものではありません。刑事より緩い基準なので、刑事で無罪でも民事で賠償が認められることがある、という理解まで持てると盤石です。

</details>

**問5.** サーバーのアクセスログを訴訟の証拠として提出したいと考えています。伝聞証拠 (hearsay) の問題を回避するために、ログの扱いとして最も適切 (BEST) な説明はどれでしょう？

1. ログは機械が生成したものなので、どのような取得方法でも常に証拠になる
2. ログは伝聞証拠にあたるため、いかなる場合も証拠にできない
3. 通常業務の過程で継続的に取得・保全された記録であれば、ビジネス記録の例外として認められうる
4. インシデント発生後に管理者がログの重要部分を抜粋して作り直せば証拠能力が高まる

<details><summary>答えと解説</summary>

正解: **3**

システムログは「通常業務の過程で作成されるビジネス記録 (business records exception)」として伝聞証拠の例外になりえます。そのためには、インシデントの有無にかかわらず日常的にログを取得・保全している実績が重要です。「常に証拠になる」「いかなる場合も不可」という極端な選択肢はどちらも誤りで、事後に抜粋して作り直す行為はむしろ改ざんと見なされ証拠能力を損ないます。極端な表現 (always/never) の選択肢は疑う、という試験テクニックも使えます。

</details>

## 2. 証拠の収集と保全

### 大原則: オリジナルには手を加えない

証拠収集の鉄則は「**オリジナルの証拠には一切手を加えず、検証可能なコピーで分析する**」ことです。疑わしいPCをその場で開いてファイルを見て回る——これは典型的な NG 行為で、タイムスタンプ(ファイルの作成・更新・最終アクセスの日時)が書き換わり、証拠能力が失われます。ファイルを開いただけでも最終アクセス日時が更新されることがあります。

### チェーンオブカストディ (chain of custody)

証拠が収集されてから法廷に出るまで、**誰が・いつ・どこで・何を・どう扱ったか**を途切れなく記録したものです。これが1か所でも途切れると「その間に改ざんされたのでは」という疑いを排除できず、証拠の価値が大きく下がります。証拠ラベル、署名付きの受け渡し記録、施錠された保管庫での管理がセットです。記録の例です。

| 日時 | 証拠 | 作業 | 渡した人 → 受けた人 | 場所 |
|---|---|---|---|---|
| 5/10 09:12 | EV-001 ノートPC | 押収、ラベル貼付、写真撮影 | 情報システム部 田中 → 調査員 鈴木 | 3階会議室 |
| 5/10 10:30 | EV-001 | 保管庫へ搬入 | 鈴木 → 保管責任者 佐藤 | 証拠保管庫(施錠) |
| 5/11 13:00 | EV-001 | イメージ取得のため持ち出し | 佐藤 → 鈴木 | 解析室 |

### 揮発性の順序 (order of volatility)

消えやすいものから先に収集します。順序は超頻出です。

| 順 | 対象 | 性質 |
|---|---|---|
| 1 | CPU レジスタ・キャッシュ(CPU 内部の作業用の小さな記憶) | 数ナノ秒で変化 |
| 2 | メモリ (RAM)・ARP キャッシュ(第14章で見た、IP アドレスと MAC アドレスの対応表)・プロセス状態(動いているプログラムと通信の一覧) | 電源断で消失 |
| 3 | 一時ファイル・スワップ(メモリが足りないときにディスクへ退避した領域) | 再起動で消えうる |
| 4 | ディスク上のデータ | 電源断でも残る |
| 5 | リモートログ・バックアップ・アーカイブ | 最も永続的 |

メモリには、動いているマルウェアの本体、通信中の相手、ディスク上では暗号化されているデータの復号済みの中身や暗号鍵が残っていることがあります。電源を切るとすべて消えます。

💡 コツ: 「電源を切る前にメモリを取る」。ライブフォレンジック(稼働中に収集)とデッドボックス(停止後にディスクを解析)の使い分けは、揮発性データが必要かで決まります。

### 法的ホールドと専門家への相談

- **法的ホールド (litigation hold)**: 訴訟の通知や予見があったら、関連データの**自動削除・上書きを直ちに停止**し保全します。保持期限が来たからと消してしまうと、証拠隠滅 (spoliation) と見なされえます
- 証拠の押収には**捜索令状 (search warrant)** か所有者の**同意**が必要です。企業内でも、調査の進め方は**まず法務・弁護士に相談**してから動くのが CISSP 的な正解です

### 確認問題

**問1.** 揮発性の順序 (order of volatility) に従って証拠を収集するとき、最初に収集すべきものはどれでしょう？

1. ハードディスク上のログファイル
2. CPU のレジスタとキャッシュ
3. バックアップテープ
4. スワップファイル

<details><summary>答えと解説</summary>

正解: **2**

最も消えやすいもの=CPU のレジスタ・キャッシュから収集します。次にメモリやネットワーク状態、一時ファイル・スワップ、ディスク、最後にバックアップ・アーカイブの順です。ディスク上のログやバックアップは電源を切っても残るため後回しにできます。「重要なものから集める」ではなく「消えやすいものから集める」のがポイントで、ここを入れ替えるひっかけが定番です。

</details>

**問2.** チェーンオブカストディを維持する目的として、最も適切 (BEST) なものはどれでしょう？

1. 証拠の分析を高速化するため
2. 調査費用を会計上正しく計上するため
3. 収集から提出まで証拠が改ざんされていないことを証明するため
4. 調査担当者の労働時間を記録するため

<details><summary>答えと解説</summary>

正解: **3**

チェーンオブカストディは「誰が・いつ・どこで・何を・どう扱ったか」を途切れなく記録し、証拠の完全性(改ざんされていないこと)を法廷で証明するための仕組みです。分析速度や費用管理、勤怠記録は目的ではありません。記録が一瞬でも途切れると「その間の改ざんの可能性」を否定できなくなる——つまり途切れた時点で証拠価値が大きく毀損する、という点まで押さえましょう。

</details>

**問3.** ランサムウェアに感染した疑いのある稼働中のサーバーを調査します。最初に (FIRST) 行うべき行動として最も適切なものはどれでしょう？

1. メモリの内容をダンプして保全する
2. 直ちに電源ケーブルを抜いてディスクを取り出す
3. ウイルス対策ソフトでフルスキャンを実行する
4. OS を再起動してセーフモードで調べる

<details><summary>答えと解説</summary>

正解: **1**

稼働中のマシンでは、電源断で失われるメモリ(暗号鍵、プロセス、C2 通信(第17章で見た、攻撃者の指令サーバーとのやり取り)の痕跡が残っていることが多い)を先に保全します。電源を抜くと揮発性データが全滅し、再起動やフルスキャンはディスクとメモリの状態を書き換えてしまうため、いずれも証拠保全の観点で NG です。「封じ込めを急いで電源断」を選ばせるひっかけですが、フォレンジック文脈では揮発性の順序が優先されます。

</details>

**問4.** 自社が訴訟の相手方から法的ホールド (litigation hold) の通知を受け取りました。情報セキュリティ部門が直ちに行うべきこととして最も適切なものはどれでしょう？

1. 保持期限が過ぎた関連データを通常どおり削除する
2. 関連しそうなデータを調査しやすいよう1つのフォルダに移動・整理する
3. 対象データを編集して個人情報をあらかじめ削っておく
4. 関連データの自動削除・上書き処理を停止し、現状のまま保全する

<details><summary>答えと解説</summary>

正解: **4**

法的ホールドを受けたら、関連データの自動削除(保持スケジュールによる消去、ログローテーションなど)を直ちに停止し、現状のまま保全します。保持期限が来ていても削除すれば証拠隠滅 (spoliation) と見なされえます。ファイルの移動・整理や編集はメタデータや内容を変えてしまうため保全に反します。「保持ポリシーどおりの削除なら問題ない」というのが最大のひっかけです。

</details>

**問5.** 押収したPCのディスクを分析する方法として、最も適切 (BEST) なものはどれでしょう？

1. オリジナルのディスクを直接マウントして素早く調べる
2. 検証可能なイメージコピーを作成し、分析はコピーに対して行う
3. オリジナルから必要なファイルだけをUSBメモリにコピーして調べる
4. オリジナルのディスクをまずデフラグして読み取りやすくする

<details><summary>答えと解説</summary>

正解: **2**

オリジナルには手を加えず、ビット単位のイメージコピーを作って分析するのが鉄則です。オリジナルを直接マウント(OS につないで読み書きできる状態に)するとアクセス日時などが書き換わり、必要なファイルだけの論理コピーでは削除済み領域やスラックスペース(ファイル末尾の使われていない余白。以前のデータの断片が残る)が失われます。デフラグはデータ配置を物理的に書き換える最悪の操作です。「速さ・手軽さ」を理由にする選択肢は、証拠保全の文脈ではほぼ誤答と考えてよいでしょう。

</details>

## 3. デジタルフォレンジックとeディスカバリ

### フォレンジックの基本手順

デジタルフォレンジック (digital forensics) は、**識別 → 保全 → 収集 → 分析 → 報告**という流れで進めます。各段階で記録を残し、あとから第三者が同じ手順をたどれる(再現可能である)ことが信頼性の裏付けになります。

### ディスクイメージングの3点セット

| 要素 | 役割 |
|---|---|
| ビット単位コピー (bit-level image) | 削除済み領域やスラックスペースまで丸ごと複製する |
| ライトブロッカー (write blocker) | 収集中にオリジナルへ書き込みが起きないよう物理的に防ぐ |
| ハッシュ値 (SHA-256 など。第11章で見たハッシュ) | 取得前後で一致を確認し、コピーがオリジナルと同一である完全性を証明する |

💡 コツ: 「なぜ論理コピーでなくビットイメージか?」→ 削除されたファイルの痕跡まで取るため。「なぜハッシュか?」→ 同一性(完全性)の証明。この2つの「なぜ」がそのまま設問になります。

- **論理コピー**: OS から見えるファイルだけを写すコピー。削除済み領域やスラックスペースは写りません
- **スラックスペース (slack space)**: ディスクは決まった大きさの区画(例: 4KB)単位でファイルを置くため、ファイルの末尾と区画の終わりの間に余りが出ます。そこに以前のファイルの断片が残っていることがあります

取得の流れをコマンドで書くと、たとえば次のようになります(Linux の例。/dev/sdb はライトブロッカー経由でつないだ証拠ディスク、ハッシュ値は途中を省略)。

```
$ sha256sum /dev/sdb
3a7bd3e2360a3d29...  /dev/sdb
$ dd if=/dev/sdb of=evidence.img bs=4M
$ sha256sum evidence.img
3a7bd3e2360a3d29...  evidence.img
```

- 1〜2行目: 原本ディスク全体のハッシュ値(SHA-256)を計算します。2行目がその結果です
- 3行目: `dd` で原本ディスクを先頭から最後までビット単位で読み、ファイル evidence.img に書き出します。`if=` は読み込み元、`of=` は書き込み先、`bs=4M` は一度に読む量です
- 4〜5行目: できたイメージのハッシュ値を計算します。原本と同じ値なので、1ビットも違わない複製だと示せます。1ビットでも違えば、まったく別の値になります

この2つのハッシュ値は、チェーンオブカストディの記録にも書き残します。

### 対象別の難しさ

- **メモリフォレンジック**: 稼働中にしか取れない。マルウェアの実体や暗号鍵が見つかる
- **ネットワーク**: パケットキャプチャ(通信の中身をそのまま記録)や NetFlow(誰がどこへどれだけ通信したかだけの記録。第24章で詳しく見ます)。事前に取得していなければ後からは再現できない
- **モバイル**: 暗号化・ロック・機種差が壁。押収時は電波遮断袋 (Faraday bag) で遠隔ワイプ(ネット経由で端末のデータを消去する機能)を防ぐ
- **クラウド**: データの物理的所在が不明、マルチテナント(複数の利用企業が同じ設備を共有する形。第10章で見たクラウドの特徴)で他社データと同居、収集は事業者の協力と契約(SLA・監査権)に依存
- **アンチフォレンジック**: 消去・難読化・タイムスタンプ改ざんなど、解析を妨害する行為。タイムライン分析(ファイルやログの日時を1本の時系列に並べる分析)で矛盾を見つけます

### eディスカバリ (electronic discovery)

訴訟で電子的記録 (ESI: Electronically Stored Information。メール・文書ファイル・チャット・ログなど) を相手方に開示する手続きです。EDRM(eディスカバリの標準的な手順モデル)の流れ——**識別 → 保全 → 収集 → 処理 → レビュー → 提出 (production)**——を押さえましょう。処理は重複の除去や形式の変換、レビューは関連性と秘匿特権(弁護士とのやり取りなど、開示を拒める情報)の確認です。フォレンジックと同じく保全が要で、調査では従業員のプライバシーや人権への配慮(調査方針の事前告知、必要最小限の範囲)も忘れてはいけません。

### 確認問題

**問1.** ディスクイメージ取得の前後でハッシュ値を計算して比較する目的として、最も適切 (MOST) なものはどれでしょう？

1. コピーがオリジナルと同一であること(完全性)を証明するため
2. ディスクの空き容量を正確に測定するため
3. イメージファイルを暗号化して機密性を守るため
4. 取得作業の所要時間を短縮するため

<details><summary>答えと解説</summary>

正解: **1**

ハッシュ値が取得前後で一致すれば、イメージがオリジナルのビット単位の完全な複製であることを数学的に示せます。これは完全性 (integrity) の証明であり、機密性(暗号化)とは別の性質です。容量測定や時間短縮はハッシュの役割ではありません。「ハッシュ=暗号化」と混同させる選択肢が定番のひっかけで、ハッシュは一方向で鍵もなく、守るのは完全性だと切り分けましょう。

</details>

**問2.** 証拠ディスクからイメージを取得する際にライトブロッカーを使う理由として、正しいものはどれでしょう？

1. 読み取り速度を向上させるため
2. イメージファイルの圧縮率を高めるため
3. 収集作業中にオリジナルのディスクへ書き込みが発生するのを防ぐため
4. ディスクの不良セクタを自動修復するため

<details><summary>答えと解説</summary>

正解: **3**

ライトブロッカーは、接続した時点で OS が自動的に行うものも含め、オリジナル媒体へのあらゆる書き込みを遮断する装置(またはソフトウェア)です。PCにディスクをつなぐだけでもマウント処理などで書き込みが起こりえるため、これを防がないと「オリジナルに手を加えない」原則が崩れます。速度・圧縮・修復の機能はありません。修復(書き換え)はむしろ証拠保全と正反対の行為です。

</details>

**問3.** クラウド上のシステムに対するフォレンジック調査が、オンプレミスより難しくなる理由の説明として最も適切 (BEST) なものはどれでしょう？

1. クラウドのデータはすべて暗号化されており復号する方法が存在しないため
2. データの物理的所在が特定しにくく、収集がクラウド事業者の協力と契約条件に依存するため
3. クラウドにはログ機能が存在しないため
4. クラウド上のデータは法律上いかなる場合も証拠として認められないため

<details><summary>答えと解説</summary>

正解: **2**

クラウドではデータがどの国のどのサーバーにあるか特定しづらく(管轄権の問題)、マルチテナントで他社データと同居し、物理媒体の押収もできないため、収集は事業者の協力・SLA・監査権条項に依存します。だからこそ契約段階でフォレンジック協力条項を入れておくのが CISSP 的な備えです。「復号不能」「ログがない」「証拠にできない」という全否定の選択肢はいずれも事実に反します。

</details>

**問4.** eディスカバリ (EDRM) のプロセスで、「保全 (preservation)」の次に行うフェーズはどれでしょう？

1. 提出 (production)
2. レビュー (review)
3. 処理 (processing)
4. 収集 (collection)

<details><summary>答えと解説</summary>

正解: **4**

EDRM の流れは「識別→保全→収集→処理→レビュー→提出」です。まず対象を特定して消えないように保全し、それから収集します。処理(重複排除や形式変換)とレビュー(関連性・秘匿特権の確認)を経て、最後に相手方へ提出します。保全と収集の順序を逆にするひっかけに注意——「消える前に守る」が先、「集める」はその後です。

</details>

**問5.** 押収したスマートフォンを証拠として保全する際、電波を遮断する袋 (Faraday bag) に入れる主な理由として最も適切なものはどれでしょう？

1. バッテリーの消耗を完全に止めるため
2. 落下などの物理的衝撃から保護するため
3. 遠隔からのワイプ(消去)やデータ変更を防ぐため
4. 指紋が付着するのを防ぐため

<details><summary>答えと解説</summary>

正解: **3**

スマートフォンはネットワークにつながっている限り、所有者や攻撃者が遠隔ワイプを実行したり、新着データで状態が変わったりします。Faraday bag は電波を遮断してこれを防ぎ、押収時点の状態を保全します。電波遮断中も端末は基地局を探して動き続けるためバッテリーはむしろ消耗しますし、衝撃保護や指紋対策は主目的ではありません。「機内モードにすればよい」と考えがちですが、操作自体が状態を変えるため袋のほうが安全、という点も覚えておきましょう。

</details>

**問6.** 証拠ディスクのイメージを取得したところ、原本とイメージの SHA-256 ハッシュ値が一致しませんでした。この結果から言えることとして、最も適切なものはどれでしょう？

1. ハッシュ値は計算するたびに変わるものなので問題ない
2. イメージが原本と同一だとは示せないため、記録を残して原因を調べ、取り直す必要がある
3. イメージが暗号化されているので、むしろ安全性が高い
4. 違いはわずかなはずなので、そのまま分析してよい

<details><summary>答えと解説</summary>

正解: **2**

ハッシュ関数は同じ入力からは必ず同じ値を出し、1ビットでも違えばまったく別の値になります(第11章)。一致しないということは、イメージが原本の完全な複製ではない(読み取りエラーや取得中の書き込みなど)ことを意味します。そのまま分析すると証拠能力を疑われるため、経緯を記録して原因を調べ、取り直します。ハッシュ値は計算のたびに変わるものではなく、暗号化とも無関係です。また、値の違いから「差の大きさ」はわかりません。

</details>
