# 第17章 ネットワーク攻撃と防御【D4】

D4 の仕上げとして、ネットワークへの代表的な攻撃と、それを検知・防御する仕組みを学びます。CISSP では攻撃の手順ではなく「防御者としてどの対策を選ぶのが最適か」が問われます。攻撃名→仕組み→最有効な対策、をセットで覚えましょう。

## 1. DoS/DDoSと中間者攻撃

### サービスを止める攻撃 — DoS/DDoS

**DoS 攻撃 (Denial of Service)** は可用性を狙う攻撃です。多数の踏み台(ボットネット)から一斉に行うものを **DDoS (Distributed DoS)** と呼び、ボットは攻撃者の **C2 サーバー (Command and Control)** から指令を受けます。

| 攻撃 | 仕組み | 代表的な対策 |
|---|---|---|
| SYN フラッド | TCP の3ウェイハンドシェイクを途中で止め、**ハーフオープン接続**を大量に残して接続テーブルを枯渇させる | **SYN クッキー (SYN cookies)**、タイムアウト短縮 |
| UDP/ICMP フラッド | 大量のパケットで帯域・処理能力を圧迫 | レートリミット、不要プロトコルの遮断 |
| 増幅攻撃 (amplification) | 送信元 IP を被害者に**偽装**して DNS/NTP に小さな問い合わせを送り、**大きな応答**を被害者に集中させる(Smurf は ICMP 版の古典) | オープンリゾルバの排除、イングレスフィルタリング |
| アプリケーション層 DoS | 正常に見える HTTP リクエスト等でサーバー資源を消費 | WAF、CDN、レートリミット |

大規模 DDoS への現実解は、ISP や専門事業者の**スクラビングセンター**(洗浄サービス)や CDN で吸収することです。

### 通信に割り込む攻撃 — オンパス攻撃

**オンパス攻撃 (on-path attack)**(従来の中間者攻撃/MITM)は、通信経路に割り込んで盗聴・改ざんする攻撃です。

- **ARP ポイズニング**: 偽の ARP 応答で「ゲートウェイの MAC は私」と学習させ、LAN 内の通信を自分経由にする。対策はスイッチの**動的 ARP 検査 (Dynamic ARP Inspection)** や静的 ARP
- **DNS キャッシュポイズニング**: 偽の名前解決結果をキャッシュさせ、利用者を偽サイトへ誘導する。対策は **DNSSEC**(応答への電子署名)
- **セッションハイジャック**: ログイン後のセッション ID を奪って本人になりすます。対策は TLS と推測困難なセッション ID
- **リプレイ攻撃 (replay attack)**: 盗んだ認証データを**そのまま再送**してなりすます。対策は**タイムスタンプとノンス (nonce)**(1回限りの乱数)

💡 コツ: 「送信元 IP の偽装 + 応答が大きいプロトコル = 増幅攻撃」「LAN 内の盗聴 = ARP、名前解決の誘導 = DNS」と、どこで何が偽装されたかで攻撃名を見分けると、選択肢を素早く絞れます。

### 確認問題

**問1.** Web サーバーの接続テーブルがハーフオープン状態の TCP 接続で埋め尽くされ、新規の接続を受け付けられなくなっています。この攻撃への対策として最も適切(BEST)なものはどれでしょう？

1. SYN クッキーを有効にする
2. DNSSEC を導入する
3. ポートミラーリングを設定する
4. 動的 ARP 検査を有効にする

<details><summary>答えと解説</summary>

正解: **1**

ハーフオープン接続の大量発生は SYN フラッドの典型的な症状です。SYN クッキーは接続情報をテーブルに保持せずに応答できるため、テーブル枯渇を防げます。DNSSEC は名前解決の改ざん対策、ポートミラーリングは監視用のトラフィック複製、動的 ARP 検査は ARP ポイズニング対策で、いずれも SYN フラッドには効きません。試験では「症状(ハーフオープン)→攻撃名(SYN フラッド)→対策(SYN クッキー)」の連想が問われます。

</details>

**問2.** 攻撃者が送信元 IP アドレスを標的に偽装し、小さな問い合わせを多数の DNS サーバーへ送って、大きな応答を標的に集中させました。この攻撃はどれでしょう？

1. セッションハイジャック
2. DNS 増幅攻撃
3. ARP ポイズニング
4. バッファオーバーフロー

<details><summary>答えと解説</summary>

正解: **2**

「送信元を偽装」+「小さな問い合わせに対する大きな応答を悪用」が増幅攻撃 (amplification attack) の特徴で、DNS や NTP が踏み台にされます。セッションハイジャックはセッション ID の奪取、ARP ポイズニングは LAN 内の MAC 対応表の汚染、バッファオーバーフローはメモリ領域あふれを突くソフトウェアの攻撃です。ICMP を使う古典の Smurf 攻撃も同じ「増幅+偽装」の構図である点を押さえましょう。

</details>

**問3.** 社内 LAN で、攻撃者 PC が偽の ARP 応答を流してデフォルトゲートウェイになりすまし、他の端末の通信を盗聴していました。この攻撃を防ぐのに最も効果的(MOST effective)なスイッチの機能はどれでしょう？

1. スパニングツリープロトコル (STP)
2. ポートミラーリング
3. 動的 ARP 検査 (Dynamic ARP Inspection)
4. QoS によるトラフィック優先制御

<details><summary>答えと解説</summary>

正解: **3**

動的 ARP 検査は、DHCP スヌーピングで学習した正しい IP と MAC の対応表と照合し、偽の ARP 応答を破棄するため、ARP ポイズニングへの直接的な対策になります。STP はループ防止、ポートミラーリングは監視用の複製(むしろ盗聴にも使われ得る機能)、QoS は帯域制御であり、なりすまし防止にはなりません。「LAN 内でゲートウェイになりすます=ARP の問題」という連想がポイントです。

</details>

**問4.** 攻撃者が正規ユーザーの認証パケットを盗聴し、後でそのまま再送してシステムへのなりすましログインに成功しました。この攻撃への対策として最も適切(BEST)なものはどれでしょう？

1. パスワードの複雑さ要件を強化する
2. 送信データを圧縮する
3. ネットワーク帯域を増強する
4. タイムスタンプとノンスを用いた認証にする

<details><summary>答えと解説</summary>

正解: **4**

盗んだデータを「そのまま再送」するのがリプレイ攻撃です。タイムスタンプや1回限りの乱数であるノンス (nonce) を認証に組み込めば、再送されたデータは古い・使用済みと判定でき無効化できます。パスワードをいくら複雑にしても、暗号化されたままの認証データを再送されれば通ってしまう点がひっかけです。圧縮や帯域増強は可用性・効率の話で、リプレイ対策とは無関係です。

</details>

**問5.** 自社の EC サイトが大規模な DDoS 攻撃を受けてサービス停止しています。セキュリティ責任者として最初に(FIRST)行うべきことはどれでしょう？

1. すべてのサーバーを停止して被害拡大を防ぐ
2. インシデント対応計画を発動し、ISP・DDoS 対策サービスと連携して通信の洗浄を開始する
3. 攻撃元の IP アドレスへ逆に大量のパケットを送って反撃する
4. 翌週の経営会議で対応方針を審議する

<details><summary>答えと解説</summary>

正解: **2**

DDoS への対応は事前に定めたインシデント対応計画に従い、ISP やスクラビングサービスと連携してトラフィックを洗浄するのが定石です。全サーバー停止は攻撃者の目的(可用性の停止)を自ら達成してしまい、反撃(hack back)は違法となるおそれがあり CISSP 倫理にも反します。経営会議を待つのは対応の遅延にすぎません。CISSP では「計画に従って行動する」が FIRST 問題の定番の正解筋です。

</details>

## 2. 偵察・盗聴とその対策

### 攻撃は「偵察」から始まる

本格的な攻撃の前には、標的の情報を集める**偵察 (reconnaissance)** が行われます。防御側は偵察の兆候を「攻撃の前段階」として捉えることが重要です。

- **ポートスキャン**: 開いているポート(=稼働サービス)を調べる行為。それ自体は侵入ではありませんが、攻撃準備のシグナルです
- **列挙 (enumeration)**: ユーザー名や共有資源など、より踏み込んだ情報収集
- **バナーグラビング (banner grabbing)**: サービスの応答メッセージからソフトウェア名やバージョンを特定する手法。不要なバージョン表示は消すのが対策です

### 盗聴 (eavesdropping) とスニッフィング

**スニッフィング**は、NIC を**無差別モード (promiscuous mode)** にして、同一ネットワーク上を流れる自分宛て以外のフレームも取得する行為です。スイッチ環境では基本的に自分宛てしか届きませんが、ミラーポートの悪用、物理的な**ネットワークタップ**の設置、前章の ARP ポイズニングなどで盗聴は依然として可能です。無線 LAN は電波が届く範囲の誰でも傍受できるため、特に注意が必要です。

盗聴への最も効果的な対策は**通信の暗号化**です。「盗まれても読めない」状態にすることが本質であり、TLS・IPsec・WPA3 などを使います。

### なりすまし (spoofing) と放射からの漏えい

**スプーフィング**は送信元の偽装全般を指します。IP スプーフィング(送信元 IP の偽装)、MAC スプーフィング、メールの送信者偽装などがあります。社外から「送信元が社内アドレス」のパケットが届くのは偽装の証拠であり、境界ルーターの**イングレスフィルタリング**(入口での送信元検証)で破棄します。逆に自社から出る偽装パケットを止めるのが**イーグレスフィルタリング**です。

また、モニタやケーブルの**電磁放射**から情報を復元する攻撃(エマネーション)への対策分野を **EMSEC/TEMPEST** と呼び、シールド(**ファラデーケージ**)、白色雑音、コントロールゾーンの設定が代表的な対策です。

💡 コツ: 「盗聴の最良対策は暗号化」「偵察の検知は攻撃の予兆」「放射漏えいは TEMPEST」の3点は、選択肢の言い換えに惑わされず即答できるようにしましょう。

### 確認問題

**問1.** 攻撃者が NIC を無差別モード (promiscuous mode) に設定しました。これによって可能になることはどれでしょう？

1. MAC アドレスを自由に偽装できる
2. 無線チャネルを電波妨害できる
3. 同一ネットワーク上を流れる他者宛てのトラフィックを受信できる
4. ルーターのルーティングテーブルを改ざんできる

<details><summary>答えと解説</summary>

正解: **3**

無差別モードは「自分宛てではないフレームも破棄せずに取り込む」NIC の動作モードで、スニッフィング(盗聴)の技術的な前提です。MAC の偽装はスプーフィングで別の操作、電波妨害はジャミング、ルーティングテーブルの改ざんはルーティングプロトコルへの攻撃であり、無差別モードそのものの効果ではありません。「promiscuous = 何でも受け取る」というイメージで覚えましょう。

</details>

**問2.** ネットワーク上の盗聴による情報漏えいを防ぐ対策として、最も効果的(MOST effective)なものはどれでしょう？

1. パスワードポリシーを強化する
2. 通信を暗号化する
3. IDS を導入して監視する
4. 定期的にポートスキャンを実施する

<details><summary>答えと解説</summary>

正解: **2**

盗聴は通信経路のどこかで必ず起こり得るという前提に立ち、「取得されても内容を読めなくする」暗号化が最も本質的で効果の高い対策です。パスワード強化は認証の話であり、平文通信ならパスワード自体が盗聴されます。IDS は検知はできても盗聴自体(受動的攻撃)は見えないことが多く、ポートスキャンは自組織の露出確認で盗聴対策ではありません。「受動的攻撃には予防(暗号化)で臨む」が定石です。

</details>

**問3.** ディスプレイやケーブルから漏れる電磁放射を傍受して画面内容を復元する攻撃が懸念されています。対策として適切なものはどれでしょう？

1. ファラデーケージなどの電磁シールドを施す
2. DNSSEC を導入する
3. SPF レコードを設定する
4. NAC で端末を検疫する

<details><summary>答えと解説</summary>

正解: **1**

電磁放射(エマネーション)からの情報漏えい対策は EMSEC/TEMPEST の領域で、ファラデーケージによるシールド、白色雑音の放射、接近を制限するコントロールゾーンが代表的な対策です。DNSSEC は DNS 応答の真正性、SPF はメール送信元の検証、NAC は接続端末の統制であり、物理的な放射漏えいには無力です。「電磁波・放射」というキーワードが出たら TEMPEST を思い出してください。

</details>

**問4.** IDS が、外部の単一 IP アドレスから自社の全サーバーに対する広範囲なポートスキャンを検知しました。この事象の解釈として最も適切(BEST)なものはどれでしょう？

1. すでに機密データが漏えいしたことが確定した
2. 誤検知なので無視してよい
3. 内部犯行の決定的な証拠である
4. 本格的な攻撃に先立つ偵察活動の可能性が高い

<details><summary>答えと解説</summary>

正解: **4**

ポートスキャンは稼働サービスを洗い出す情報収集であり、攻撃のライフサイクルでは偵察段階に位置づけられます。スキャンだけではデータ漏えいは発生していないため「漏えい確定」は過剰解釈、外部 IP からの事象なので「内部犯行の証拠」も不適切、攻撃の予兆を「無視してよい」は防御者として最悪の判断です。偵察の検知は、監視強化や露出面の点検につなげるべきシグナルです。

</details>

**問5.** インターネット側から、送信元 IP アドレスが社内プライベートアドレスになっているパケットが境界ルーターに届いています。対策として最も適切(BEST)なものはどれでしょう？

1. 社内 DNS サーバーを増強する
2. DHCP のリース期間を短縮する
3. 境界ルーターでイングレスフィルタリングを実施して破棄する
4. メールを S/MIME で暗号化する

<details><summary>答えと解説</summary>

正解: **3**

外部から社内アドレスを名乗るパケットが来ることは正常にはあり得ず、IP スプーフィングの典型です。入口で送信元アドレスの妥当性を検証して破棄するイングレスフィルタリングが直接の対策になります。DNS 増強や DHCP リース期間は無関係、S/MIME はメールの機密性・真正性の対策です。自社から出る偽装パケットを止めるイーグレスフィルタリングとの方向の違いも、ひっかけとして頻出です。

</details>

## 3. 検知と防御のアーキテクチャ

### IDS と IPS — 「見る」か「止める」か

- **IDS (Intrusion Detection System)**: 攻撃を**検知して警告**します。通信のコピーを受け取るため、通信は止めません
- **IPS (Intrusion Prevention System)**: 通信経路上(**インライン**)に設置され、悪性トラフィックを**その場で遮断**できます

設置場所により、ネットワーク全体を見る **NIDS** と、ホスト上で動く **HIDS** に分かれます。

### 検知方式の対比(超頻出)

| 方式 | 仕組み | 長所 | 短所 |
|---|---|---|---|
| **シグネチャ型** (signature-based) | 既知の攻撃パターンと照合 | 誤検知が少ない | **未知の攻撃は検知不能**、定義の更新が必須 |
| **異常検知型** (anomaly-based) | 正常時の**ベースライン**からの逸脱を検知 | **未知(ゼロデイ)の攻撃も検知し得る** | 誤検知が多い、学習・チューニングが必要 |

**誤検知 (false positive)** は正常を攻撃と誤ること、**見逃し (false negative)** は攻撃を検知できないことです。一般に見逃しのほうが危険ですが、IPS の誤検知は正常業務を止めるため、文脈に応じたチューニングが問われます。

### プロキシとメールセキュリティ

- **フォワードプロキシ**: 内部ユーザーの外部アクセスを代理し、URL フィルタリングやログ取得を行います
- **リバースプロキシ**: 外部クライアントの要求を受けて**内部サーバーへ中継**します。負荷分散や WAF と組み合わせ、サーバーを直接公開しない構成にできます

メールの送信ドメイン認証は3兄弟の役割分担が頻出です。

| 技術 | 検証するもの |
|---|---|
| **SPF** | 送信元 **IP** がドメインの許可リストにあるか(DNS の TXT レコード) |
| **DKIM** | DNS で公開した**公開鍵**で、メールの**電子署名**を検証(改ざん・ドメイン詐称の検出) |
| **DMARC** | SPF/DKIM の結果をどう扱うかの**ポリシー**(隔離・拒否)と**レポート** |

💡 コツ: 多層防御では「境界のファイアウォール → IPS → プロキシ/WAF → エンドポイント」のように、1つの失敗を次の層が補う構成が BEST とされます。単一の製品で全部守る選択肢はたいてい誤りです。ハニーポット(おとり)による攻撃者の観察は D7 の運用で詳しく扱います。

### 確認問題

**問1.** IDS と比較したときの IPS の本質的な違いとして、正しいものはどれでしょう？

1. IDS は暗号化された通信を自動的に復号できる
2. IPS は通信経路上にインラインで設置され、悪性トラフィックを遮断できる
3. IDS はファイアウォールの完全な代替になる
4. IPS は検知ログを一切取得しない

<details><summary>答えと解説</summary>

正解: **2**

IPS は通信の経路上(インライン)に置かれるため、検知した悪性トラフィックをその場で遮断(prevention)できます。IDS は通信のコピーを監視する受動的な装置で、復号機能があるわけではなく、アクセス制御を行うファイアウォールの代替にもなりません。IPS もログは取得します。「IDS=検知して知らせる、IPS=インラインで止める」の対比が、位置(インラインか否か)とセットで問われます。

</details>

**問2.** シグネチャ型と比較したときの異常検知型(アノマリ型)IDS の最大の利点(BEST advantage)はどれでしょう？

1. 誤検知がほとんど発生しない
2. 導入後のチューニングが不要である
3. シグネチャが存在しない未知の攻撃を検知できる可能性がある
4. 処理負荷が常に小さい

<details><summary>答えと解説</summary>

正解: **3**

異常検知型は正常時のベースラインからの逸脱を見るため、既知パターンに依存せず、ゼロデイなど未知の攻撃も検知し得るのが最大の利点です。その代償として誤検知が多く、ベースラインの学習とチューニングが必要になります。つまり選択肢の「誤検知が少ない」「チューニング不要」はシグネチャ型の特徴か、どちらにも当てはまらない記述で、長所と短所を入れ替えるのが定番のひっかけです。

</details>

**問3.** 送信側がメールに電子署名を付与し、受信側が送信ドメインの DNS に公開された公開鍵でその署名を検証する仕組みはどれでしょう？

1. SPF
2. DMARC
3. S/MIME
4. DKIM

<details><summary>答えと解説</summary>

正解: **4**

DKIM はドメイン単位の電子署名で、DNS に公開した公開鍵により「そのドメインから送られ、途中で改ざんされていない」ことを検証します。SPF は送信元 IP が許可リストにあるかの検証、DMARC は SPF/DKIM の結果を受けて隔離・拒否を指示するポリシーとレポートの枠組みです。S/MIME は個人間のメール暗号化・署名であり、ドメイン認証の仕組みではありません。3つの役割分担は表で丸ごと覚えましょう。

</details>

**問4.** 導入した IPS が正当な業務トラフィックを攻撃と誤判定して遮断し、業務部門から苦情が出ています。対応として最も適切(BEST)なものはどれでしょう？

1. シグネチャと検知閾値をチューニングし、誤検知を減らしてから遮断を継続する
2. IPS を撤去し、今後一切の侵入防止装置を導入しない
3. すべての社内トラフィックを検査対象外の許可リストに登録する
4. 業務部門に遮断を我慢するよう通達する

<details><summary>答えと解説</summary>

正解: **1**

誤検知(false positive)による業務影響は、シグネチャ・閾値・除外ルールのチューニングで削減するのが正攻法です。撤去は防御そのものの放棄、全トラフィックの除外は IPS を形骸化させる極端な対応で、我慢の強要はセキュリティと事業の整合というガバナンスの考え方に反します。CISSP では「極端な選択肢(全部やめる・全部許可)はまず誤り」という感覚も役立ちます。

</details>

**問5.** 外部クライアントからのリクエストをいったん受け取り、背後の内部 Web サーバー群へ中継する装置はどれでしょう？

1. フォワードプロキシ
2. DNS リゾルバ
3. リバースプロキシ
4. DHCP リレーエージェント

<details><summary>答えと解説</summary>

正解: **3**

リバースプロキシは外部からの要求をサーバー側で受け、内部サーバーへ中継します。サーバーを直接公開せず、負荷分散や WAF、TLS 終端と組み合わせられるため多層防御の定番要素です。フォワードプロキシは逆に「内部ユーザーの外向きアクセス」を代理する装置で、方向が反対という点が頻出のひっかけです。DNS リゾルバは名前解決、DHCP リレーはアドレス配布の中継であり、Web リクエストの中継とは無関係です。

</details>
