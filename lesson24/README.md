# 第24章 ログ・監視・検知（SIEM・SOAR・脅威インテリジェンス）【D7】

攻撃を「防ぐ」だけでなく「早く見つける」のがセキュリティ運用の要です。この章では、ログの設計と保護、SIEM・UEBA・SOAR による検知と対応の自動化、そして脅威インテリジェンスとハニーポットなどのデセプション技術まで、検知の仕組みを体系的に学びます。「エンティスメントとエントラップメントの違い」など CISSP 特有の頻出論点も押さえます。

## 1. ロギングと監視の設計

### ログは「説明責任」の土台

ログ (log) は、誰が・いつ・何をしたかの記録です。ログがあって初めて、利用者の行動に**説明責任 (accountability)** を持たせられます。目的は大きく3つです。

| 目的 | 説明 |
|---|---|
| 説明責任 | 一意の ID と記録で「誰がやったか」を特定する |
| イベントの再構築 | インシデント後に何が起きたかを時系列で復元する |
| 検知 | 異常なパターンをリアルタイム/事後に発見する |

記録すべき代表例は、**認証の成功と失敗・特権操作 (privileged operations)・設定変更・重要データへのアクセス**です。すべてを記録すると量が膨大になるため、**クリッピングレベル (clipping level)** という「しきい値を超えたときだけ記録する」手法を使います（例: ログイン失敗が5回を超えたら記録）。母集団から一部を抜き出す**サンプリング (sampling)** との違いも押さえましょう。

### ログ自体を守る

攻撃者は証拠を消すために真っ先にログを狙います。対策は次のとおりです。

- **中央ログサーバーへ即時転送**し、発生元に残さない（一方向の転送が理想）
- **WORM (Write Once Read Many)** メディアや追記専用ストレージで改ざんを防ぐ
- ログへのアクセスを最小権限にし、ログの参照・削除も監査する
- **NTP による時刻同期**。時刻がずれていると複数機器のログを突き合わせられず、法的証拠としての価値も下がります

保持期間は法令・規制とポリシーで決め、期限が来たら確実に廃棄します。

### 監視の手法

- **リアルタイム監視**（アラート即応）と**事後レビュー**（定期的なログレビュー）を併用します
- **NetFlow** は「誰が誰と・いつ・どれだけ」通信したかのメタデータのみを記録し、**フルパケットキャプチャ**は中身まで全部記録します。容量と目的で使い分けます
- **エグレス監視 (egress monitoring)** は外向き通信を監視してデータ持ち出し（漏えい）を検知する考え方で、DLP とも連携します

💡 コツ: 「ログの完全性を守る BEST は?」と聞かれたら、**別サーバーへの即時転送 + 改ざん防止（WORM・ハッシュ）**の方向が正解筋です。

### 確認問題

**問1.** 利用者に説明責任 (accountability) を持たせるために、監査ログとあわせて必須となるものはどれでしょう？

1. 共有アカウントの利用
2. 一意の利用者 ID による識別と認証
3. ログの圧縮保存
4. 管理者によるログの毎日の削除

<details><summary>答えと解説</summary>

正解: **2**

説明責任は「識別 → 認証 → 認可 → 監査」の積み重ねで成立し、行動を特定の個人に結びつけるには一意の ID が不可欠です。共有アカウントは「誰がやったか」を特定できなくするため説明責任を壊す代表例です。圧縮は保存効率の話で、削除はむしろ証拠の喪失になります。試験では「共有アカウント＝説明責任の敵」という図式が繰り返し問われます。

</details>

**問2.** ログイン失敗が5回を超えた場合にのみ記録する、という設定が表す概念はどれでしょう？

1. サンプリング
2. ログローテーション
3. クリッピングレベル
4. 正規化

<details><summary>答えと解説</summary>

正解: **3**

クリッピングレベル (clipping level) は「しきい値を超えたイベントだけを記録する」手法で、ログ量を抑えつつ意味のある異常を捉えます。サンプリングは母集団から一部を統計的に抜き出す手法で、しきい値ではありません（ここがひっかけ）。ログローテーションは古いログの世代管理、正規化は SIEM が形式を揃える処理です。

</details>

**問3.** 攻撃者による監査ログの改ざんを防ぐ対策として最も効果的 (MOST effective) なものはどれでしょう？

1. ログを発生元サーバーのローカルディスクに長期保存する
2. ログを生成元とは別の中央ログサーバーへ即時転送し、追記専用媒体に保存する
3. ログファイルの名前を推測されにくいものに変える
4. ログの記録項目を減らして攻撃者の興味を引かないようにする

<details><summary>答えと解説</summary>

正解: **2**

侵害されたサーバーのローカルログは攻撃者が自由に消せるため、別サーバーへの即時転送と WORM（追記専用）保存の組み合わせが最も効果的です。ローカル長期保存は逆効果、ファイル名変更は隠蔽による security through obscurity にすぎず、記録項目を減らすのは検知能力を自ら下げる行為です。「ログの完全性＝転送＋改ざん防止」の筋で選びましょう。

</details>

**問4.** 複数の機器のログを突き合わせてインシデントを再構築する際、前提として最も重要 (MOST important) なものはどれでしょう？

1. NTP によるすべての機器の時刻同期
2. すべての機器のログ形式が同一ベンダーであること
3. ログが暗号化されていること
4. ログが毎日印刷されていること

<details><summary>答えと解説</summary>

正解: **1**

時刻がずれていると、イベントの前後関係を正しく並べられず再構築が成立しません。法廷での証拠価値にも関わるため、NTP による時刻同期は監査ログの大前提です。ログ形式の違いは SIEM の正規化で吸収できます。暗号化は機密性の保護であり、再構築の前提そのものではありません。印刷は現実的でなく完全性の保証にもなりません。

</details>

**問5.** 社内から外部へのデータ持ち出しを検知したい場合、監視の焦点として最も適切 (BEST) なものはどれでしょう？

1. インバウンド通信のシグネチャ検査
2. サーバー室の入退室ログ
3. パスワードポリシーの強化
4. エグレストラフィック（外向き通信）の監視

<details><summary>答えと解説</summary>

正解: **4**

データの持ち出し（exfiltration）は内部から外部への通信で起きるため、エグレス監視が直球の対策です。DLP と組み合わせると効果が高まります。インバウンド検査は侵入の検知には有効ですが持ち出しの方向と逆です。入退室ログは物理的な持ち出しの一部しかカバーせず、パスワード強化は予防策であって検知にはなりません。「持ち出し＝外向き＝エグレス」と覚えましょう。

</details>

## 2. SIEM・UEBA・SOAR

### SIEM — ログを「集めて・揃えて・関連づける」

**SIEM (Security Information and Event Management)** は、組織中の機器からログを集約し、**正規化 (normalization)** で形式を揃え、**相関分析 (correlation)** で複数のイベントを関連づけてアラートを出す仕組みです。単体では無害に見えるイベント（深夜のログイン + 大量のファイルアクセス + 外部への大容量通信）も、組み合わせれば攻撃の兆候として浮かび上がります。

| 機能 | 内容 |
|---|---|
| 集約 (aggregation) | 多数のソースからログを1か所に集める |
| 正規化 | ベンダーごとに異なる形式を共通形式へ変換する |
| 相関分析 | 複数イベントをルールで関連づけ、攻撃の文脈を作る |
| アラート・ダッシュボード | 検知を通知し、可視化する |

SIEM は導入して終わりではなく、**相関ルールのチューニング**を続けないと誤検知の洪水になります。**アラート疲れ (alert fatigue)** — 大量の誤検知でアナリストが本物を見逃す状態 — は試験でも実務でも重要な論点です。

### UEBA — 「いつもと違う」を見つける

**UEBA (User and Entity Behavior Analytics)** は、ユーザーや端末の平常時の行動**ベースライン**を学習し、そこからの逸脱（深夜の大量ダウンロード、普段使わない国からのアクセスなど)を検知します。シグネチャに頼らないため、**内部不正や乗っ取られたアカウント**の検知に強いのが特徴です。

### SOAR — 対応を自動化する

**SOAR (Security Orchestration, Automation and Response)** は、**プレイブック (playbook)** に沿って対応を自動化します（例: 不審メール検知 → 添付をサンドボックスへ → 悪性なら全受信者から隔離 → チケット起票）。SIEM が「見つける」、SOAR が「動く」という分担で、アナリストを定型作業から解放します。

### SOC と外部委託

検知・対応を担う組織が **SOC (Security Operations Center)** です。Tier1（一次トリアージ）→ Tier2（詳細分析）→ Tier3（ハンティング・高度分析）と階層化するのが典型です。自前で24時間365日の体制を持てない場合は **MSSP** や **MDR** への委託を検討しますが、**リスクの説明責任は委託しても自組織に残る**点を忘れてはいけません。

💡 コツ: 「複数ソースのログを相関分析して一元的に検知したい」→ SIEM、「ふるまいの逸脱を検知」→ UEBA、「対応の自動化」→ SOAR。問題文の動詞で選び分けましょう。

### 確認問題

**問1.** ファイアウォール・AD・プロキシなど複数ソースのログを一元的に集約し、相関分析でインシデントの兆候を検知したい場合、導入すべきものとして最も適切 (BEST) なものはどれでしょう？

1. DLP
2. SIEM
3. NIPS
4. WAF

<details><summary>答えと解説</summary>

正解: **2**

「複数ソースの集約」「相関分析」「一元的な検知」はいずれも SIEM の定義そのものです。DLP はデータ持ち出し防止、NIPS はネットワーク上のインライン遮断、WAF は Web アプリの保護で、いずれも単一領域の対策です。問題文のキーワード（集約・正規化・相関）から SIEM を即答できるようにしましょう。

</details>

**問2.** SIEM が異なるベンダーのログ形式を共通の形式に変換する処理を何と呼ぶでしょう？

1. 集約 (aggregation)
2. トークン化 (tokenization)
3. 相関分析 (correlation)
4. 正規化 (normalization)

<details><summary>答えと解説</summary>

正解: **4**

正規化は形式がバラバラのログを共通フォーマットへ揃える処理で、その後の相関分析の前提になります。集約は「集める」処理、相関分析は「関連づける」処理で、処理の順序（集約→正規化→相関）ごと覚えると整理できます。トークン化は機微データを代替値に置き換えるデータ保護技術で、SIEM の処理とは別物です（ひっかけ）。

</details>

**問3.** 正規のアカウントを乗っ取った攻撃者が、そのユーザーの普段と異なる時間帯・量のデータアクセスを行っています。この種の異常を検知するのに最も適した (MOST suitable) 技術はどれでしょう？

1. シグネチャベースの IDS
2. UEBA（ふるまい分析）
3. 脆弱性スキャナ
4. ファイアウォールのパケットフィルタ

<details><summary>答えと解説</summary>

正解: **2**

正規アカウントによる操作はシグネチャ（既知の攻撃パターン）に一致しないため、シグネチャ型 IDS では捉えにくいのが弱点です。UEBA は本人の平常ベースラインとの「ずれ」を検知するため、乗っ取りや内部不正に強いのが持ち味です。脆弱性スキャナは弱点の棚卸しで検知ではなく、パケットフィルタは許可済み通信をそのまま通します。

</details>

**問4.** フィッシングメール検知後の「隔離→調査→チケット起票」という定型対応をプレイブックで自動化し、アナリストの負荷を減らしたい。導入すべきものとして最も適切 (BEST) なものはどれでしょう？

1. SOAR
2. UEBA
3. ハニーポット
4. NetFlow コレクタ

<details><summary>答えと解説</summary>

正解: **1**

プレイブックに基づく対応の自動化・オーケストレーションは SOAR の定義です。SIEM/UEBA が「検知」を担い、SOAR が「対応」を自動化するという役割分担を押さえましょう。UEBA はふるまい検知、ハニーポットはおとりによる検知・観察、NetFlow は通信メタデータの収集で、いずれも対応の自動化はしません。

</details>

**問5.** SIEM 導入後、誤検知アラートが大量に発生しアナリストが重要なアラートを見逃し始めました。最初に取るべき (FIRST) 対応はどれでしょう？

1. SIEM を停止して手動のログレビューに戻す
2. アラートの通知先を増やして全員で確認する
3. 相関ルールをチューニングし、誤検知の原因となるルールとしきい値を調整する
4. アナリストを増員して全アラートを確認させる

<details><summary>答えと解説</summary>

正解: **3**

アラート疲れ (alert fatigue) の根本原因は検知ルールの精度にあるため、まずルールとしきい値のチューニングで誤検知そのものを減らすのが正攻法です。SIEM 停止は検知能力の放棄で論外、通知先や人員を増やすのはノイズの総量を変えない対症療法で、コストだけが増えます。CISSP では「根本原因に最初に手を打つ」選択肢が FIRST 問題の正解筋になりやすいことを覚えておきましょう。

</details>

## 3. 脅威インテリジェンスとデセプション

### 脅威インテリジェンス — 敵を知る

**脅威インテリジェンス (threat intelligence)** は、攻撃者・手口・兆候に関する情報を収集・分析し、防御に活かす活動です。レベル別に整理すると理解しやすくなります。

| レベル | 内容 | 主な利用者 |
|---|---|---|
| 戦略 (strategic) | 攻撃動向・地政学リスクなど大局 | 経営層 |
| 運用 (operational) | 攻撃キャンペーンや攻撃者グループの情報 | セキュリティ管理者 |
| 戦術 (tactical) | IoC や TTP などの技術的詳細 | SOC アナリスト |

- **IoC (Indicator of Compromise)**: 侵害の痕跡。悪性 IP・ハッシュ値・ドメインなど「点」の情報。変更されやすく寿命が短い
- **TTP (Tactics, Techniques, and Procedures)**: 攻撃者の戦術・技術・手順という「ふるまい」の情報。攻撃者が簡単に変えられないため、より価値が高い

共有には **STIX**（記述形式）と **TAXII**（交換プロトコル）が使われます。**MITRE ATT&CK** は実際の攻撃の TTP を体系化したナレッジベースで、検知ルールの網羅性確認や攻撃シミュレーションの土台になります。

### 脅威ハンティング — 待たずに探しに行く

**脅威ハンティング (threat hunting)** は、アラートを待つ受け身の検知と違い、「すでに侵入されている」という**仮説を立てて能動的に探す**活動です。ATT&CK の TTP を仮説の種にするのが定番です。

### デセプション — おとりで欺く

- **ハニーポット (honeypot)**: わざと攻撃させるおとりシステム。正規ユーザーが触れることはないため、**アクセスがあった時点で高精度のアラート**になります。攻撃手法の研究にも使えます
- **ハニーネット (honeynet)**: ハニーポットで構成したおとりネットワーク
- **ハニートークン**: 使われるはずのない偽の認証情報や偽レコード。使われたら侵害のサイン

法的な論点として、**エンティスメント (enticement)** と**エントラップメント (entrapment)** の違いが超頻出です。

- エンティスメント（誘引）: **すでに侵入の意図を持つ者**に機会を見せること。**合法**で、ハニーポットはこちら
- エントラップメント（罠にはめる）: **その気のない者をそそのかして**犯罪をさせること。**違法・訴追の防御事由**になります

💡 コツ: 「IoC は点、TTP はふるまい」「ハニーポットは誘うだけなら合法（エンティスメント）」の2つはそのまま出題されます。

### 確認問題

**問1.** IoC と比べたときの TTP ベースの検知の利点として、最も適切 (BEST) なものはどれでしょう？

1. 攻撃者はふるまい（TTP）を簡単には変えられないため、検知が長期間有効である
2. TTP は IP アドレスのリストなので自動ブロックが容易である
3. TTP は暗号化されており改ざんされない
4. IoC より収集コストが常に低い

<details><summary>答えと解説</summary>

正解: **1**

悪性 IP やハッシュ値（IoC）は攻撃者が簡単に変更できるため寿命が短いのに対し、攻撃の手口そのもの（TTP）を変えるのは攻撃者にとって高コストです。だから TTP ベースの検知は長持ちします。IP アドレスのリストは IoC の説明（ひっかけ）。暗号化どうこうは無関係で、TTP の分析はむしろ IoC 収集より手間がかかります。

</details>

**問2.** 脅威インテリジェンスを機械可読な形式で記述し、組織間で自動交換するための標準の組み合わせはどれでしょう？

1. SAML と OAuth
2. SNMP と NetFlow
3. STIX と TAXII
4. TLS と IPsec

<details><summary>答えと解説</summary>

正解: **3**

STIX が脅威情報の記述形式、TAXII がその交換プロトコルで、セットで覚えます（「STIX に書いて TAXII で運ぶ」）。SAML/OAuth は認証・認可のフェデレーション、SNMP/NetFlow はネットワーク管理・通信メタデータ、TLS/IPsec は通信の暗号化であり、脅威情報共有の標準ではありません。

</details>

**問3.** 脅威ハンティングが通常のアラート監視と本質的に異なる点はどれでしょう？

1. 検知した攻撃を自動的に遮断する点
2. 「すでに侵害されている」という仮説を立てて能動的に痕跡を探しに行く点
3. 経営層向けの報告書を作成する点
4. シグネチャの更新を自動化する点

<details><summary>答えと解説</summary>

正解: **2**

脅威ハンティングは、アラートを待つ受動的な監視と違い、仮説駆動 (hypothesis-driven) で能動的に探す活動です。MITRE ATT&CK の TTP を仮説の種にするのが定番です。自動遮断は IPS/SOAR の領域、報告書作成はハンティングの本質ではなく、シグネチャ更新の自動化は従来型検知の運用です。「ハンティング＝仮説＋能動」で覚えましょう。

</details>

**問4.** 本番ネットワークに偽の管理者クレデンシャルを仕込み、それが使用されたら即座にアラートを出す仕組みはどれに該当するでしょう？

1. ハニーネット
2. ペネトレーションテスト
3. サンドボックス
4. ハニートークン

<details><summary>答えと解説</summary>

正解: **4**

**問5.** 組織が DMZ にハニーポットを設置し、侵入を試みる攻撃者を誘い込んで手口を観察しています。この行為の法的な位置づけとして最も適切 (MOST accurate) なものはどれでしょう？

1. エントラップメントであり、違法となる可能性が高い
2. エンティスメントであり、一般に合法と解される
3. 盗聴にあたるため令状が必要である
4. 攻撃者への反撃（hack back）として扱われる

<details><summary>答えと解説</summary>

正解: **2**

すでに侵入の意図を持つ者に「機会を見せる」のはエンティスメント（誘引）で、一般に合法です。その気のない人をそそのかして犯罪させるエントラップメントとの違いが超頻出論点で、ハニーポットは前者に該当します。自組織のおとりへのアクセスの観察は盗聴の問題とは別であり、反撃 (hack back) は攻撃者システムへ能動的に侵入し返す行為を指すのでいずれも誤りです。

</details>
