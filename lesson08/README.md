# 第8章 データ保護技術と保持・廃棄【D2】

データは「置いてある・運んでいる・使っている」のどの状態かで守り方が変わります。この章では3つの状態ごとの保護技術、DLP・DRM・CASB の使い分け、そして最後まで問われる「安全な廃棄」までを一気に押さえます。D2 の得点源であり、シナリオ問題の頻出地帯です。

## 1. データ状態別の保護（at rest / in transit / in use）

### データには3つの「状態」がある

データの守り方を考えるとき、CISSP ではまず「そのデータはいまどの状態か」を見ます。状態ごとに有効な保護技術が違うからです。この対比表は**超頻出**なので、そらで言えるようにしましょう。

| 状態 | 意味 | 主な保護技術 |
|---|---|---|
| 保存データ (data at rest) | ディスクやテープに置かれている | フルディスク暗号化 (FDE)、データベース暗号化 (TDE)、ファイル暗号化 |
| 転送中データ (data in transit) | ネットワークを流れている | TLS、IPsec、VPN、SSH |
| 使用中データ (data in use) | メモリ上で処理されている | メモリ保護、セキュアエンクレーブ (secure enclave)、準同型暗号 (homomorphic encryption) |

「使用中」が盲点になりがちです。処理するには復号が必要なので従来は保護が難しかったのですが、暗号化したまま計算できる**準同型暗号**や、CPU 内の隔離領域で処理する**エンクレーブ**が解答の選択肢に出ます。

### 暗号化の選択基準

どの暗号化を使うかは、データの**分類 (classification)** と脅威で決めます。盗難が心配なノート PC にはフルディスク暗号化、DB 管理者からも列を隠したいなら列レベル暗号化、経路上の盗聴には TLS、というように「何から守るか」で選びます。

### ベースラインとスコーピング・テーラリング

セキュリティ対策をゼロから設計せず、NIST SP 800-53 のような**セキュリティベースライン (security baseline)** から出発するのが定石です。システムの影響度（低・中・高）に応じたベースラインを選び、次の2段階で自組織に合わせます。

- **スコーピング (scoping)**: 自システムに該当しないコントロールを対象から外す（例: 無線を使わないなら無線関連を除外）
- **テーラリング (tailoring)**: 残ったコントロールを組織の実情に合わせて調整する（パラメータ変更や補償コントロール (compensating control) への差し替え）

💡 コツ: 「除外するのがスコーピング、調整するのがテーラリング」。順番は スコーピング → テーラリング です。

### 確認問題

**問1.** 営業部員のノートPCの盗難・紛失に備え、保存されている顧客情報を保護したいと考えています。最も適切 (BEST) な対策はどれでしょう？

1. TLS による通信の暗号化
2. フルディスク暗号化 (FDE) の導入
3. DLP によるメール監視
4. パスワードのハッシュ化

<details><summary>答えと解説</summary>

正解: **2**

盗難・紛失で狙われるのはディスク上の「保存データ (data at rest)」なので、フルディスク暗号化が最も適切です。TLS は「転送中データ」の保護であり、PC が盗まれた場面では役に立ちません。DLP は送信経路での漏えい検知が主目的で、盗まれた端末内のデータは守れません。パスワードのハッシュ化は認証情報の保護技術で、顧客情報ファイルそのものは保護しません。「どの状態のデータが危険にさらされているか」から逆算するのがコツです。

</details>

**問2.** クラウド上で、暗号化されたデータを復号せずにそのまま統計処理したいという要件があります。この「使用中データ (data in use)」の保護を実現する技術はどれでしょう？

1. トランスポート層の TLS 1.3
2. AES によるフルディスク暗号化
3. 準同型暗号 (homomorphic encryption)
4. SHA-256 によるハッシュ化

<details><summary>答えと解説</summary>

正解: **3**

準同型暗号は、暗号文のまま加算や乗算などの計算ができる技術で、「復号せずに処理する」という要件にぴったり合います。TLS は転送中、フルディスク暗号化は保存時の保護で、処理するときにはどちらも復号が必要です。ハッシュ化は一方向変換なので、そもそも元データを使った計算ができません。「使用中データの保護＝準同型暗号・セキュアエンクレーブ」という対応はひっかけ抜きの頻出知識です。

</details>

**問3.** NIST SP 800-53 のベースラインを自組織に適用する際、「このシステムには無線 LAN が存在しないので、無線関連のコントロールを対象から除外する」作業を何と呼ぶでしょう？

1. スコーピング (scoping)
2. テーラリング (tailoring)
3. プロビジョニング (provisioning)
4. ベースライニング (baselining)

<details><summary>答えと解説</summary>

正解: **1**

該当しないコントロールを適用範囲から「外す」のがスコーピングです。テーラリングは、残したコントロールのパラメータを調整したり補償コントロールに差し替えたりする「調整」の作業なので、除外そのものとは区別されます。この2つの入れ替えが定番のひっかけです。プロビジョニングはアカウントやリソースの払い出し、ベースライニングは基準となる構成を定める行為で、どちらもコントロールの除外作業ではありません。

</details>

**問4.** 本社と支社の間で、業務システムの通信をインターネット経由でやり取りすることになりました。経路上の盗聴から通信全体を保護する対策として最も適切 (MOST appropriate) なものはどれでしょう？

1. 両拠点のサーバにフルディスク暗号化を導入する
2. データベースの列レベル暗号化を導入する
3. DLP を両拠点に配置する
4. 拠点間を IPsec VPN で接続する

<details><summary>答えと解説</summary>

正解: **4**

経路上の盗聴から守る対象は「転送中データ (data in transit)」なので、拠点間 IPsec VPN が最も適切です。フルディスク暗号化や列レベル暗号化は保存データの保護であり、ネットワークに出た瞬間のデータは守れません。DLP は機密データの持ち出し検知が目的で、盗聴対策にはなりません。「拠点間・サイト間の通信保護＝IPsec VPN」は定番の対応づけとして覚えておきましょう。

</details>

**問5.** 新システムに適用するセキュリティベースラインを選定します。選定の根拠として最も適切 (BEST) なものはどれでしょう？

1. 他社で最も導入実績が多いベースラインを選ぶ
2. システムが扱うデータの分類と影響度に基づいて選ぶ
3. コストが最も低いベースラインを選ぶ
4. 最も厳格なベースラインを常に全システムへ適用する

<details><summary>答えと解説</summary>

正解: **2**

ベースラインは、データの分類 (classification) とシステムの影響度（低・中・高）に見合ったものを選ぶのが原則です。他社の実績やコストは参考情報にすぎず、自組織のリスクに合う保証がありません。「常に最も厳格なものを全システムへ」は一見安全そうですが、過剰なコントロールはコストと業務効率を損ない、リスクに見合った保護という原則に反します。CISSP では『常に最強』より『リスクに見合った選択』が正解になる、と覚えておきましょう。

</details>

## 2. DLP・DRM・CASB とマーキング・非識別化

### 漏えいを防ぐ3つのツールの使い分け

「機密データの漏えいを防ぎたい」というシナリオで、どのツールを選ぶかは**超頻出**です。

| ツール | 得意なこと | 典型シナリオ |
|---|---|---|
| DLP (Data Loss Prevention) | 組織の外へ出ていくデータの検知・ブロック | メールや USB への機密情報コピーを止めたい |
| DRM / IRM (Digital Rights Management) | 配布した後のファイルの利用制御 | 社外に渡した文書の印刷・転送・コピーを禁止したい |
| CASB (Cloud Access Security Broker) | クラウドサービス利用の可視化と制御 | 無許可のクラウドストレージ利用（シャドー IT）を見つけて制御したい |

DLP には、ゲートウェイで通信を監視する**ネットワーク型**と、端末上で USB コピーなどを監視する**エンドポイント型**があります。検知方法はキーワードや正規表現による**パターン検知**と、分類ラベルを見る**ラベル検知**が代表的で、擬陽性（false positive）とのバランス調整が運用の課題になります。

💡 コツ: 「出て行く前に止める＝DLP、出て行った後も制御＝DRM、クラウドの出入り口＝CASB」。

### マーキング・ラベリングと取り扱い

分類 (classification) を決めたら、データに**マーキング／ラベリング**して利用者が一目で分かるようにします。電子データならヘッダやメタデータのラベル、物理媒体ならテープやバックアップ媒体への貼り付けラベルです。ラベルがあるからこそ、DLP のラベル検知や「極秘は社外メール禁止」といった**取り扱い (handling)** ルールが機能します。

### 非識別化の技術

個人データを安全に活用するための変換技術は、違いを問う問題が出ます。

- **擬名化 (pseudonymization)**: 氏名などを仮名に置き換える。**対応表があれば元に戻せる**（GDPR では個人データのまま）
- **匿名化 (anonymization)**: 個人を特定できないよう**不可逆**に加工する。もはや個人データではない
- **トークン化 (tokenization)**: 値を無意味なトークンに置換し、対応表（トークンボルト）で管理。クレジットカード番号の保護で定番
- **マスキング (masking)**: 表示時に一部を伏せ字にする（例: ****-1234）

### 確認問題

**問1.** 情報システム部門が把握していないクラウドストレージの業務利用（シャドー IT）を可視化し、ポリシーで制御したいと考えています。最も適切 (BEST) なソリューションはどれでしょう？

1. エンドポイント型 DLP
2. DRM
3. CASB
4. 次世代ファイアウォール

<details><summary>答えと解説</summary>

正解: **3**

CASB は利用者とクラウドサービスの間に立ち、どのクラウドが使われているかの可視化（シャドー IT の発見）とポリシー制御を行う専用ソリューションなので、これが最適です。エンドポイント型 DLP は端末からのデータ持ち出し検知が主目的で、クラウド利用全体の可視化は守備範囲外です。DRM は配布後のファイル利用制御であり用途が異なります。次世代ファイアウォールも一部のアプリ識別はできますが、「クラウド利用の可視化と制御」という問いには CASB が最も直接的な答えです。

</details>

**問2.** 従業員が顧客の個人情報を誤って社外メールに添付して送信してしまう事故を防ぎたいと考えています。最も適切 (MOST effective) な対策はどれでしょう？

1. ネットワーク型 DLP をメールゲートウェイに導入する
2. メールサーバのディスクを暗号化する
3. 送信メールをすべてアーカイブする
4. CASB を導入する

<details><summary>答えと解説</summary>

正解: **1**

送信メールの内容を検査し、個人情報を含むメールをブロック・警告できるのはネットワーク型 DLP です。ディスク暗号化は保存データの保護であり、正規の送信経路から出て行くメールは止められません。アーカイブは事後調査には役立ちますが予防になりません。CASB はクラウドサービス利用の制御が主目的で、社外メール送信そのものの検査は DLP の役割です。「漏えいの経路がどこか」を特定してからツールを選ぶのがポイントです。

</details>

**問3.** 取引先に提供した提案書 PDF について、提供後も「印刷禁止・転送禁止・閲覧期限30日」という制御を維持したいという要件があります。適切な技術はどれでしょう？

1. TLS による暗号化送信
2. ネットワーク型 DLP
3. ファイルのパスワード ZIP 化
4. DRM / IRM

<details><summary>答えと解説</summary>

正解: **4**

DRM（IRM とも呼ばれます）は、ファイル自体に利用権限を埋め込み、組織の外に出た後も印刷・転送・閲覧期限などを制御し続けられる技術です。TLS は送信経路の保護だけで、届いた後の利用は制御できません。DLP は自組織から出る時点の検知・ブロックが役割で、すでに渡した相手側での利用は制御できません。パスワード ZIP は開封さえされれば後の利用は自由です。「渡した後も制御＝DRM」という対応づけが決め手です。

</details>

**問4.** GDPR の文脈で、氏名を仮 ID に置き換えたが、別に保管した対応表を使えば本人を再識別できる状態にする処理を何と呼ぶでしょう？

1. 匿名化 (anonymization)
2. 擬名化 (pseudonymization)
3. マスキング (masking)
4. 正規化 (normalization)

<details><summary>答えと解説</summary>

正解: **2**

対応表などの追加情報があれば元に戻せる（再識別できる）処理は擬名化です。GDPR では擬名化したデータは依然として個人データとして扱われる点も重要です。匿名化は不可逆で、再識別できないからこそ個人データでなくなります。この「戻せるか戻せないか」が両者を分けるひっかけポイントです。マスキングは表示上の伏せ字にすぎず、正規化はデータベース設計の用語で非識別化とは無関係です。

</details>

**問5.** 決済システムでクレジットカード番号を保護するため、番号を無意味な代替値に置き換え、元の番号との対応は厳重に守られた専用の保管庫 (vault) でのみ管理する方式を採用しました。この技術はどれでしょう？

1. ハッシュ化
2. トークン化 (tokenization)
3. 準同型暗号
4. 消磁 (degaussing)

<details><summary>答えと解説</summary>

正解: **2**

値を無意味なトークンに置き換え、対応表をトークンボルトで管理するのはトークン化で、PCI DSS 環境のカード番号保護の定番です。ハッシュ化は一方向変換で対応表を持たず、元の値に戻す運用はできません。トークンは暗号鍵から数学的に導出されるのではなく対応表で管理される点が暗号化との違いです。準同型暗号は暗号文のまま計算する技術、消磁は磁気媒体のデータ破壊技術で、いずれも場面が異なります。

</details>

## 3. データ残留と安全な廃棄（サニタイズ）

### 消したつもりでも残っている — データ残留

ファイルを削除したりフォーマットしたりしても、媒体上にはデータの痕跡が残ります。これを**データ残留 (data remanence)** と呼び、廃棄した PC やリース返却したストレージからの情報漏えいの原因になります。保持期間が終わったデータは、後で説明責任を果たせる形で確実に廃棄する（defensible destruction）ことが求められます。

### サニタイズ手法の強度順

手法を**弱い順**に並べられるようにしましょう。この順序は**超頻出**です。

| 手法 | 内容 | 残るリスク |
|---|---|---|
| 消去 (erasing) | 通常のファイル削除 | データ本体はほぼ全部残る |
| クリアリング (clearing) | 全領域の上書き (overwrite) | 通常のツールでは復元不可。ラボレベルの攻撃には不安が残る |
| パージング (purging) | より強力な消去（消磁など） | ラボレベルの攻撃にも耐える |
| 消磁 (degaussing) | 強磁界で磁気記録を破壊 | **磁気媒体のみ有効**。ドライブ自体も使用不能になることが多い |
| 物理破壊 (destruction) | 粉砕・溶解・焼却 | 最も確実。媒体の再利用は不可 |

💡 コツ: 「媒体を再利用したいならクリアリング／パージング、再利用しないなら物理破壊」。

### SSD の落とし穴

SSD はフラッシュメモリなので**消磁が効きません**。また、ウェアレベリングのせいで上書きしても書き込まれない領域が残り得ます。そこで有効なのが**暗号化消去 (crypto-erase / cryptographic erasure)** です。あらかじめ媒体全体を暗号化しておき、廃棄時に**暗号鍵だけを破壊**すれば、残ったデータは復号不能なゴミになります。クラウドのように物理媒体に手が届かない環境でも使える点が強みです。

### 検証と記録

サニタイズは実施して終わりではなく、**正しく消えたことの検証 (verification)** と**廃棄証明書 (certificate of destruction)** などの記録が必要です。外部業者に委託する場合も、廃棄の責任（due care）は組織に残ることを忘れないでください。紙媒体はクロスカットシュレッダーや溶解処理が標準です。

### 確認問題

**問1.** 退役させる磁気ハードディスクに最高機密データが含まれており、媒体を再利用する予定はありません。最も確実 (BEST) なサニタイズ手法はどれでしょう？

1. 全領域を1回上書きするクリアリング
2. OS 標準のフォーマット
3. ファイルシステム上の削除
4. 粉砕による物理破壊

<details><summary>答えと解説</summary>

正解: **4**

再利用しない最高機密媒体には、最も強度が高い物理破壊が正解です。クリアリングは通常の復元ツールには有効ですが、再利用予定がないのにあえて弱い手法を選ぶ理由がありません。フォーマットや削除は管理情報を消すだけでデータ本体が残るため、サニタイズとしては最弱です。「再利用の予定があるか」と「データの機密度」の2軸で手法を選ぶのがこの分野の解法パターンです。

</details>

**問2.** SSD の廃棄で消磁 (degaussing) が不適切な理由として、正しいものはどれでしょう？

1. SSD は磁気でデータを記録していないため効果がないから
2. SSD は消磁するとデータが自動的にバックアップされるから
3. 消磁は紙媒体専用の手法だから
4. 消磁には法律上の制限があるから

<details><summary>答えと解説</summary>

正解: **1**

消磁は強力な磁界で「磁気記録」を破壊する手法なので、フラッシュメモリに電荷でデータを保持する SSD にはそもそも効果がありません。これが正解の理由のすべてです。バックアップが走るという事実はなく、消磁は磁気テープや HDD 向けであって紙媒体用でもありません。法律上の制限も論点ではありません。SSD にはさらにウェアレベリングで上書きが行き届かない問題もあるため、暗号化消去 (crypto-erase) が推奨される、という流れで覚えましょう。

</details>

**問3.** クラウドサービスの解約にあたり、物理媒体に直接アクセスできない環境で保存データを確実に使用不能にしたいと考えています。最も適切 (MOST appropriate) な方法はどれでしょう？

1. クラウド事業者のデータセンターで消磁を依頼する
2. 暗号化消去 (crypto-erase) — 保存データの暗号鍵を破壊する
3. 仮想マシンを削除して解約する
4. データを別リージョンへ移動する

<details><summary>答えと解説</summary>

正解: **2**

あらかじめ暗号化して保存したデータの鍵を破壊する暗号化消去なら、物理媒体に触れなくてもデータを実質的に復元不能にできます。クラウドの共有ストレージでは自社データだけを消磁することは現実的に不可能です。仮想マシンの削除は論理的な削除にすぎず、ストレージ上のデータ残留が解消される保証はありません。別リージョンへの移動はコピーが増えるだけで廃棄になりません。「物理媒体に手が届かない＝crypto-erase」が定番の対応です。

</details>

**問4.** 「削除やフォーマットの後も媒体上にデータの痕跡が残り、復元される可能性がある」ことを指す用語はどれでしょう？

1. データマスキング (data masking)
2. データスワッピング (data swapping)
3. データ残留 (data remanence)
4. データディドル (data diddling)

<details><summary>答えと解説</summary>

正解: **3**

削除後も痕跡が残る現象はデータ残留 (data remanence) です。サニタイズ（クリアリング・パージング・破壊）が必要になる根本的な理由がこれです。データマスキングは表示時の伏せ字、データスワッピングは統計データで値を入れ替える非識別化手法、データディドルは入力データを不正に改ざんする攻撃の名前で、いずれも「残留」とは別概念です。似たカタカナ用語を並べるのが典型的なひっかけパターンなので、定義で区別しましょう。

</details>

**問5.** リース満了で返却するサーバの磁気ディスクには機密データが含まれています。リース会社はディスクを再利用する予定です。この状況で最も適切 (BEST) な対応はどれでしょう？

1. ディスクを粉砕してから返却する
2. ファイルをすべてごみ箱から削除して返却する
3. 返却後にリース会社へ消去を依頼する
4. 返却前にパージングを実施し、消去を検証して記録を残す

<details><summary>答えと解説</summary>

正解: **4**

再利用される媒体には物理破壊は使えないため、ラボレベルの復元にも耐えるパージングを自組織の管理下で実施し、検証と記録まで行うのが正解です。粉砕は再利用というリース条件に反します。ごみ箱からの削除はデータ残留がそのまま残る最弱の方法です。返却後の消去依頼は、消えるまでの間データが第三者の手に渡るうえ、実施の保証もありません。委託しても廃棄の説明責任 (due care) は自組織に残る、という視点も覚えておきましょう。

</details>
